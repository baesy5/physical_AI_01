    Chapter 15: 차선 인식과 차선 유지¶

    Part 5: [2권] 시뮬레이션 고급 기능과 안전 주행

    🎯 이 장에서 배우는 것¶

    • 카메라 이미지에서 Canny 엣지 검출을 적용하여 차선 경계를 추출할 수 있다
    • 허프 변환(Hough Transform)으로 직선 차선을 검출하는 파이프라인을 구현할 수 있다
    • 검출된 차선 정보를 바탕으로 PID 기반 차선 유지 조향 제어를 작성할 수 있다
    • 전통적 비전 기법과 딥러닝 기반 차선 인식의 장단점을 비교하여 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔: 고속도로를 달리다가 차선을 벗어나면 "삐~" 하고 경고음이 울리는 기능, 어떻게 만들어졌을까요?

    여러분이 탄 차량이 차선을 인식하고, 차선 안에 머무르도록 스스로 조향하는 기능을 LKAS(Lane Keeping Assist System) 라고 합니다. 이 기능은 현재 거의 모든 신차에 기본 탑재되어 있으며, 자율주행의 가장 기본적이면서도 필수적인 기능입니다.

    이 장에서는 CARLA 시뮬레이터의 카메라 이미지를 사용하여 직접 차선 인식 알고리즘을 만들고, 인식 결과를 조향에 반영하는 전체 과정을 처음부터 끝까지 구현합니다. 이 과정을 통해 컴퓨터 비전의 핵심 기법과 제어 이론의 기초를 동시에 경험하게 됩니다.

    📚 핵심 개념¶

    개념 1: Canny 엣지 검출 — 윤곽선 찾기의 기본¶

    🎨 비유로 시작: 여러분이 색칠 공부 책을 만든다고 상상해 보세요. 원본 사진에서 색을 모두 빼고, 경계선만 남기는 작업이 바로 엣지 검출입니다. 차선은 도로 위에 그려진 밝은 선이므로, 도로(어두운 부분)와 차선(밝은 부분)의 밝기 차이가 큰 경계를 찾으면 차선을 검출할 수 있습니다.

    📖 정확한 정의: Canny 엣지 검출은 이미지에서 밝기가 급격하게 변하는 지점(엣지)을 찾아내는 알고리즘입니다. 1986년 John Canny가 제안했으며, 다음 단계로 동작합니다.

    • 1단계 — 노이즈 제거: 가우시안 블러(Gaussian Blur)로 이미지를 부드럽게 만들어 잡음을 줄입니다
    • 2단계 — 그래디언트 계산: 각 픽셀에서 밝기 변화의 크기와 방향을 계산합니다
    • 3단계 — 비최대 억제(Non-Maximum Suppression): 엣지 후보 중 가장 강한 것만 남깁니다
    • 4단계 — 이중 임계값(Double Threshold): 낮은 임계값과 높은 임계값 사이의 엣지를 판별합니다
    flowchart LR A["원본 이미지\n(컬러)"] --> B["그레이스케일\n변환"] B --> C["가우시안\n블러"] C --> D["Canny 엣지\n검출"] D --> E["엣지 이미지\n(흑백)"]

    💻 예시로 확인:

    import cv2
import numpy as np

# 이미지를 그레이스케일로 변환
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

# 가우시안 블러 적용 (커널 크기 5x5)
blur = cv2.GaussianBlur(gray, (5, 5), 0)

# Canny 엣지 검출 (낮은 임계값 50, 높은 임계값 150)
edges = cv2.Canny(blur, 50, 150)

    여기서 50과 150은 임계값(threshold) 입니다. 밝기 변화가 150보다 크면 확실한 엣지, 50~150 사이면 주변에 강한 엣지가 있을 때만 엣지로 판정합니다.

    알아보기 📌: 임계값을 너무 낮게 설정하면 노이즈까지 엣지로 검출되고, 너무 높게 설정하면 진짜 차선도 놓칠 수 있습니다. 적절한 값을 찾는 것이 핵심입니다.

    개념 2: 관심 영역(ROI)과 허프 변환 — 직선 찾기¶

    🎨 비유로 시작: 어지러운 방에서 리모컨을 찾으려면, 방 전체를 뒤지는 것보다 소파 주변만 집중적으로 살피는 게 효율적이죠? 마찬가지로, 카메라 이미지 전체에서 차선을 찾는 대신 도로가 보이는 영역만 잘라내어 검색하면 훨씬 정확하고 빠릅니다. 이것이 관심 영역(ROI, Region of Interest) 설정입니다.

    📖 관심 영역(ROI) 정의: 카메라 이미지에서 차선이 존재할 가능성이 높은 영역만 마스크(mask)로 선택하는 기법입니다. 일반적으로 이미지의 하단 삼각형 또는 사다리꼴 영역이 도로에 해당합니다.

    def region_of_interest(edges, vertices):
    """관심 영역만 남기는 마스크 적용"""
    mask = np.zeros_like(edges)
    cv2.fillPoly(mask, vertices, 255)
    masked = cv2.bitwise_and(edges, mask)
    return masked

    📖 허프 변환(Hough Transform) 정의: 엣지 이미지에서 직선을 수학적으로 검출하는 알고리즘입니다. 각 엣지 점을 극좌표(ρ, θ) 공간으로 변환하여, 같은 직선 위에 있는 점들이 한 곳에 모이는 원리를 이용합니다.

    flowchart LR A["엣지 이미지"] --> B["ROI 마스크\n적용"] B --> C["허프 변환\n직선 검출"] C --> D["왼쪽 차선\n오른쪽 차선\n분류"] D --> E["차선 선분\n좌표"]

    💻 예시로 확인:

    # 허프 변환으로 직선 검출
lines = cv2.HoughLinesP(
    masked_edges,      # ROI가 적용된 엣지 이미지
    rho=2,             # 거리 해상도 (픽셀 단위)
    theta=np.pi / 180, # 각도 해상도 (1도 단위)
    threshold=50,      # 최소 투표 수
    minLineLength=40,  # 최소 선분 길이
    maxLineGap=100     # 선분 간 최대 허용 간격
)

    알아보기 📌: HoughLinesP의 'P'는 Probabilistic(확률적) 을 의미합니다. 모든 점을 계산하지 않고 일부만 무작위 샘플링하여 속도를 높인 버전입니다.

    왼쪽/오른쪽 차선 분류: 검출된 직선의 기울기(slope) 를 이용하여 분류합니다.

    • 기울기가 음수(-): 이미지 좌표계에서 왼쪽 차선 (화면 왼쪽 아래 → 오른쪽 위 방향)
    • 기울기가 양수(+): 오른쪽 차선 (화면 오른쪽 아래 → 왼쪽 위 방향)
    def classify_lines(lines):
    """기울기로 왼쪽/오른쪽 차선 분류"""
    left_lines = []
    right_lines = []

    if lines is None:
        return left_lines, right_lines

    for line in lines:
        x1, y1, x2, y2 = line[0]
        if x2 == x1:
            continue  # 수직선 무시
        slope = (y2 - y1) / (x2 - x1)

        if slope < -0.5:  # 왼쪽 차선
            left_lines.append(line[0])
        elif slope > 0.5:  # 오른쪽 차선
            right_lines.append(line[0])

    return left_lines, right_lines

    개념 3: 차선 중심 편차와 PID 조향 제어¶

    🎨 비유로 시작: 자전거를 탈 때를 떠올려 보세요. 길 한가운데를 달리고 있는지 확인하려면, 양쪽 도로 가장자리와 내 위치의 차이를 눈으로 판단합니다. 오른쪽으로 치우쳤으면 왼쪽으로 핸들을 돌리고, 왼쪽으로 치우쳤으면 오른쪽으로 돌립니다. 이것이 바로 차선 유지 제어의 핵심 원리입니다.

    📖 차선 중심 편차(Lateral Offset) 정의: 왼쪽 차선과 오른쪽 차선의 중간점(차선 중심)과 카메라(차량) 중심 사이의 수평 거리 차이를 말합니다.

    def compute_lateral_offset(left_lines, right_lines, image_width):
    """차선 중심과 차량 중심의 편차 계산"""
    # 이미지 하단에서의 차선 x 좌표 추정
    left_x = average_x_at_bottom(left_lines)
    right_x = average_x_at_bottom(right_lines)

    lane_center = (left_x + right_x) / 2
    vehicle_center = image_width / 2

    # 양수: 차량이 오른쪽으로 치우침, 음수: 왼쪽으로 치우침
    offset = lane_center - vehicle_center
    return offset

    📖 PID 제어 정의: P(비례), I(적분), D(미분) 세 가지 요소를 조합하여 오차를 줄이는 제어 방식입니다.

    flowchart LR A["목표값\n(편차 = 0)"] --> B["오차 계산\n(편차)"] B --> C["PID\n컨트롤러"] C --> D["조향각\n출력"] D --> E["차량\n이동"] E --> F["새로운\n위치"] F --> B
    • P (비례): 현재 오차에 비례하여 조향. 편차가 크면 많이 틀고, 작으면 조금 틂
    • I (적분): 누적된 오차에 반응. 한쪽으로 계속 치우쳐 있으면 점점 더 강하게 보정
    • D (미분): 오차 변화 속도에 반응. 급격히 벗어나면 빠르게 대응
    class PIDController:
    def __init__(self, kp, ki, kd):
        self.kp = kp  # 비례 이득
        self.ki = ki  # 적분 이득
        self.kd = kd  # 미분 이득
        self.prev_error = 0.0
        self.integral = 0.0

    def compute(self, error, dt):
        self.integral += error * dt
        derivative = (error - self.prev_error) / dt if dt > 0 else 0

        output = (self.kp * error + 
                  self.ki * self.integral + 
                  self.kd * derivative)

        self.prev_error = error
        return output

    알아보기 📌: 실제 차선 유지에서는 P 제어만으로도 기본적인 동작이 가능합니다. 이 장에서는 PD 제어(비례 + 미분)를 중심으로 구현합니다. 적분 항은 시뮬레이션에서 오히려 불안정을 유발할 수 있으므로, 0으로 시작하는 것을 추천합니다.

    개념 4: 전통적 비전 vs 딥러닝 기반 차선 인식¶

    🎨 비유로 시작: 요리에 비유하면, 전통적 비전 방식은 레시피를 보고 한 단계씩 따라 하는 요리이고, 딥러닝 방식은 수천 번 요리를 해본 경험으로 감각적으로 요리하는 것과 같습니다.

    📖 정의 및 비교:

    • 전통적 비전 기반: 사람이 설계한 규칙(엣지 검출 → ROI → 허프 변환 → 차선 분류)을 순서대로 적용하는 방식
    • 딥러닝 기반: 대량의 차선 이미지 데이터를 학습하여 신경망이 스스로 차선 위치를 예측하는 방식
    flowchart TB subgraph 전통적_비전["전통적 비전 파이프라인"] direction LR T1["그레이스케일"] --> T2["블러"] T2 --> T3["Canny 엣지"] T3 --> T4["ROI 마스크"] T4 --> T5["허프 변환"] T5 --> T6["차선 좌표"] end subgraph 딥러닝_기반["딥러닝 기반"] direction LR D1["원본 이미지"] --> D2["CNN 모델"] D2 --> D3["차선 좌표"] end

    각 방식의 특징:

    전통적 비전의 장점 - 작동 원리가 투명하고 디버깅이 쉽다 - 학습 데이터가 필요 없다 - 연산량이 적어 저사양 하드웨어에서도 동작한다

    전통적 비전의 단점 - 그림자, 역광, 비 등 환경 변화에 취약하다 - 곡선 차선 검출이 어렵다 (허프 변환은 직선 전용) - 새로운 상황마다 규칙을 수동으로 추가해야 한다

    딥러닝 기반의 장점 - 다양한 환경(날씨, 조명)에 강건하다 - 곡선, 합류 구간 등 복잡한 차선도 처리 가능하다 - 학습 데이터가 많을수록 성능이 향상된다

    딥러닝 기반의 단점 - 대량의 라벨링된 데이터가 필요하다 - 모델 내부 동작을 설명하기 어렵다 (블랙박스) - GPU 등 고성능 하드웨어가 필요할 수 있다

    생각해보기 🤔: 앞의 챕터에서 만들었던 End-to-End 모델은 카메라 이미지에서 바로 조향값을 출력했습니다. 이번 장의 전통적 비전 방식과 비교했을 때, 어떤 상황에서 어떤 방식이 더 유리할까요?

    🔨 따라하기¶

    이제 핵심 개념을 바탕으로, CARLA 시뮬레이터에서 차선 인식 → 차선 유지 주행을 처음부터 구현해 보겠습니다.

    Step 1: CARLA 카메라 설정 및 이미지 수집¶

    먼저 CARLA에 차량을 스폰하고, 전방 카메라를 장착합니다.

    import carla
import cv2
import numpy as np
import time

# CARLA 서버 연결
client = carla.Client('localhost', 2000)
client.set_timeout(10.0)
world = client.get_world()

# 차량 스폰
blueprint_library = world.get_blueprint_library()
vehicle_bp = blueprint_library.filter('model3')[0]
spawn_point = world.get_map().get_spawn_points()[0]
vehicle = world.spawn_actor(vehicle_bp, spawn_point)

# 전방 RGB 카메라 설정
camera_bp = blueprint_library.find('sensor.camera.rgb')
camera_bp.set_attribute('image_size_x', '640')
camera_bp.set_attribute('image_size_y', '480')
camera_bp.set_attribute('fov', '90')

# 카메라 위치: 차량 앞쪽 위
camera_transform = carla.Transform(
    carla.Location(x=1.5, z=2.4)
)
camera = world.spawn_actor(camera_bp, camera_transform, attach_to=vehicle)

# 이미지 저장용 변수
latest_image = None

def camera_callback(image):
    """카메라 콜백: CARLA 이미지를 NumPy 배열로 변환"""
    global latest_image
    array = np.frombuffer(image.raw_data, dtype=np.uint8)
    array = array.reshape((image.height, image.width, 4))  # BGRA
    latest_image = array[:, :, :3]  # BGR만 추출

camera.listen(camera_callback)
print("카메라 설정 완료! 이미지 수신 대기 중...")

    알아보기 📌: CARLA의 카메라는 BGRA 형식(파란색-초록색-빨간색-투명도)으로 이미지를 출력합니다. OpenCV도 BGR 형식을 사용하므로, 알파 채널만 제거하면 바로 활용할 수 있습니다.

    Step 2: 차선 검출 파이프라인 구현¶

    이 단계에서는 그레이스케일 → 블러 → Canny → ROI → 허프 변환의 전체 파이프라인을 하나의 함수로 구현합니다.

    def detect_lane_lines(image):
    """
    전통적 비전 파이프라인으로 차선 검출
    입력: BGR 이미지 (640x480)
    출력: 왼쪽 차선 리스트, 오른쪽 차선 리스트
    """
    height, width = image.shape[:2]

    # --- 1단계: 그레이스케일 변환 ---
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

    # --- 2단계: 가우시안 블러 ---
    blur = cv2.GaussianBlur(gray, (5, 5), 0)

    # --- 3단계: Canny 엣지 검출 ---
    edges = cv2.Canny(blur, 50, 150)

    # --- 4단계: 관심 영역(ROI) 설정 ---
    # 이미지 하단 사다리꼴 영역만 선택
    roi_vertices = np.array([[
        (50, height),           # 왼쪽 하단
        (width * 0.45, height * 0.6),  # 왼쪽 상단
        (width * 0.55, height * 0.6),  # 오른쪽 상단
        (width - 50, height)    # 오른쪽 하단
    ]], dtype=np.int32)

    mask = np.zeros_like(edges)
    cv2.fillPoly(mask, roi_vertices, 255)
    masked_edges = cv2.bitwise_and(edges, mask)

    # --- 5단계: 허프 변환 ---
    lines = cv2.HoughLinesP(
        masked_edges,
        rho=2,
        theta=np.pi / 180,
        threshold=50,
        minLineLength=40,
        maxLineGap=100
    )

    # --- 6단계: 왼쪽/오른쪽 분류 ---
    left_lines = []
    right_lines = []

    if lines is not None:
        for line in lines:
            x1, y1, x2, y2 = line[0]
            if x2 == x1:
                continue
            slope = (y2 - y1) / (x2 - x1)
            if slope < -0.5:
                left_lines.append((x1, y1, x2, y2))
            elif slope > 0.5:
                right_lines.append((x1, y1, x2, y2))

    return left_lines, right_lines

    Step 3: 차선 평균화 및 시각화¶

    검출된 여러 개의 선분을 하나의 대표 차선으로 합치고, 화면에 그립니다.

    def average_lane_line(lines, height):
    """여러 선분을 하나의 대표 직선으로 평균화"""
    if not lines:
        return None

    # 모든 선분의 기울기와 절편 평균 계산
    slopes = []
    intercepts = []

    for x1, y1, x2, y2 in lines:
        slope = (y2 - y1) / (x2 - x1)
        intercept = y1 - slope * x1
        slopes.append(slope)
        intercepts.append(intercept)

    avg_slope = np.mean(slopes)
    avg_intercept = np.mean(intercepts)

    # y 좌표 범위에서 x 좌표 계산
    y_bottom = height
    y_top = int(height * 0.6)

    x_bottom = int((y_bottom - avg_intercept) / avg_slope)
    x_top = int((y_top - avg_intercept) / avg_slope)

    return (x_bottom, y_bottom, x_top, y_top)


def draw_lanes(image, left_lines, right_lines):
    """이미지 위에 차선을 시각화"""
    overlay = image.copy()
    height = image.shape[0]

    left_lane = average_lane_line(left_lines, height)
    right_lane = average_lane_line(right_lines, height)

    # 초록색으로 차선 그리기
    if left_lane:
        x1, y1, x2, y2 = left_lane
        cv2.line(overlay, (x1, y1), (x2, y2), (0, 255, 0), 5)

    if right_lane:
        x1, y1, x2, y2 = right_lane
        cv2.line(overlay, (x1, y1), (x2, y2), (0, 255, 0), 5)

    # 차선 사이 영역을 반투명 초록으로 채우기
    if left_lane and right_lane:
        pts = np.array([
            [left_lane[0], left_lane[1]],
            [left_lane[2], left_lane[3]],
            [right_lane[2], right_lane[3]],
            [right_lane[0], right_lane[1]]
        ], dtype=np.int32)
        cv2.fillPoly(overlay, [pts], (0, 255, 0))
        result = cv2.addWeighted(image, 0.8, overlay, 0.2, 0)
    else:
        result = overlay

    return result, left_lane, right_lane

    Step 4: 차선 중심 편차 계산¶

    검출된 차선으로부터 차량이 얼마나 벗어나 있는지 계산합니다.

    def compute_offset(left_lane, right_lane, image_width):
    """
    차선 중심과 차량 중심의 편차(offset) 계산
    양수: 차량이 왼쪽으로 치우침 → 오른쪽으로 조향 필요
    음수: 차량이 오른쪽으로 치우침 → 왼쪽으로 조향 필요
    """
    vehicle_center = image_width / 2

    if left_lane and right_lane:
        # 이미지 하단에서 양쪽 차선의 x 좌표
        left_x = left_lane[0]
        right_x = right_lane[0]
        lane_center = (left_x + right_x) / 2
        offset = lane_center - vehicle_center
    elif left_lane:
        # 왼쪽 차선만 보이면 → 대략적 추정
        offset = left_lane[0] + 200 - vehicle_center
    elif right_lane:
        # 오른쪽 차선만 보이면 → 대략적 추정
        offset = right_lane[0] - 200 - vehicle_center
    else:
        # 차선 없음 → 편차 0 (직진 유지)
        offset = 0

    # 픽셀 단위를 정규화 (-1.0 ~ 1.0)
    normalized_offset = offset / (image_width / 2)
    normalized_offset = np.clip(normalized_offset, -1.0, 1.0)

    return normalized_offset

    알아보기 📌: 한쪽 차선만 검출된 경우에도 대략적인 편차를 추정하는 것이 중요합니다. 실제 도로에서는 차선이 끊기거나 가려지는 상황이 빈번하기 때문입니다. 여기서 200이라는 값은 차선 폭의 절반을 픽셀 단위로
