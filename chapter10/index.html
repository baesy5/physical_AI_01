    상태와 행동 설계 – 로봇의 눈과 손을 정의하다¶

    Part 3 | [2권] 강화학습의 세계로 – 핵심 개념 이해하기 | 10차시 / 전체 20차시

    🎯 이 장에서 배우는 것¶

    • 바닥 센서의 연속적 값을 이산적 상태(discrete state)로 변환할 수 있다
    • 로봇이 취할 수 있는 행동 집합(action space)을 정의할 수 있다
    • 상태-행동 조합의 수를 계산하고, 이것이 Q-테이블의 크기가 됨을 이해할 수 있다
    • 상태와 행동 설계가 강화학습 성능에 미치는 영향을 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    지난 시간까지 우리는 강화학습의 기본 개념 — 에이전트, 환경, 보상 — 을 배웠습니다. 그런데 한 가지 빠진 것이 있어요.

    "로봇은 세상을 어떻게 바라보고, 어떤 행동을 할 수 있는 거지?"

    사람은 눈으로 세상을 보고, 손과 발로 행동합니다. 강화학습 에이전트도 마찬가지예요. 상태(State)는 로봇의 눈이고, 행동(Action)은 로봇의 손입니다.

    그런데 현실의 센서 값은 0~1023 같은 연속적인 숫자로 들어옵니다. 이걸 그대로 쓰면 경우의 수가 폭발해서 학습이 불가능해져요. 그래서 우리는 이 연속적인 값을 "검정이냐 흰색이냐" 같은 간단한 범주로 바꿔야 합니다.

    이번 장에서는 라인트레이서 로봇을 예로, 센서 값을 유한한 상태 목록으로 바꾸고, 행동을 정의하고, 이 둘을 조합해서 Q-테이블의 뼈대를 만들어 봅니다. 이 설계가 잘못되면 아무리 좋은 알고리즘도 소용없으니, 정말 중요한 단계예요! 🏗️

    📚 핵심 개념¶

    개념 1: 상태(State) — 로봇의 눈 👀¶

    비유부터 시작할게요.

    여러분이 어두운 방에서 바닥의 검은 테이프를 따라 걸어야 한다고 상상해보세요. 손전등 두 개를 들고 있는데, 하나는 왼발 앞을, 하나는 오른발 앞을 비춥니다. 각 손전등이 비추는 곳이 "검은 테이프 위인지, 흰 바닥인지"를 확인하면서 걸어가죠.

    이것이 바로 바닥 센서 2개로 상태를 파악하는 것입니다.

    정확한 정의: 상태(State)란 에이전트가 특정 시점에 환경으로부터 받아들이는 관찰 정보를 정리한 것입니다. 강화학습에서 에이전트는 현재 상태를 보고 다음 행동을 결정합니다.

    예시로 확인: 우리 라인트레이서에는 바닥 센서가 2개 있습니다. 각 센서는 0~1023 범위의 아날로그 값을 출력해요.

    • 값이 500 이상 → 검은 선 위 (검정 ⬛)
    • 값이 500 미만 → 흰 바닥 위 (흰색 ⬜)

    이렇게 나누면 센서 하나당 2가지, 센서 2개니까 2 × 2 = 4가지 상태가 만들어집니다!

    graph TD A["바닥 센서 2개의 조합"] --> S0["상태 0<br/>왼쪽: ⬛ 오른쪽: ⬛<br/>양쪽 다 선 위"] A --> S1["상태 1<br/>왼쪽: ⬛ 오른쪽: ⬜<br/>선이 왼쪽으로 치우침"] A --> S2["상태 2<br/>왼쪽: ⬜ 오른쪽: ⬛<br/>선이 오른쪽으로 치우침"] A --> S3["상태 3<br/>왼쪽: ⬜ 오른쪽: ⬜<br/>양쪽 다 선 밖"]

    💡 핵심 포인트: 연속적인 센서 값(0~1023)을 "검정/흰색"이라는 이산적(discrete) 범주로 바꾸는 과정을 이산화(discretization)라고 합니다.

    개념 2: 행동(Action) — 로봇의 손 🤖¶

    비유부터 시작할게요.

    게임 컨트롤러를 생각해보세요. 버튼이 많을수록 정교한 조작이 가능하지만, 게임을 처음 배우는 사람에게는 버튼이 적을수록 좋겠죠? 로봇의 행동도 마찬가지입니다. 처음에는 간단한 행동 몇 가지로 시작하는 것이 현명합니다.

    정확한 정의: 행동(Action)이란 에이전트가 특정 상태에서 선택할 수 있는 동작의 목록입니다. 이 목록 전체를 행동 공간(Action Space)이라고 부릅니다.

    예시로 확인: 우리 라인트레이서의 행동은 딱 3가지입니다.

    • 행동 0: 직진(FORWARD) — 양쪽 바퀴를 같은 속도로 회전
    • 행동 1: 좌회전(LEFT) — 왼쪽 바퀴를 느리게, 오른쪽 바퀴를 빠르게
    • 행동 2: 우회전(RIGHT) — 왼쪽 바퀴를 빠르게, 오른쪽 바퀴를 느리게
    graph LR ActionSpace["행동 공간<br/>(Action Space)"] --> A0["행동 0: 직진 ⬆️"] ActionSpace --> A1["행동 1: 좌회전 ↩️"] ActionSpace --> A2["행동 2: 우회전 ↪️"]

    개념 3: 상태-행동 조합과 Q-테이블의 탄생 📊¶

    비유부터 시작할게요.

    레스토랑 메뉴판을 떠올려보세요. 메인 요리 4종류, 음료 3종류가 있다면 가능한 조합은 4 × 3 = 12가지입니다. 손님(에이전트)은 이 12가지 조합 중 하나를 고르죠.

    강화학습에서도 동일합니다. 각 상태에서 어떤 행동을 골라야 할지 판단하려면, 모든 상태-행동 조합에 대해 "이 상태에서 이 행동이 얼마나 좋은가?"를 기록해둘 표가 필요합니다. 그것이 바로 Q-테이블이에요!

    정확한 정의: Q-테이블은 상태 × 행동 크기의 2차원 표로, 각 칸에 해당 상태에서 해당 행동을 했을 때 기대되는 가치(Q-value)를 저장합니다.

    예시로 확인: 우리의 경우:

    • 상태 4개 × 행동 3개 = 12칸의 Q-테이블
    graph TD subgraph Q-테이블 구조 direction TB Header["4개 상태 × 3개 행동 = 12칸"] S0["상태0 ⬛⬛"] --> S0A["직진: ?, 좌회전: ?, 우회전: ?"] S1["상태1 ⬛⬜"] --> S1A["직진: ?, 좌회전: ?, 우회전: ?"] S2["상태2 ⬜⬛"] --> S2A["직진: ?, 좌회전: ?, 우회전: ?"] S3["상태3 ⬜⬜"] --> S3A["직진: ?, 좌회전: ?, 우회전: ?"] end

    처음에는 모든 칸이 0으로 시작합니다. 로봇이 경험을 쌓으면서 이 값들이 업데이트되고, 결국 "상태 1(선이 왼쪽)이면 좌회전이 최고!"라는 지식이 숫자로 새겨지는 거예요.

    🔑 기억하세요: Q-테이블의 크기 = 상태 수 × 행동 수. 상태와 행동을 어떻게 설계하느냐가 Q-테이블의 크기를 결정하고, 학습 난이도를 좌우합니다!

    개념 4: 설계가 성능을 결정한다 ⚖️¶

    비유부터 시작할게요.

    같은 풍경을 찍더라도 카메라 해상도에 따라 사진의 품질이 달라지죠. 그런데 해상도가 무조건 높다고 좋을까요? 100메가픽셀 사진을 찍으면 디테일은 살지만, 저장 공간과 처리 시간이 어마어마해집니다.

    상태 설계도 같습니다.

    너무 단순한 설계 (해상도 낮음): 센서 2개를 합쳐서 "선 위" vs "선 밖" 딱 2개 상태로 만들면? 로봇이 선의 왼쪽에 있는지 오른쪽에 있는지 구분을 못 해요. 좌회전할지 우회전할지 판단 불가!

    너무 복잡한 설계 (해상도 높음): 센서 값 0~1023을 10단위로 쪼개서 각각 약 100개 구간으로 나누면? 상태 수가 100 × 100 = 10,000개, Q-테이블은 30,000칸! 학습이 한참 걸립니다.

    적절한 설계 (우리의 선택): 센서 2개를 각각 검정/흰색 2개로 나누면 상태 4개, Q-테이블 12칸. 라인트레이서에는 이 정도면 충분해요! ✨

    graph LR A["설계 선택"] --> B["너무 단순<br/>2상태 × 3행동 = 6칸<br/>❌ 구분 못함"] A --> C["적절 👍<br/>4상태 × 3행동 = 12칸<br/>✅ 학습 가능"] A --> D["너무 복잡<br/>10000상태 × 3행동 = 30000칸<br/>❌ 학습 너무 오래"]

    🔨 따라하기¶

    이제 직접 코드로 구현해봅시다! Python으로 상태와 행동을 정의하고, Q-테이블을 만들어보겠습니다.

    Step 1: 센서 값을 이산적 상태로 변환하는 함수 만들기¶

    센서가 보내는 연속적인 값을 "검정(1)" 또는 "흰색(0)"으로 바꾸는 함수를 만듭니다.

    def read_sensor(value, threshold=500):
    """
    센서 값을 이산적 상태로 변환
    - value: 센서의 아날로그 값 (0~1023)
    - threshold: 기준값 (이 이상이면 검정)
    - 반환: 1(검정) 또는 0(흰색)
    """
    if value >= threshold:
        return 1  # 검정 (선 위)
    else:
        return 0  # 흰색 (선 밖)

    💡 threshold(임계값) 은 "검정과 흰색을 가르는 기준점"이에요. 로봇마다, 바닥 재질마다 이 값이 달라질 수 있습니다.

    Step 2: 두 센서 값을 하나의 상태 번호로 합치기¶

    센서가 2개이므로, 두 결과를 조합하여 0~3 사이의 상태 번호를 만듭니다.

    def get_state(left_value, right_value, threshold=500):
    """
    왼쪽/오른쪽 센서 값을 받아 상태 번호(0~3)를 반환
    - 상태 0: 왼쪽=검정, 오른쪽=검정 (양쪽 다 선 위)
    - 상태 1: 왼쪽=검정, 오른쪽=흰색 (선이 왼쪽)
    - 상태 2: 왼쪽=흰색, 오른쪽=검정 (선이 오른쪽)
    - 상태 3: 왼쪽=흰색, 오른쪽=흰색 (선 밖)
    """
    left = read_sensor(left_value, threshold)
    right = read_sensor(right_value, threshold)
    state = left * 2 + right  # 이진수 조합!
    return state

    🤔 왜 left * 2 + right 인가요? 이것은 2비트 이진수를 십진수로 바꾸는 공식이에요. - (1, 1) → 1×2 + 1 = 3... 잠깐, 그러면 상태 번호가 뒤바뀌네요?

    사실 번호 자체는 중요하지 않아요. 4개 상태가 서로 구분만 되면 됩니다. 여기서는 편의상 (검정,검정)=3, (검정,흰색)=2, (흰색,검정)=1, (흰색,흰색)=0 이 됩니다. 코드의 주석과 매핑을 일치시키려면 아래 Step 3에서 이름표를 붙여줄게요.

    Step 3: 상태와 행동에 이름표 붙이기¶

    숫자만으로는 헷갈리니까, 의미 있는 이름을 딕셔너리로 정의합니다.

    # 상태 정의
STATE_NAMES = {

    Step 4: Q-테이블 초기화하기¶

    이제 진짜 Q-테이블을 만듭니다! NumPy를 사용하면 한 줄이면 됩니다.

    import numpy as np

# 모든 값을 0으로 초기화한 Q-테이블

    Step 5: 상태 변환 테스트하기¶

    실제 센서 값이 들어왔을 때 제대로 변환되는지 확인해봅시다.

    # 다양한 센서 값으로 테스트
test_cases = [
    (600, 620, "양쪽 다 선 위에 있을 때"),
    (700, 300, "선이 왼쪽으로 치우쳤을 때"),
    (200, 550, "선이 오른쪽으로 치우쳤을 때"),
    (100, 150, "양쪽 다 선 밖일 때"),
]

print("=== 센서 값 → 상태 변환 테스트 ===\n")
for left_val, right_val, description in test_cases:
    state = get_state(left_val, right_val)
    print(f"  {description}")
    print(f"    센서: 왼쪽={left_val}, 오른쪽={right_val}")
    print(f"    → 상태 {state}: {STATE_NAMES[state]}")
    print()

    Step 6: Q-테이블에서 행동 선택 시뮬레이션¶

    학습이 어느 정도 진행된 후의 Q-테이블을 가정하고, 어떻게 행동을 선택하는지 체험해봅시다.

    # 학습이 진행된 후의 Q-테이블 (가상의 값)
q_table_trained = np.array([
    [0.0, 0.0, 0.0],   # 상태 0: 양쪽 흰색 → 아직 잘 모름
    [0.2, 0.1, 0.9],   # 상태 1: 선이 오른쪽 → 우회전이 최고!
    [0.3, 0.8, 0.1],   # 상태 2: 선이 왼쪽 → 좌회전이 최고!
    [0.9, 0.2, 0.2],   # 상태 3: 양쪽 선 위 → 직진이 최고!
])

print("=== 학습된 Q-테이블로 행동 선택 ===\n")
for state in range(NUM_STATES):
    best_action = np.argmax(q_table_trained[state])
    q_values = q_table_trained[state]
    print(f"  상태 {state} ({STATE_NAMES[state]})")
    print(f"    Q값: 직진={q_values[0]:.1f}, 좌회전={q_values[1]:.1f}, 우회전={q_values[2]:.1f}")
    print(f"    → 최선의 행동: {ACTION_NAMES[best_action]}")
    print()

    np.argmax()는 배열에서 가장 큰 값의 인덱스를 반환합니다. Q값이 가장 높은 행동 = 최선의 행동이 되는 거죠!

    📝 전체 코드¶

    아래 코드를 복사해서 바로 실행해보세요!

    import numpy as np

# === 1. 센서 값 이산화 함수 ===
def read_sensor(value, threshold=500):
    """센서 값을 검정(1) 또는 흰색(0)으로 변환"""
    if value >= threshold:
        return 1
    else:
        return 0

def get_state(left_value, right_value, threshold=500):
    """두 센서 값을 상태 번호(0~3)로 변환"""
    left = read_sensor(left_value, threshold)
    right = read_sensor(right_value, threshold)
    state = left * 2 + right
    return state

# === 2. 상태와 행동 정의 ===
STATE_NAMES = {
    0: "⬜⬜ 양쪽 흰색 (선 밖)",
    1: "⬜⬛ 선이 오른쪽",
    2: "⬛⬜ 선이 왼쪽",
    3: "⬛⬛ 양쪽 검정 (선 위)",
}

ACTION_NAMES = {
    0: "⬆️ 직진 (FORWARD)",
    1: "↩️ 좌회전 (LEFT)",
    2: "↪️ 우회전 (RIGHT)",
}

NUM_STATES = len(STATE_NAMES)
NUM_ACTIONS = len(ACTION_NAMES)

# === 3. Q-테이블 초기화 ===
q_table = np.zeros((NUM_STATES, NUM_ACTIONS))

print("=" * 50)
print("🤖 라인트레이서 강화학습 - 상태/행동 설계")
print("=" * 50)
print(f"\n📊 상태 수: {NUM_STATES}, 행동 수: {NUM_ACTIONS}")
print(f"📋 Q-테이블 크기: {NUM_STATES} × {NUM_ACTIONS} = {NUM_STATES * NUM_ACTIONS}칸\n")

# === 4. 센서 변환 테스트 ===
print("--- 센서 값 → 상태 변환 테스트 ---\n")
test_cases = [
    (600, 620, "양쪽 다 선 위"),
    (700, 300, "선이 왼쪽으로 치우침"),
    (200, 550, "선이 오른쪽으로 치우침"),
    (100, 150, "양쪽 다 선 밖"),
]

for left_val, right_val, desc in test_cases:
    state = get_state(left_val, right_val)
    print(f"  센서({left_val}, {right_val}) → 상태 {state}: {STATE_NAMES[state]}  ({desc})")

# === 5. 학습된 Q-테이블 시뮬레이션 ===
q_table_trained = np.array([
    [0.0, 0.0, 0.0],
    [0.2, 0.1, 0.9],
    [0.3, 0.8, 0.1],
    [0.9, 0.2, 0.2],
])

print("\n--- 학습된 Q-테이블에서 행동 선택 ---\n")
for state in range(NUM_STATES):
    best_action = np.argmax(q_table_trained[state])
    print(f"  상태 {state} → 최선의 행동: {ACTION_NAMES[best_action]}")

print("\n✅ 상태-행동 설계 완료! Q-테이블의 뼈대가 준비되었습니다.")
