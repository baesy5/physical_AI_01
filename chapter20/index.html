    Chapter 20: 결과 비교와 분석 – 규칙 기반 vs 강화학습¶

    🏁 드디어 마지막 챕터입니다! 20차시 동안 함께 달려온 여정의 피날레를 장식해봅시다.

    🎯 이 장에서 배우는 것¶

    • 규칙 기반과 Q-learning 라인트레이싱의 성능을 정량적 지표로 비교할 수 있다
    • 각 접근 방식의 장단점을 개발 시간, 적응성, 성능 관점에서 분석할 수 있다
    • 프로젝트 전체를 돌아보며 강화학습 핵심 개념을 자신의 언어로 종합 정리할 수 있다
    • 강화학습이 실제 세상에서 어떻게 활용되는지 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    요리 대회를 상상해보세요. 🍳

    한 참가자는 레시피북을 보고 정확히 따라 만들었고, 다른 참가자는 수백 번 시행착오를 거쳐 자기만의 감을 익힌 뒤 요리했습니다. 둘 다 맛있는 요리를 만들 수 있지만, "새로운 재료가 주어졌을 때" 누가 더 잘 대응할까요?

    우리도 지금까지 두 가지 방식으로 햄스터 로봇을 주행시켰습니다.

    • 규칙 기반: 사람이 직접 "센서 값이 이러면 이렇게 해라"라고 작성
    • Q-learning: 로봇이 스스로 시행착오를 통해 주행 전략을 학습

    이제 이 둘을 같은 트랙에서 동시에 평가하고, 숫자로 비교하는 시간입니다. 단순히 "어느 게 더 좋다"가 아니라, 각각 언제 빛나는지를 이해하는 것이 진짜 실력입니다.

    📚 핵심 개념¶

    개념 1: 성능 측정 지표 📊¶

    비유: 학교 성적표에 국어, 수학, 영어 점수가 따로 있듯이, 로봇 주행도 여러 각도에서 점수를 매겨야 공정합니다.

    정의: 성능 측정 지표(Performance Metrics)란, 두 알고리즘을 객관적으로 비교하기 위해 측정하는 수치화된 기준입니다.

    우리가 사용할 지표 4가지:

    • 완주 시간(Lap Time) ⏱️: 트랙 한 바퀴를 도는 데 걸린 시간(초). 짧을수록 좋음
    • 이탈 횟수(Off-track Count) 🚧: 주행 중 라인을 완전히 벗어난 횟수. 적을수록 좋음
    • 누적 보상(Cumulative Reward) 💰: 한 에피소드 동안 받은 총 보상. 높을수록 좋음
    • 주행 안정성(Smoothness) 🌊: 급격한 방향 전환 횟수. 적을수록 부드러운 주행

    개념 2: 공정한 비교 실험 설계 ⚖️¶

    비유: 100m 달리기를 비교하려면, 두 선수가 같은 트랙, 같은 날씨, 같은 출발선에서 뛰어야 합니다. 한 명은 흙바닥, 한 명은 우레탄 트랙이면 비교가 무의미하죠.

    정의: 공정한 비교란, 비교 대상 외의 모든 조건(트랙 모양, 센서, 속도 범위 등)을 동일하게 맞추고 실험하는 것입니다.

    우리 실험의 통제 조건:

    • 동일한 트랙(같은 검은 테이프 경로)
    • 동일한 햄스터 로봇(배터리 상태도 비슷하게)
    • 동일한 센서 읽기 방식
    • 각 방식당 최소 5회 반복 실행 → 평균 사용

    개념 3: 정성적 분석 – 장단점 비교 🔍¶

    비유: 자전거와 자동차를 비교할 때, 단순히 "속도"만 보면 자동차가 이깁니다. 하지만 "주차 편의성", "운동 효과", "유지비"를 함께 보면 이야기가 달라지죠.

    정의: 정성적 분석이란 숫자로 측정하기 어려운 측면(개발 난이도, 확장 가능성, 유지보수 등)을 종합적으로 평가하는 것입니다.

    비교 관점:

    • 개발 시간: 코드를 처음 작성하는 데 얼마나 걸렸나?
    • 적응성: 트랙이 바뀌면 어떻게 되나?
    • 이해 가능성: 로봇이 왜 그렇게 행동하는지 설명할 수 있나?
    • 확장 가능성: 더 복잡한 문제에 적용할 수 있나?

    개념 4: 프로젝트 종합 회고 🧩¶

    비유: 퍼즐을 다 맞추고 나면, 한 발 물러서서 전체 그림을 감상하는 시간이 필요합니다. 조각 하나하나에 집중했던 순간들이 모여 어떤 그림이 되었는지 보는 거예요.

    정의: 프로젝트 회고란, 전체 학습 과정에서 배운 핵심 개념들을 연결하고, 무엇을 잘했고 무엇이 아쉬웠는지 돌아보는 과정입니다.

    graph LR A[에이전트<br/>햄스터 로봇] -->|행동 선택| B[환경<br/>트랙] B -->|상태 + 보상| A A -->|경험 저장| C[Q-테이블] C -->|전략 개선| A D[탐험 ↔ 활용] -->|균형 조절| A E[에피소드 반복] -->|점점 똑똑해짐| C

    이 다이어그램은 우리가 20차시 동안 배운 강화학습의 핵심 순환 구조입니다.

    🔨 따라하기¶

    Step 1: 성능 측정 코드 준비하기¶

    먼저, 두 방식 모두에 공통으로 사용할 성능 측정 도구를 만듭니다.

    import time

class PerformanceTracker:
    """주행 성능을 측정하는 도구"""

    def __init__(self):
        self.start_time = None
        self.off_track_count = 0
        self.total_reward = 0
        self.direction_changes = 0
        self.last_action = None

    def start(self):
        """측정 시작"""
        self.start_time = time.time()
        self.off_track_count = 0
        self.total_reward = 0
        self.direction_changes = 0
        self.last_action = None
        print("⏱️ 성능 측정을 시작합니다!")

    def record_step(self, action, reward, is_off_track):
        """매 스텝마다 기록"""
        self.total_reward += reward

        if is_off_track:
            self.off_track_count += 1

        if self.last_action is not None and action != self.last_action:
            self.direction_changes += 1
        self.last_action = action

    def finish(self):
        """측정 종료 및 결과 반환"""
        elapsed = time.time() - self.start_time
        result = {
            "완주 시간(초)": round(elapsed, 2),
            "이탈 횟수": self.off_track_count,
            "누적 보상": round(self.total_reward, 2),
            "방향 전환 횟수": self.direction_changes
        }
        print("🏁 측정 완료!")
        for key, value in result.items():
            print(f"  {key}: {value}")
        return result

    💡 이 클래스는 규칙 기반이든 Q-learning이든 동일하게 사용합니다. 공정한 비교의 첫걸음이에요!

    Step 2: 규칙 기반 주행 + 성능 측정¶

    이전 챕터에서 만든 규칙 기반 코드에 성능 측정을 붙입니다.

    from roboid import Hamster
import time

hamster = Hamster()
tracker = PerformanceTracker()

def get_state():
    """센서 값을 상태로 변환"""
    left = hamster.left_floor()
    right = hamster.right_floor()
    threshold = 50
    if left < threshold and right < threshold:
        return "both_black"      # 라인 위 정중앙
    elif left < threshold:
        return "left_black"      # 라인이 왼쪽에
    elif right < threshold:
        return "right_black"     # 라인이 오른쪽에
    else:
        return "both_white"      # 라인 이탈

def rule_based_action(state):
    """규칙 기반 행동 결정"""
    if state == "both_black":
        return "forward"
    elif state == "left_black":
        return "turn_left"
    elif state == "right_black":
        return "turn_right"
    else:  # both_white
        return "turn_right"  # 이탈 시 오른쪽으로 복귀 시도

def execute_action(action):
    """행동 실행"""
    if action == "forward":
        hamster.wheels(30, 30)
    elif action == "turn_left":
        hamster.wheels(10, 30)
    elif action == "turn_right":
        hamster.wheels(30, 10)

# 규칙 기반 주행 실행 (한 바퀴)
tracker.start()
steps = 0
max_steps = 500  # 최대 스텝 수

while steps < max_steps:
    state = get_state()
    action = rule_based_action(state)
    execute_action(action)

    is_off = (state == "both_white")
    reward = 1 if state == "both_black" else (0.5 if state != "both_white" else -1)

    tracker.record_step(action, reward, is_off)
    steps += 1
    time.sleep(0.05)

hamster.stop()
rule_result = tracker.finish()

    Step 3: Q-learning 주행 + 성능 측정¶

    학습이 완료된 Q-테이블을 로드하여 주행합니다.

    import json

# 학습된 Q-테이블 불러오기
with open("q_table.json", "r") as f:
    q_table = json.load(f)

actions = ["forward", "turn_left", "turn_right"]

def q_learning_action(state):
    """Q-테이블에서 최적 행동 선택 (활용만)"""
    if state in q_table:
        values = q_table[state]
        best_idx = values.index(max(values))
        return actions[best_idx]
    else:
        return "forward"  # 처음 보는 상태면 직진

# Q-learning 주행 실행 (한 바퀴)
tracker_q = PerformanceTracker()
tracker_q.start()
steps = 0

while steps < max_steps:
    state = get_state()
    action = q_learning_action(state)
    execute_action(action)

    is_off = (state == "both_white")
    reward = 1 if state == "both_black" else (0.5 if state != "both_white" else -1)

    tracker_q.record_step(action, reward, is_off)
    steps += 1
    time.sleep(0.05)

hamster.stop()
ql_result = tracker_q.finish()

    Step 4: 결과 비교 시각화¶

    두 방식의 결과를 한눈에 비교합니다.

    def compare_results(rule_results, ql_results, num_trials=5):
    """여러 번 실험한 결과의 평균을 비교"""

    print("\n" + "=" * 50)
    print("📊 성능 비교 결과 (평균)")
    print("=" * 50)

    metrics = ["완주 시간(초)", "이탈 횟수", "누적 보상", "방향 전환 횟수"]

    for metric in metrics:
        rule_avg = sum(r[metric] for r in rule_results) / len(rule_results)
        ql_avg = sum(r[metric] for r in ql_results) / len(ql_results)

        # 어느 쪽이 나은지 판단
        if metric in ["완주 시간(초)", "이탈 횟수", "방향 전환 횟수"]:
            winner = "규칙 기반 ✅" if rule_avg <= ql_avg else "Q-learning ✅"
        else:
            winner = "규칙 기반 ✅" if rule_avg >= ql_avg else "Q-learning ✅"

        print(f"\n📌 {metric}")
        print(f"   규칙 기반:  {rule_avg:.2f}")
        print(f"   Q-learning: {ql_avg:.2f}")
        print(f"   → 우세: {winner}")

    print("\n" + "=" * 50)

    규칙 기반의 강점 🛡️

    • 개발이 빠르고 직관적 — "센서가 이러면 이렇게 해"가 전부
    • 동작 원리를 누구에게나 설명할 수 있음
    • 단순한 트랙에서는 안정적이고 예측 가능한 성능
    • 디버깅이 쉬움 — 문제가 생기면 규칙을 고치면 됨

    규칙 기반의 약점 ⚡

    • 트랙이 바뀌면 규칙을 사람이 직접 수정해야 함
    • 복잡한 상황(교차로, 급커브 연속 등)에서 규칙이 폭발적으로 늘어남
    • 사람이 미처 생각하지 못한 상황에 대응 불가

    Q-learning의 강점 🌟

    • 환경이 바뀌어도 재학습하면 적응 가능
    • 사람이 예상하지 못한 전략을 스스로 발견할 수 있음
    • 문제가 복잡해져도 기본 구조(상태-행동-보상)는 동일
    • 보상 설계만 잘하면 다양한 문제에 범용 적용 가능

    Q-learning의 약점 ⚡

    • 학습에 시간이 많이 걸림 (수백~수천 에피소드)
    • 왜 그런 행동을 하는지 설명하기 어려울 수 있음 (블랙박스)
    • 보상 설계가 잘못되면 엉뚱한 행동을 학습
    • 상태 공간이 커지면 Q-테이블이 감당하기 어려워짐

    Step 6: 20차시 프로젝트 종합 회고¶

    # 우리가 20차시 동안 배운 것을 코드 주석으로 정리합니다

"""
🧩 강화학습 핵심 개념 총정리

1. 에이전트(Agent): 행동을 결정하는 주체 → 햄스터 로봇
2. 환경(Environment): 에이전트가 상호작용하는 세계 → 트랙
3. 상태(State): 현재 상황을 나타내는 정보 → 센서 값 조합
4. 행동(Action): 에이전트가 선택할 수 있는 것 → 직진, 좌회전, 우회전
5. 보상(Reward): 행동의 결과에 대한 피드백 → +1, -1 등
6. Q-테이블: 각 (상태, 행동) 쌍의 가치를 기록한 표
7. 탐험(Exploration): 새로운 행동을 시도 → epsilon 확률로
8. 활용(Exploitation): 알고 있는 최선을 선택 → Q값이 가장 높은 행동
9. 학습률(alpha): 새 경험을 얼마나 반영할지 → 0.1 ~ 0.5
10. 할인율(gamma): 미래 보상을 얼마나 중시할지 → 0.9 ~ 0.99
11. 에피소드: 시작부터 종료까지 한 번의 시도
12. 수렴: Q값이 안정되어 더 이상 크게 변하지 않는 상태
"""

# 우리의 학습 여정
journey = {
    "Part 1": "강화학습이 뭔지 알게 됨 🌱",
    "Part 2": "격자 세계에서 Q-learning 구현 🎮",
    "Part 3": "시뮬레이션으로 라인트레이싱 학습 🖥️",
    "Part 4": "실제 햄스터 로봇에 적용 🤖",
    "Part 5": "결과를 분석하고 의미를 찾음 📊"
}

for part, description in journey.items():
    print(f"{part}: {description}")

print("\n🎓 축하합니다! 강화학습의 전체 과정을 완주했습니다!")

    📝 전체 코드¶

    아래는 비교 실험을 5회 반복하고 결과를 정리하는 통합 코드입니다.

    import time
import json
from roboid import Hamster

# ── 성능 측정 도구 ──
class PerformanceTracker:
    def __init__(self):
        self.reset()

    def reset(self):
        self.start_time = None
        self.off_track_count = 0
        self.total_reward = 0
        self.direction_changes = 0
        self.last_action = None

    def start(self):
        self.reset()
        self.start_time = time.time()

    def record_step(self, action, reward, is_off_track):
        self.total_reward += reward
        if is_off_track:
            self.off_track_count += 1
        if self.last_action is not None and action != self.last_action:
            self.direction_changes += 1
        self.last_action = action

    def finish(self):
        elapsed = time.time() - self.start_time
        return {
            "완주 시간(초)": round(elapsed, 2),
            "이탈 횟수": self.off_track_count,
            "누적 보상": round(self.total_reward, 2),
            "방향 전환 횟수": self.direction_changes
        }

# ── 공통 함수 ──
hamster = Hamster()
THRESHOLD = 50
MAX_STEPS = 500
ACTIONS = ["forward", "turn_left", "turn_right"]

def get_state():
    left = hamster.left_floor()
    right = hamster.right_floor()
    if left < THRESHOLD and right < THRESHOLD:
        return "both_black"
    elif left < THRESHOLD:
        return "left_black"
    elif right < THRESHOLD:
        return "right_black"
    else:
        return "both_white"

def execute_action(action):
    if action == "forward":
        hamster.wheels(30, 30)
    elif action == "turn_left":
        hamster.wheels(10, 30)
    elif action == "turn_right":
        hamster.wheels(30, 10)

def get_reward(state):
    if state == "both_black":
        return 1.0
    elif state == "both_white":
        return -1.0
    else:
        return 0.5

# ── 규칙 기반 ──
def rule_based_action(state):
    rules = {
        "both_black": "forward",
        "left_black": "turn_left",
        "right_black": "turn_right",
        "both_white": "turn_right"
    }
    return rules.get(state, "forward")

# ── Q-learning ──
with open("q_table.json", "r") as f:
    q_table = json.load(f)

def q_learning_action(state):
    if state in q_table:
        values = q_table[state]
        return ACTIONS[values.index(max(values))]
    return "forward"

# ── 실험 실행 ──
def run_trial(action_fn, label):
    tracker = PerformanceTracker()
    tracker.start()
    for _ in range(MAX_STEPS):
        state = get_state()
        action = action_fn(state)
        execute_action(action)
        reward = get_reward(state)
        is_off = (state == "both_white")
        tracker.record_step(action, reward, is_off)
        time.sleep(0.05)
    hamster.stop()
    result = tracker.finish()
    print(f"  [{label}] {result}")
    return result

# 5회 반복 실험
NUM_TRIALS = 5
rule_results = []
ql_results = []

for i in range(NUM_TRIALS):
    print(f"\n--- 실험 {i+1}/{NUM_TRIALS} ---")
    input("규칙 기반 준비되면 Enter...")
    rule_results.append(run_trial(rule_based_action, "규칙 기반"))
    time.sleep(2)

    input("Q-learning 준비되면 Enter...")
    ql_results.append(run_trial(q_learning_action, "Q-learning"))
    time.sleep(2)

# ── 결과 비교 ──
print("\n" + "=" * 50)
print("📊 최종 성능 비교 (5회 평균)")
print("=" * 50)

for metric in ["완주 시간(초)", "이탈 횟수", "누적 보상", "방향 전환 횟수"]:
    r_avg = sum(r[metric] for r in rule_results) / NUM_TRIALS
    q_avg = sum(r[metric] for r in ql_results) / NUM_TRIALS
    print(f"\n📌 {metric}")
    print(f"   규칙 기반:  {r_avg:.2f}")
    print(f"   Q-learning: {q_avg:.2f}")

print("\n🎉 비교 실험이 완료되었습니다!")

    ⚠️ 자주 하는 실수¶

    실수 1: 한 번 실행으로 결론 내리기 🎲

    로봇은 매번 약간씩 다르게 동작합니다(배터리 상태, 바닥 상태 등). 반드시 5회 이상 반복하고 평균을 사용하세요. 한 번의 결과로 "Q-learning이 더 나빠!"라고 단정짓지 마세요.

    실수 2: 학습 중인 Q-테이블로 비교하기 📉

    Q-learning은 학습이 충분히 끝난 Q-테이블(수렴된 상태)을 사용해야 합니다. 에피소드 50번 돌린 미완성 Q-테이블과 비교하면 당연히 규칙 기반이 압승합니다. 이것은 공정한 비교가 아닙니다.

    실수 3: "무조건 강화학습이 좋다"는 편견 🤔

    강화학습은 만능이 아닙니다. 단순한 문제에서는 규칙 기반이 더 효율적인 경우가 많습니다. "이 문제에 어떤 방법이 적합한가?"를 판단하는 능력이 진짜 실력입니다. 복잡도가 낮으면 규칙 기반, 복잡도가 높고 환경이 변하면 강화학습을 고려하세요.
