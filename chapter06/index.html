    라인트레이싱의 원리와 센서 상태 분류¶

    Part 2 | [1권] 라인트레이싱 – 로봇이 선을 따라 달린다

    🎯 이 장에서 배우는 것¶

    • 라인트레이싱의 기본 원리(센서→판단→동작 루프)를 설명할 수 있다
    • 바닥 센서 2개의 값 조합으로 4가지 상태를 분류할 수 있다
    • 센서 값을 측정하여 적절한 임계값(threshold)을 설정할 수 있다
    • 상태 분류 결과를 코드로 구현할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분, 자동차 공장에서 부품을 나르는 로봇을 본 적 있나요? 물류 창고에서 바닥의 선을 따라 움직이는 로봇은 이미 우리 생활 곳곳에서 활약하고 있어요. 이 로봇들의 가장 기본이 되는 기술이 바로 라인트레이싱입니다.

    라인트레이싱은 "센서로 보고, 판단하고, 움직인다"는 로봇 제어의 핵심 구조를 가장 직관적으로 체험할 수 있는 주제예요. 그리고 이 장에서 배우는 상태 분류라는 개념은, 나중에 강화학습에서 로봇이 "지금 내가 어떤 상황인지" 파악하는 State(상태) 개념과 정확히 같은 구조입니다.

    쉽게 말해, 이 장은 로봇에게 "눈"을 달아주고, 눈에 보이는 것을 분류하는 방법을 가르쳐주는 시간이에요! 👀

    📚 핵심 개념¶

    개념 1: 라인트레이싱이란? 🚗¶

    비유로 시작해볼게요.

    눈을 감고 걸어본 적 있나요? 아마 몇 걸음 못 가서 방향을 잃었을 거예요. 이번엔 눈을 뜨고 바닥의 흰 점선을 따라 걸어보세요. 쉽죠? 이때 여러분의 몸은 이런 과정을 반복하고 있어요.

    1. 눈으로 선이 어디 있는지 본다
    2. 뇌에서 "왼쪽으로 치우쳤네, 오른쪽으로 가야겠다"고 판단한다
    3. 다리가 오른쪽으로 방향을 틀어 걷는다

    이 과정을 로봇으로 옮기면 그게 바로 라인트레이싱입니다!

    정확한 정의:

    라인트레이싱(Line Tracing) 이란, 로봇이 바닥에 그려진 선(주로 검은 테이프)을 센서로 감지하면서 자율적으로 따라가는 주행 방식이다.

    로봇에서의 대응 관계:

    • 🧑 사람의 눈 → 🤖 로봇의 바닥 센서(IR 센서)
    • 🧑 사람의 뇌 → 🤖 로봇의 프로그램(판단 로직)
    • 🧑 사람의 다리 → 🤖 로봇의 모터(바퀴)
    flowchart LR A["👁️ 센서\n(바닥을 본다)"] --> B["🧠 판단\n(어디로 갈지 결정)"] B --> C["🦿 동작\n(모터를 제어)"] C --> A

    이 센서 → 판단 → 동작 의 반복 구조를 제어 루프(Control Loop) 라고 불러요. 로봇은 이 루프를 1초에 수십~수백 번 반복하면서 선을 따라갑니다. 사람이 걸으면서 끊임없이 눈으로 확인하는 것과 똑같죠!

    개념 2: 바닥 센서는 어떻게 작동할까? 🔦¶

    비유로 시작해볼게요.

    어두운 방에서 손전등을 켜고 바닥을 비춰보세요. 흰 바닥은 빛을 많이 반사해서 밝게 보이고, 검은 종이 위는 빛이 흡수되어 어둡게 보이죠? 바닥 센서도 정확히 이 원리입니다.

    정확한 정의:

    IR(적외선) 바닥 센서는 적외선 빛을 바닥에 쏘고, 반사되어 돌아오는 빛의 양을 측정하는 센서이다.

    작동 원리:

    • 흰 바닥 → 빛 반사 多 → 센서 값이 높음 (예: 800~1000)
    • 검은 선 → 빛 흡수 多 → 센서 값이 낮음 (예: 100~300)

    우리 햄스터 로봇에는 바닥 센서가 왼쪽, 오른쪽 2개 달려 있어요. 이 2개의 센서가 바로 로봇의 "두 눈" 역할을 합니다.

    flowchart TB subgraph 로봇["🤖 로봇 (위에서 본 모습)"] L["왼쪽 센서\n(Left)"] R["오른쪽 센서\n(Right)"] end L -->|"빛 반사량 측정"| FLOOR["바닥"] R -->|"빛 반사량 측정"| FLOOR

    센서 값은 0~100 범위의 숫자로 들어오는데, 실제 값은 환경(조명, 바닥 색상, 테이프 종류)에 따라 달라져요. 그래서 직접 측정해보는 과정이 꼭 필요합니다!

    개념 3: 4가지 상태 분류 📋¶

    비유로 시작해볼게요.

    횡단보도를 건너는 상황을 생각해보세요. 왼발이 흰 줄 위에 있을 수도 있고, 오른발이 흰 줄 위에 있을 수도 있고, 둘 다 줄 위이거나 둘 다 벗어나 있을 수도 있죠. 이렇게 왼발·오른발 각각이 "줄 위" 또는 "줄 밖" 2가지이니, 조합하면 2 × 2 = 4가지 경우가 생겨요.

    로봇도 똑같습니다! 왼쪽 센서와 오른쪽 센서가 각각 "검은 선 위" 또는 "흰 바닥 위" 2가지이므로, 총 4가지 상태가 만들어져요.

    정확한 정의:

    2개의 센서가 각각 흰색(W) 또는 검정(B)을 감지할 때, 가능한 조합은 4가지이며, 각 조합은 로봇의 현재 위치를 나타내는 상태(State) 가 된다.

    4가지 상태와 의미:

    flowchart TB subgraph S1["상태 1: 둘 다 흰색 (W, W)"] direction LR S1D["로봇이 선 위에 잘 있다\n→ 직진! ⬆️"] end subgraph S2["상태 2: 왼쪽만 검정 (B, W)"] direction LR S2D["로봇이 오른쪽으로 치우쳤다\n→ 왼쪽으로 틀어! ⬅️"] end subgraph S3["상태 3: 오른쪽만 검정 (W, B)"] direction LR S3D["로봇이 왼쪽으로 치우쳤다\n→ 오른쪽으로 틀어! ➡️"] end subgraph S4["상태 4: 둘 다 검정 (B, B)"] direction LR S4D["선을 완전히 벗어났거나 교차로\n→ 정지 또는 특별 동작 🛑"] end

    🤔 잠깐, 헷갈릴 수 있는 포인트!

    "왼쪽 센서가 검은 선을 감지했다"는 것은 왼쪽 센서 아래에 검은 선이 있다는 뜻이에요. 이 말은 로봇이 선의 오른쪽으로 치우쳐서 왼쪽 센서가 선 위에 올라간 거예요. 그래서 왼쪽으로 꺾어야 다시 중앙으로 돌아옵니다.

    이 4가지 상태가 정리되면, 로봇의 "판단"은 아주 심플해집니다. 상태를 보고 정해진 동작을 하면 되니까요!

    개념 4: 임계값(Threshold) 설정 🎚️¶

    비유로 시작해볼게요.

    시험에서 "60점 이상이면 합격"이라는 기준이 있죠? 59점은 불합격, 60점은 합격. 이 60점이 바로 임계값입니다. 센서도 마찬가지로, "이 값 이상이면 흰색, 이하면 검정"이라고 판단하는 기준점이 필요해요.

    정확한 정의:

    임계값(Threshold) 이란, 센서 값을 두 그룹(흰색 / 검정)으로 분류하기 위한 기준값이다.

    임계값을 정하는 방법:

    1. 흰 바닥 위에서 센서 값을 여러 번 측정한다 (예: 80, 85, 78, 82…)
    2. 검은 테이프 위에서 센서 값을 여러 번 측정한다 (예: 15, 20, 18, 22…)
    3. 두 값의 중간값을 임계값으로 설정한다

    예를 들어, 흰 바닥 평균이 80이고 검은 테이프 평균이 20이라면:

    임계값 = (80 + 20) ÷ 2 = 50

    센서 값이 50 이상이면 "흰색", 50 미만이면 "검정"으로 판단하는 거죠!

    flowchart LR V["센서 값"] --> CMP{"값 ≥ 임계값?"} CMP -->|"Yes"| W["⬜ 흰색"] CMP -->|"No"| B["⬛ 검정"]

    ⚡ 왜 직접 측정해야 할까요?

    같은 센서라도 조명 밝기, 바닥 재질, 테이프 종류에 따라 값이 크게 달라져요. 실험실에서 잘 되던 코드가 집에서 안 되는 이유가 바로 이것! 그래서 환경이 바뀌면 임계값도 다시 측정해야 합니다.

    🔨 따라하기¶

    이제 직접 로봇의 센서 값을 측정하고, 임계값을 설정하고, 4가지 상태를 분류하는 코드를 만들어볼 거예요!

    Step 1: 센서 값 읽어보기 👀¶

    먼저 로봇의 바닥 센서가 어떤 값을 보내주는지 확인해봅시다.

    from roboid import *

hamster = Hamster()

# 5초 동안 센서 값을 관찰하기
for i in range(50):
    left = hamster.left_floor()    # 왼쪽 바닥 센서
    right = hamster.right_floor()  # 오른쪽 바닥 센서
    print(f"왼쪽: {left}, 오른쪽: {right}")
    wait(100)  # 0.1초 대기

    로봇을 흰 바닥 위에 놓고 실행해보세요. 어떤 숫자가 나오나요? 이번엔 검은 테이프 위에 놓고 다시 실행해보세요. 값이 확 달라지는 게 보일 거예요!

    Step 2: 흰색과 검정의 센서 값 기록하기 📝¶

    좀 더 체계적으로 측정해봅시다. 아래 코드는 센서 값을 10번 측정해서 평균을 구해줍니다.

    from roboid import *

hamster = Hamster()

def measure_average(label):
    """센서 값을 10번 측정하여 평균을 구하는 함수"""
    left_total = 0
    right_total = 0
    count = 10

    print(f"\n--- {label} 측정 시작 ---")
    print("3초 후 측정을 시작합니다. 로봇을 위치시켜주세요!")
    wait(3000)

    for i in range(count):
        left = hamster.left_floor()
        right = hamster.right_floor()
        left_total += left
        right_total += right
        print(f"  {i+1}번째: 왼쪽={left}, 오른쪽={right}")
        wait(200)

    left_avg = left_total / count
    right_avg = right_total / count
    print(f"평균: 왼쪽={left_avg:.1f}, 오른쪽={right_avg:.1f}")
    return left_avg, right_avg

# 흰 바닥에서 측정
print("로봇을 흰 바닥 위에 놓아주세요!")
white_left, white_right = measure_average("흰 바닥")

# 검은 테이프에서 측정
print("\n로봇을 검은 테이프 위에 놓아주세요!")
black_left, black_right = measure_average("검은 테이프")

# 결과 출력
print("\n========== 측정 결과 ==========")
print(f"흰 바닥 - 왼쪽: {white_left:.1f}, 오른쪽: {white_right:.1f}")
print(f"검은 선 - 왼쪽: {black_left:.1f}, 오른쪽: {black_right:.1f}")

    실행 후 나온 값을 종이나 메모장에 적어두세요. 이 값을 바탕으로 임계값을 정할 거예요!

    Step 3: 임계값 계산하기 🧮¶

    Step 2에서 측정한 값으로 임계값을 계산합니다.

    # Step 2의 코드에 이어서 추가하세요

# 임계값 계산: 흰색 평균과 검정 평균의 중간값
threshold_left = (white_left + black_left) / 2
threshold_right = (white_right + black_right) / 2

# 좌우 센서의 임계값이 비슷하면 하나로 통일하는 것이 편리
threshold = (threshold_left + threshold_right) / 2

print(f"\n========== 임계값 ==========")
print(f"왼쪽 센서 임계값: {threshold_left:.1f}")
print(f"오른쪽 센서 임계값: {threshold_right:.1f}")
print(f"통합 임계값: {threshold:.1f}")

    💡 팁: 왼쪽과 오른쪽 센서의 임계값이 크게 다르지 않다면, 하나의 통합 임계값을 사용하는 게 코드가 간결해져요. 만약 차이가 크다면 각각 따로 쓰는 게 정확합니다.

    Step 4: 4가지 상태 분류 함수 만들기 🏷️¶

    이제 핵심이에요! 센서 값을 읽어서 4가지 상태 중 하나로 분류하는 함수를 만들어봅시다.

    # 임계값 설정 (Step 3에서 구한 값을 넣으세요!)
THRESHOLD = 50  # 예시 값, 여러분이 측정한 값으로 바꾸세요!

def get_state(left_sensor, right_sensor):
    """
    센서 값을 받아서 4가지 상태 중 하나를 반환한다.

    반환값:
    - "GO"    : 둘 다 흰색 → 직진
    - "LEFT"  : 왼쪽 검정, 오른쪽 흰색 → 왼쪽으로
    - "RIGHT" : 왼쪽 흰색, 오른쪽 검정 → 오른쪽으로
    - "STOP"  : 둘 다 검정 → 정지
    """
    left_is_black = left_sensor < THRESHOLD
    right_is_black = right_sensor < THRESHOLD

    if not left_is_black and not right_is_black:
        return "GO"       # 둘 다 흰색
    elif left_is_black and not right_is_black:
        return "LEFT"     # 왼쪽만 검정
    elif not left_is_black and right_is_black:
        return "RIGHT"    # 오른쪽만 검정
    else:
        return "STOP"     # 둘 다 검정

    ⚠️ 자주 하는 실수¶

    1. 임계값을 대충 정해요 😅

    "대충 50으로 하면 되겠지~" 라고 생각하기 쉬운데, 환경마다 센서 값이 천차만별입니다. 흰 바닥에서 90이 나오는 곳도 있고 60이 나오는 곳도 있어요. 반드시 Step 2처럼 직접 측정한 뒤 임계값을 정하세요. 측정 안 하면 로봇이 흰 바닥도 검정으로 인식하는 황당한 일이 벌어질 수 있어요!

    2. 왼쪽/오른쪽 방향을 헷갈려요 🔄

    가장 흔한 실수! "왼쪽 센서가 검은 선 감지 → 왼쪽으로 가야지!" 라고 생각하면 오히려 선에서 더 멀어져요. 왼쪽 센서가 검은 선을 감지했다는 건 로봇이 오른쪽으로 치우쳤다는 뜻이니까 왼쪽으로 틀어야 합니다. 로봇 입장이 아니라 선의 입장에서 생각해보세요.
