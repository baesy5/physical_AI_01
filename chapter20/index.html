    Chapter 20: Sim-to-Real: 모델 이식과 최적화¶

    Part 6 | [2권] RC카로 현실 세계에 도전하기

    🎯 이 장에서 배우는 것¶

    • CARLA에서 학습한 Keras 모델을 TensorFlow Lite로 변환하여 경량화할 수 있다
    • 라즈베리파이에서 TFLite 모델을 로드하고 실시간 추론 파이프라인을 구축할 수 있다
    • Sim-to-Real Gap의 원인을 이해하고, 전이 학습(Fine-tuning)으로 성능을 개선할 수 있다
    • 추론 속도와 정확도의 트레이드오프를 분석하여 최적 모델 설정을 찾을 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔

    여러분이 CARLA 시뮬레이터에서 열심히 학습시킨 자율주행 AI 모델이 있습니다. 고성능 GPU가 탑재된 컴퓨터에서는 완벽하게 차선을 따라갑니다. 그런데 이 모델을 손바닥만 한 라즈베리파이에 올려서 실제 RC카를 움직이려 합니다. 과연 그대로 작동할까요?

    답은 "그냥은 안 된다" 입니다. 두 가지 큰 장벽이 있습니다.

    첫 번째 장벽 — 하드웨어의 한계: CARLA에서 학습한 모델은 수십 MB에 달하고, 추론에 상당한 연산이 필요합니다. 라즈베리파이는 GPU가 없고 메모리도 제한적이어서 원본 모델을 그대로 실행하면 1초에 한두 번밖에 예측하지 못합니다. 실시간 주행에는 최소 초당 10회 이상 예측이 필요한데 말입니다.

    두 번째 장벽 — 현실과 시뮬레이션의 차이: 시뮬레이터의 도로는 깨끗하고 조명이 일정합니다. 하지만 현실에서는 그림자, 반사광, 바닥 재질, 카메라 노이즈 등 예측 불가능한 변수가 가득합니다. 이 차이를 Sim-to-Real Gap이라 부릅니다.

    이 장에서는 이 두 장벽을 넘는 방법을 배웁니다. 이것은 자율주행뿐 아니라 로봇, 드론, IoT 등 AI를 현실 기기에 적용하는 모든 분야에서 핵심이 되는 기술입니다.

    📚 핵심 개념¶

    개념 1: 모델 경량화와 TensorFlow Lite¶

    비유로 시작 📦¶

    여러분이 해외여행을 간다고 상상해보세요. 집에 있는 옷장 전체를 가져갈 수는 없습니다. 여행 가방에 맞게 옷을 골라 압축팩에 넣고, 무거운 코트 대신 가벼운 바람막이로 대체합니다. 모델 경량화도 정확히 이 과정입니다. 크고 무거운 원본 모델을 작고 가벼운 형태로 변환하되, 핵심 성능은 최대한 유지하는 것입니다.

    정확한 정의¶

    TensorFlow Lite(TFLite) 는 모바일, 임베디드 기기 등 제한된 환경에서 머신러닝 모델을 실행하기 위한 경량 프레임워크입니다. 기존 TensorFlow/Keras 모델을 .tflite 형식으로 변환하며, 이 과정에서 다음과 같은 최적화가 적용됩니다.

    • 양자화(Quantization): 모델 가중치를 32비트 부동소수점에서 8비트 정수로 변환합니다. 모델 크기가 약 1/4로 줄어들고 추론 속도도 빨라집니다.
    • 연산자 융합(Operator Fusion): 여러 개의 연산을 하나로 합쳐 불필요한 중간 단계를 줄입니다.
    • 불필요한 노드 제거(Pruning): 학습에만 쓰이고 추론에는 필요 없는 노드를 제거합니다.

    예시로 확인¶

    graph LR A["Keras 모델<br/>.h5 / .keras<br/>약 15MB"] -->|TFLite 변환| B["TFLite 모델<br/>.tflite<br/>약 4MB"] B -->|양자화 적용| C["양자화 모델<br/>.tflite<br/>약 1.2MB"] style A fill:#ff9999,stroke:#333 style B fill:#ffcc66,stroke:#333 style C fill:#99ff99,stroke:#333

    정리하기 📌

    TFLite 변환은 모델의 "지능"은 유지하면서 "크기와 무게"를 줄이는 작업입니다. 특히 양자화를 적용하면 크기는 1/4, 속도는 2~4배 향상되지만, 약간의 정확도 손실이 있을 수 있습니다.

    개념 2: 실시간 추론 파이프라인¶

    비유로 시작 🏭¶

    공장의 컨베이어 벨트를 떠올려보세요. 원재료(카메라 이미지)가 들어오면, 전처리(크기 조정, 정규화) → 모델 추론(조향값 예측) → 후처리(모터 제어 명령 변환)를 거쳐 완제품(RC카의 움직임)이 나옵니다. 이 컨베이어 벨트가 멈추거나 느려지면 RC카가 벽에 부딪히겠죠. 실시간 추론 파이프라인은 이 컨베이어 벨트를 끊김 없이 빠르게 돌리는 시스템입니다.

    정확한 정의¶

    추론 파이프라인(Inference Pipeline) 은 입력 데이터를 받아 모델 예측 결과를 출력하기까지의 전체 데이터 처리 흐름입니다. 라즈베리파이 RC카에서는 다음 단계로 구성됩니다.

    graph TB A["📷 카메라 캡처<br/>PiCamera로 프레임 획득"] --> B["🔧 전처리<br/>크기 조정, 정규화, 색상 변환"] B --> C["🧠 모델 추론<br/>TFLite 인터프리터 실행"] C --> D["📊 후처리<br/>조향각·속도 값 변환"] D --> E["🏎️ 모터 제어<br/>PWM 신호로 서보·DC모터 구동"] E --> A style C fill:#4ecdc4,stroke:#333,color:#000

    이 루프가 1초에 10회 이상 돌아야(100ms 이내 한 사이클) RC카가 안정적으로 주행할 수 있습니다.

    예시로 확인¶

    각 단계별 소요 시간 목표:

    • 카메라 캡처: ~20ms
    • 전처리: ~5ms
    • 모델 추론: ~50ms (양자화 적용 시)
    • 후처리 + 모터 제어: ~10ms
    • 합계: ~85ms → 약 12 FPS ✅

    알아보기 💡

    FPS(Frames Per Second)는 1초에 처리하는 프레임 수입니다. 자율주행 RC카에서 10 FPS 이상이면 안정적, 5 FPS 이하면 반응이 너무 느려서 위험합니다.

    개념 3: Sim-to-Real Gap (시뮬레이션-현실 격차)¶

    비유로 시작 🎮¶

    레이싱 게임을 1,000시간 플레이한 사람이 실제 카트를 타면 어떨까요? 게임에서는 모든 것이 이상적입니다. 노면은 균일하고, 시야는 선명하며, 물리 법칙도 단순화되어 있습니다. 하지만 실제로는 타이어 마찰감, 바람, 눈부심 등 전혀 경험하지 못한 요소들이 쏟아집니다. 게임 실력이 아무리 좋아도 처음엔 실제 카트를 제대로 못 모는 이유입니다. AI 모델도 마찬가지입니다.

    정확한 정의¶

    Sim-to-Real Gap은 시뮬레이션 환경에서 학습한 모델이 실제 환경에서 성능이 저하되는 현상입니다. 주요 원인은 다음과 같습니다.

    graph TD GAP["🔍 Sim-to-Real Gap의 원인"] GAP --> V["시각적 차이<br/>텍스처, 조명, 그림자, 색감"] GAP --> P["물리적 차이<br/>마찰력, 관성, 지연시간"] GAP --> S["센서 차이<br/>카메라 화질, 왜곡, 노이즈"] GAP --> D["동역학 차이<br/>모터 응답, 배터리 전압 변화"] style GAP fill:#ff6b6b,stroke:#333,color:#fff style V fill:#ffd93d,stroke:#333 style P fill:#6bcb77,stroke:#333 style S fill:#4d96ff,stroke:#333,color:#fff style D fill:#ff922b,stroke:#333

    예시로 확인¶

    CARLA 시뮬레이터와 실제 RC카 환경을 비교해봅시다.

    • CARLA의 도로: 깨끗한 아스팔트, 선명한 차선, 균일한 조명
    • 실제 바닥: 마스킹테이프 차선, 바닥 무늬와 얼룩, 형광등 반사와 그림자
    • CARLA의 카메라: 노이즈 없는 완벽한 이미지, 고정 시야각
    • 실제 카메라: 센서 노이즈, 렌즈 왜곡, 흔들림

    이러한 차이 때문에 CARLA에서 조향 오차가 ±2°였던 모델이 실제에서는 ±15° 이상으로 벌어질 수 있습니다.

    개념 4: 전이 학습 (Transfer Learning & Fine-tuning)¶

    비유로 시작 🎓¶

    한국에서 운전면허를 딴 사람이 일본에서 운전한다고 상상해보세요. 운전의 기본 원리(핸들, 브레이크, 가속)는 같지만, 좌측통행이라는 차이에 적응해야 합니다. 운전을 처음부터 다시 배울 필요는 없고, 달라진 부분만 연습하면 됩니다. 전이 학습이 바로 이 방식입니다.

    정확한 정의¶

    전이 학습(Transfer Learning) 은 한 환경에서 학습한 모델의 지식을 다른 환경에 활용하는 기법입니다. 특히 Fine-tuning(미세 조정) 은 기존 모델의 가중치를 초기값으로 사용하고, 새로운 데이터로 추가 학습하여 새 환경에 적응시키는 방법입니다.

    graph LR subgraph "시뮬레이션" A["CARLA 데이터<br/>10,000장"] --> B["모델 학습<br/>epoch 50"] end subgraph "현실 적응" C["실제 RC카 데이터<br/>500장"] --> D["Fine-tuning<br/>epoch 10"] end B -->|가중치 전달| D D --> E["✅ 현실 적응 모델"] style B fill:#4ecdc4,stroke:#333 style D fill:#ff6b6b,stroke:#333,color:#fff style E fill:#99ff99,stroke:#333

    핵심 전략:

    • 초기 층(Conv 층) 동결: 시뮬레이션에서 배운 일반적인 특징(에지, 선, 곡선 인식)은 현실에서도 유효하므로 유지합니다
    • 후반 층(Dense 층) 학습: 도로 환경에 특화된 판단 부분만 새 데이터로 업데이트합니다
    • 낮은 학습률 사용: 기존 지식을 크게 훼손하지 않도록 학습률을 원래의 1/10~1/100로 낮춥니다

    정리하기 📌

    전이 학습의 핵심은 "적은 데이터로도 빠르게 새 환경에 적응"하는 것입니다. 실제 RC카 데이터를 수백 장만 모아도 CARLA에서 학습한 기반 위에 효과적으로 미세 조정할 수 있습니다.

    🔨 따라하기¶

    준비물¶

    • CARLA에서 학습한 Keras 모델 파일 (driving_model.h5)
    • 라즈베리파이 4B (4GB 이상 권장)
    • PC (모델 변환용, TensorFlow 설치)
    • 실제 RC카 주행 데이터 (이전 장에서 수집한 이미지 + 조향값)

    Step 1: Keras 모델을 TFLite로 변환하기¶

    PC에서 진행합니다. 먼저 CARLA에서 학습한 모델을 TFLite 형식으로 변환합니다.

    # convert_to_tflite.py
# PC에서 실행 (TensorFlow 2.x 필요)

import tensorflow as tf
import numpy as np
import os

# 1. 학습된 Keras 모델 로드
model = tf.keras.models.load_model('driving_model.h5')
print("원본 모델 요약:")
model.summary()

# 원본 모델 크기 확인
original_size = os.path.getsize('driving_model.h5') / (1024 * 1024)
print(f"\n원본 모델 크기: {original_size:.2f} MB")

# 2. 기본 TFLite 변환 (양자화 없음)
converter_basic = tf.lite.TFLiteConverter.from_keras_model(model)
tflite_basic = converter_basic.convert()

with open('driving_model_basic.tflite', 'wb') as f:
    f.write(tflite_basic)

basic_size = len(tflite_basic) / (1024 * 1024)
print(f"기본 TFLite 크기: {basic_size:.2f} MB")

# 3. 동적 범위 양자화 적용 변환
converter_quant = tf.lite.TFLiteConverter.from_keras_model(model)
converter_quant.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_quantized = converter_quant.convert()

with open('driving_model_quant.tflite', 'wb') as f:
    f.write(tflite_quantized)

quant_size = len(tflite_quantized) / (1024 * 1024)
print(f"양자화 TFLite 크기: {quant_size:.2f} MB")
print(f"크기 축소율: {original_size / quant_size:.1f}배")

    알아보기 💡

    tf.lite.Optimize.DEFAULT는 동적 범위 양자화를 적용합니다. 가중치를 8비트 정수로 변환하되, 추론 시 입력 데이터는 동적으로 양자화합니다. 가장 간단하면서도 효과적인 방법입니다.

    변환된 .tflite 파일을 라즈베리파이로 복사한 후, 실시간 추론 코드를 작성합니다.

    # realtime_inference.py
# 라즈베리파이에서 실행

import numpy as np
import cv2
import time

# TFLite 런타임 임포트 (라즈베리파이용)
try:
    import tflite_runtime.interpreter as tflite
    interpreter = tflite.Interpreter(model_path='driving_model_quant.tflite')
except ImportError:
    import tensorflow as tf
    interpreter = tf.lite.Interpreter(model_path='driving_model_quant.tflite')

interpreter.allocate_tensors()
input_details = interpreter.get_input_details()
output_details = interpreter.get_output_details()

# 입력 이미지 크기 확인
input_shape = input_details[0]['shape']  # 예: [1, 66, 200, 3]
IMG_HEIGHT = input_shape[1]
IMG_WIDTH = input_shape[2]

def preprocess_image(frame):
    """카메라 프레임을 모델 입력에 맞게 전처리"""
    # ROI 추출 (하단 60%만 사용 - 도로 영역)
    h, w = frame.shape[:2]
    roi = frame[int(h * 0.4):, :]

    # 크기 조정
    resized = cv2.resize(roi, (IMG_WIDTH, IMG_HEIGHT))

    # YUV 색공간 변환 (NVIDIA 모델 기준)
    yuv = cv2.cvtColor(resized, cv2.COLOR_BGR2YUV)

    # 정규화 (0~255 → 0~1)
    normalized = yuv.astype(np.float32) / 255.0

    # 배치 차원 추가
    return np.expand_dims(normalized, axis=0)

def predict_steering(frame):
    """프레임에서 조향값 예측"""
    input_data = preprocess_image(frame)
    interpreter.set_tensor(input_details[0]['index'], input_data)
    interpreter.invoke()
    steering = interpreter.get_tensor(output_details[0]['index'])[0][0]
    return float(steering)

# 카메라 초기화
cap = cv2.VideoCapture(0)
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 320)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 240)

print("실시간 추론 시작! (Ctrl+C로 종료)")
print("-" * 40)

fps_list = []

try:
    while True:
        start_time = time.time()

        ret, frame = cap.read()
        if not ret:
            print("카메라 읽기 실패")
            break

        # 추론
        steering_angle = predict_steering(frame)

        # 소요 시간 및 FPS 계산
        elapsed = time.time() - start_time
        fps = 1.0 / elapsed
        fps_list.append(fps)

        # 결과 출력
        print(f"조향: {steering_angle:+.3f} | "
              f"소요: {elapsed*1000:.1f}ms | "
              f"FPS: {fps:.1f}")

except KeyboardInterrupt:
    avg_fps = np.mean(fps_list) if fps_list else 0
    print(f"\n평균 FPS: {avg_fps:.1f}")
    print("추론 종료")
finally:
    cap.release()

    생각해보기 🤔

    위 코드에서 cap.set(cv2.CAP_PROP_FRAME_WIDTH, 320)으로 카메라 해상도를 낮게 설정한 이유는 무엇일까요? 해상도를 높이면 더 정확하지 않을까요? — 높은 해상도는 캡처와 전처리에 더 많은 시간이 들어 FPS가 떨어집니다. 모델 입력 크기(66×200)보다 약간 큰 정도면 충분합니다.

# 라즈베리파이 또는 PC에서 실행

import numpy as np
import cv2
import os
import json

# TFLite 모델 로드 (Step 3과 동일한 방식)
try:
    import tflite_runtime.interpreter as tflite
    interpreter = tflite.Interpreter(model_path='driving_model_quant.tflite')
except ImportError:
    import tensorflow as tf
    interpreter = tf.lite.Interpreter(model_path='driving_model_quant.tflite')

interpreter.allocate_tensors()
input_details = interpreter.get_input_details()
output_details = interpreter.get_output_details()

IMG_HEIGHT = input_details[0]['shape'][1]
IMG_WIDTH = input_details[0]['shape'][2]

def preprocess_image(image_path):
    """이미지 파일을 전처리"""
    frame = cv2.imread(image_path)
    h, w = frame.shape[:2]
    roi = frame[int(h * 0.4):, :]
    resized = cv2.resize(roi, (IMG_WIDTH, IMG_HEIGHT))
    yuv = cv2.cvtColor(resized, cv2.COLOR_BGR2YUV)
    normalized = yuv.astype(np.float32) / 255.0
    return np.expand_dims(normalized, axis=0)

# 실제 RC카에서 수집한 데이터로 평가
# (이전 장에서 수집한 데이터 사용)
real_data_dir = 'real_driving_data/'
label_file = os.path.join(real_data_dir, 'labels.json')

with open(label_file, 'r') as f:
    labels = json.load(f)

errors = []
for entry in labels:
    image_path = os.path.join(real_data_dir, entry['image'])
    actual_steering = entry['steering']

    if not os.path.exists(image_path):
        continue

    # 모델 예측
    input_data = preprocess_image(image_path)
    interpreter.set_tensor(input_details[0]['index'], input_data)
    interpreter.invoke()
    predicted = interpreter.get_tensor(output_details[0]['index'])[0][0]

    error = abs(actual_steering - predicted)
    errors.append(error)

if errors:
    mae = np.mean(errors)
    std = np.std(errors)
    max_err = np.max(errors)

    print("=" * 40)
    print("Sim-to-Real Gap 분석 결과")
    print("=" * 40)
    print(f"테스트 샘플 수: {len(errors)}")
    print(f"평균 절대 오차 (MAE): {mae:.4f}")
    print(f"오차 표준편차: {std:.4f}")
    print(f"최대 오차: {max_err:.4f}")
    print()

    if mae < 0.05:
        print("✅ 우수: Gap이 작습니다!")
    elif mae < 0.15:
        print("⚠️ 보통: Fine-tuning을 권장합니다.")
    else:
        print("❌ 심각: Fine-tuning이 반드시 필요합니다.")
