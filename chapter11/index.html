    보상 함수 설계 – 로봇에게 점수를 매기는 법¶

    Part 3 | [2권] 강화학습의 세계로 – 핵심 개념 이해하기 | 11차시

    🎯 이 장에서 배우는 것¶

    • 보상 함수가 무엇이고, 강화학습에서 왜 유일한 학습 신호인지 설명할 수 있다
    • 라인트레이싱 과제에 맞는 보상 체계를 직접 설계할 수 있다
    • 보상 설정을 바꿨을 때 로봇 행동이 어떻게 달라지는지 예측할 수 있다
    • 잘못된 보상 설계가 만드는 "함정"을 알고 피할 수 있다

    💡 왜 이걸 배우나요?¶

    강아지 훈련을 떠올려 보세요. 강아지가 "앉아"를 했을 때 간식을 주면 그 행동을 반복합니다. 간식 대신 혼을 내면? 다시는 앉지 않겠죠. 🐕

    강화학습에서 보상 함수는 바로 이 "간식과 혼내기" 역할을 합니다. 로봇은 코드를 읽지 못하고, 설명서도 이해하지 못합니다. 오직 "이 행동을 했더니 점수가 올랐다/내렸다" 라는 신호만으로 학습합니다.

    문제는, 이 점수 체계를 우리가 직접 만들어야 한다는 것입니다. 점수를 잘못 매기면 로봇은 우리가 원하지 않는 이상한 행동을 "최고의 전략"이라고 믿게 됩니다. 실제로 보상 설계 실수 때문에 로봇이 제자리에서 멈춰 서거나, 빙글빙글 도는 일이 자주 일어납니다.

    이번 장에서는 좋은 보상 함수를 설계하는 원리를 배우고, 우리의 라인트레이싱 로봇에 직접 적용해 봅니다. 이 능력은 앞으로 어떤 강화학습 문제를 만나도 가장 먼저 필요한 핵심 스킬입니다! 💪

    📚 핵심 개념¶

    개념 1: 보상 함수란 무엇인가 🎯¶

    비유로 시작하기

    학교 시험을 생각해 보세요. 선생님은 정답에 ✅를 주고, 오답에 ✗를 줍니다. 학생은 이 채점 결과를 보고 "아, 이렇게 풀면 맞는구나" "이건 틀린 방법이구나"를 깨닫습니다. 보상 함수는 강화학습에서 채점표 역할을 합니다.

    정확한 정의

    보상 함수(Reward Function)는 에이전트가 특정 상태에서 특정 행동을 했을 때 환경이 돌려주는 숫자 값입니다. 수학적으로 쓰면:

    R(s, a) → 숫자 한 개

    • s: 현재 상태 (예: 로봇의 센서 값)
    • a: 선택한 행동 (예: 직진, 좌회전, 우회전)
    • 돌려주는 숫자: 양수면 "잘했어!", 음수면 "그러지 마!", 0이면 "별로 상관없어"

    핵심은 이것입니다: 보상 함수는 에이전트가 학습할 수 있는 유일한 신호입니다. 우리가 아무리 "선을 따라가렴"이라고 말해도 로봇은 알아듣지 못합니다. 오직 보상 점수만 읽을 수 있습니다.

    예시로 확인

    라인트레이싱 로봇의 가장 기본적인 보상 함수:

    def simple_reward(sensor_position):
    """센서가 선 위에 있으면 +1, 아니면 -1"""
    if sensor_position == "on_line":
        return 1
    else:
        return -1

    로봇은 수천 번의 시도를 통해 "+1을 많이 받는 행동 → 선 위에 머무는 행동"을 스스로 발견합니다.

    개념 2: 보상의 크기와 종류 📊¶

    비유로 시작하기

    카페에서 아르바이트한다고 상상해 보세요. 설거지하면 100원, 커피 만들면 5,000원을 받는다면 어떤 일에 집중할까요? 당연히 커피 만들기겠죠! 보상의 크기가 행동의 우선순위를 결정합니다.

    정확한 정의

    보상은 크게 세 가지로 나눌 수 있습니다:

    • 양의 보상(Positive Reward): "이 행동 좋아!" → 에이전트가 이 행동을 더 자주 하게 만듦
    • 음의 보상(Negative Reward, 벌점): "이 행동 나빠!" → 에이전트가 이 행동을 피하게 만듦
    • 영 보상(Zero Reward): "상관없어" → 에이전트에게 아무 정보도 주지 않음

    그리고 보상의 크기(magnitude) 가 중요합니다. +1과 +100은 둘 다 양의 보상이지만, 에이전트에게 주는 영향력은 완전히 다릅니다.

    예시로 확인 – 라인트레이싱에 적용

    def detailed_reward(distance_from_center):
    """
    선 중심으로부터의 거리에 따라 보상을 다르게 준다.
    distance_from_center: 0이면 정중앙, 값이 클수록 멀리 벗어남
    """
    if distance_from_center == 0:
        return 10     # 정중앙! 최고 점수
    elif distance_from_center <= 1:
        return 5      # 선 위에는 있음. 좋아!
    elif distance_from_center <= 2:
        return -1     # 살짝 벗어남. 주의!
    else:
        return -10    # 완전히 벗어남. 큰 벌점!

    이렇게 하면 로봇은 "그냥 선 위에 있는 것"보다 "선 정중앙에 있는 것"을 선호하게 됩니다. 보상의 크기가 행동의 정밀도를 조절하는 것이죠.

    개념 3: 보상 설계의 함정 ⚠️¶

    비유로 시작하기

    어떤 회사가 직원에게 "버그를 고치면 보너스를 준다"는 규칙을 만들었습니다. 결과는? 직원들이 일부러 버그를 만든 다음 고쳐서 보너스를 받았습니다! 😱 의도와 결과가 완전히 달라진 것이죠. 이것이 바로 보상 해킹(Reward Hacking) 입니다.

    정확한 정의

    보상 설계의 대표적인 함정 3가지:

    함정 1 – 과도한 벌점이 만드는 "겁쟁이 로봇"

    선을 벗어나면 -100점을 주면 어떻게 될까요? 로봇은 벌점이 너무 무서워서 아예 움직이지 않는 전략을 선택합니다. 움직이지 않으면 벗어날 위험도 없으니까요. 점수는 0점이지만, -100점보다는 낫다고 판단하는 것입니다.

    함정 2 – 보상 해킹

    "한 걸음 전진할 때마다 +1점"이라고 설계하면, 로봇이 선을 완전히 무시하고 최대한 빨리 앞으로만 돌진할 수 있습니다. 우리는 "선을 따라 전진"을 원했지만, 로봇은 "그냥 전진"이 점수를 최대화하는 방법임을 발견한 것입니다.

    함정 3 – 희소 보상 문제

    "결승선에 도착하면 +1000점, 나머지는 0점"이라고 하면? 로봇이 우연히 결승선에 도착할 확률이 극히 낮아서 영원히 학습하지 못합니다. 가끔 한 번 받는 큰 보상보다, 자주 받는 작은 보상이 학습에 훨씬 효과적입니다.

    예시로 확인

    # ❌ 나쁜 설계: 겁쟁이 로봇을 만드는 보상
def scared_robot_reward(on_line, moved):
    if not on_line:
        return -100   # 너무 큰 벌점!
    if moved:
        return 1
    return 0

# ✅ 개선된 설계: 균형 잡힌 보상
def balanced_reward(on_line, moved):
    if not on_line:
        return -2     # 적절한 벌점
    if moved:
        return 3      # 전진 보상이 벌점보다 큼
    return -1         # 멈춰있으면 소소한 벌점

    핵심 원칙: "원하는 행동의 보상 > 벌점의 크기" 가 되어야 로봇이 도전합니다.

    개념 4: 좋은 보상 함수의 설계 원칙 🏗️¶

    비유로 시작하기

    네비게이션을 생각해 보세요. "서울에서 부산"이라고만 하면 막막하지만, 매 교차로에서 "잘 가고 있어요/경로를 이탈했어요"라고 알려주면 쉽게 도착할 수 있죠. 좋은 보상 함수도 매 순간 적절한 피드백을 제공합니다.

    정확한 정의 – 4가지 설계 원칙

    • 원칙 1: 밀도 있는 보상 – 매 행동마다 피드백을 준다 (결승선에서만 주지 않는다)
    • 원칙 2: 크기의 균형 – 보상과 벌점의 비율을 적절하게 맞춘다
    • 원칙 3: 목표 정렬 – "내가 진짜 원하는 행동"에 가장 높은 점수를 준다
    • 원칙 4: 단순함 – 너무 복잡한 보상은 예측 불가능한 행동을 만든다

    예시로 확인 – 설계 원칙의 흐름

    flowchart TD A["🎯 목표 정의하기<br/>선을 따라 안정적으로 주행"] --> B["📏 측정 가능한 기준 만들기<br/>센서와 선 중심의 거리"] B --> C["⚖️ 보상/벌점 크기 결정하기<br/>정중앙 +10, 약간 벗어남 -1, 완전 이탈 -10"] C --> D["🧪 테스트하고 조정하기<br/>로봇이 의도대로 움직이는가?"] D -->|"이상한 행동 발견"| B D -->|"잘 작동!"| E["✅ 보상 함수 완성"]

    보상 함수 설계는 한 번에 완벽하게 만드는 것이 아니라, 설계 → 테스트 → 수정을 반복하는 과정입니다.

    🔨 따라하기: 라인트레이싱 보상 함수 직접 만들기¶

    이제 파이썬으로 직접 보상 함수를 만들고, 다른 보상 설계가 로봇 행동에 어떤 영향을 주는지 시뮬레이션해 봅시다!

    Step 1: 환경 설정하기¶

    먼저 라인트레이싱 시뮬레이션의 기본 틀을 만듭니다. 로봇은 1차원 트랙 위에 있고, 선의 위치(중심)로부터 얼마나 떨어져 있는지를 기준으로 행동합니다.

    import random

# 로봇의 상태: 선 중심(0)으로부터의 거리 (-5 ~ +5)
# 음수: 왼쪽으로 벗어남, 양수: 오른쪽으로 벗어남
class SimpleLineRobot:
    def __init__(self):
        self.position = 0  # 선 중심에서 시작
        self.total_reward = 0
        self.history = []

    def move(self, action):
        """action: -1(왼쪽), 0(직진), 1(오른쪽)"""
        # 로봇 이동 + 약간의 랜덤 흔들림
        drift = random.uniform(-0.3, 0.3)
        self.position += action + drift
        # 트랙 범위 제한
        self.position = max(-5, min(5, self.position))

    def get_distance_from_center(self):
        return abs(self.position)

print("✅ 로봇 클래스 준비 완료!")

    Step 2: 첫 번째 보상 함수 – 단순 이진 보상¶

    가장 단순한 형태부터 시작합니다. 선 위에 있으면 +1, 아니면 -1.

    def reward_v1_binary(distance):
    """이진 보상: 선 위(거리 1 이내) = +1, 벗어남 = -1"""
    if distance <= 1.0:
        return 1
    else:
        return -1

# 테스트
print(f"거리 0.0 → 보상: {reward_v1_binary(0.0)}")
print(f"거리 0.5 → 보상: {reward_v1_binary(0.5)}")
print(f"거리 2.0 → 보상: {reward_v1_binary(2.0)}")

    실행 결과: 

    거리 0.0 → 보상: 1
거리 0.5 → 보상: 1
거리 2.0 → 보상: -1

    Step 3: 두 번째 보상 함수 – 거리 비례 보상¶

    이번엔 "얼마나 가까운가"에 비례해서 점수를 줍니다. 더 정교한 피드백이죠!

    def reward_v2_proportional(distance):
    """거리에 비례하는 보상: 가까울수록 높은 점수"""
    reward = 5.0 - (distance * 2.0)
    return round(reward, 1)

# 테스트
for d in [0.0, 0.5, 1.0, 2.0, 3.0, 5.0]:
    print(f"거리 {d} → 보상: {reward_v2_proportional(d)}")

    실행 결과: 

    거리 0.0 → 보상: 5.0
거리 0.5 → 보상: 4.0
거리 1.0 → 보상: 3.0
거리 2.0 → 보상: 1.0
거리 3.0 → 보상: -1.0
거리 5.0 → 보상: -5.0

    정중앙에서 +5, 멀어질수록 점수가 줄어들다가 음수가 됩니다. 로봇이 "중앙에 가까울수록 좋다"는 것을 더 세밀하게 학습할 수 있겠죠?

    Step 4: 시뮬레이션으로 비교하기¶

    이제 두 보상 함수로 로봇을 각각 100스텝 동안 운영하고, 결과를 비교합니다.

    def run_simulation(reward_function, reward_name, steps=100):
    """간단한 시뮬레이션: 로봇이 보상을 최대화하는 행동을 선택"""
    robot = SimpleLineRobot()
    total = 0
    on_line_count = 0

    for step in range(steps):
        # 세 가지 행동을 각각 시도해보고, 보상이 가장 높은 것을 선택
        best_action = 0
        best_reward = -999

        for action in [-1, 0, 1]:
            # 행동 후 예상 위치 계산
            test_pos = robot.position + action
            test_dist = abs(test_pos)
            r = reward_function(test_dist)
            if r > best_reward:
                best_reward = r
                best_action = action

        # 최선의 행동 실행
        robot.move(best_action)
        distance = robot.get_distance_from_center()
        reward = reward_function(distance)
        total += reward

        if distance <= 1.0:
            on_line_count += 1

    print(f"\n📊 [{reward_name}] 결과:")
    print(f"   총 보상: {total:.1f}")
    print(f"   선 위에 머문 비율: {on_line_count}%")
    print(f"   최종 위치: {robot.position:.2f}")

# 두 보상 함수 비교
random.seed(42)  # 동일한 조건으로 비교
run_simulation(reward_v1_binary, "이진 보상 v1")

run_simulation(reward_v2_proportional, "거리 비례 보상 v2")

    Step 5: 함정 체험 – 과도한 벌점¶

    일부러 "나쁜" 보상 함수를 만들어서 어떤 문제가 생기는지 확인해 봅시다.

    def reward_v3_scary(distance):
    """과도한 벌점: 벗어나면 -100!"""
    if distance <= 1.0:
        return 1
    else:
        return -100  # 무시무시한 벌점

def reward_v4_only_forward(distance, moved_forward=True):

    if moved_forward:
        return 5
    return 0

    Step 6: 나만의 보상 함수 설계하기¶

    이제 여러분 차례입니다! 아래 틀을 채워서 자신만의 보상 함수를 만들어 보세요.

    def my_reward(distance):
    """
    나만의 보상 함수를 설계해 보세요!

    설계 기준을 먼저 적어보세요:
    - 정중앙(거리 0): ? 점
    - 선 근처(거리 1 이내): ? 점  
    - 약간 벗어남(거리 1~2): ? 점

    """
    # 여기에 여러분의 코드를 작성하세요!
    if distance <= 0.3:
        return 10      # 예: 정중앙 보너스
    elif distance <= 1.0:
        return 3
    elif distance <= 2.0:
        return -2
    else:
        return -5

    📝 전체 코드¶

    한 번에 실행할 수 있는 전체 코드입니다.

    import random

# ========== 로봇 클래스 ==========
class SimpleLineRobot:
    def __init__(self):
        self.position = 0
        self.total_reward = 0

    def move(self, action):
        drift = random.uniform(-0.3, 0.3)
        self.position += action + drift
        self.position = max(-5, min(5, self.position))

    def get_distance_from_center(self):
        return abs(self.position)

# ========== 보상 함수들 ==========
def reward_v1_binary(distance):
    """이진 보상"""
    return 1 if distance <= 1.0 else -1

def reward_v2_proportional(distance):
    """거리 비례 보상"""
    return round(5.0 - (distance * 2.0), 1)

def reward_v3_scary(distance):
    """과도한 벌점"""
    return 1 if distance <= 1.0 else -100

# ========== 시뮬레이션 함수 ==========
def run_simulation(reward_function, reward_name, steps=100):
    robot = SimpleLineRobot()
    total = 0
    on_line_count = 0

    for step in range(steps):
        best_action = 0
        best_reward = -999

        for action in [-1, 0, 1]:
            test_pos = robot.position + action
            test_dist = abs(test_pos)
            r = reward_function(test_dist)
            if r > best_reward:
                best_reward = r
                best_action = action

        robot.move(best_action)
        distance = robot.get_distance_from_center()
        reward = reward_function(distance)
        total += reward

        if distance <= 1.0:
            on_line_count += 1

    print(f"\n📊 [{reward_name}] 결과:")
    print(f"   총 보상: {total:.1f}")
    print(f"   선 위에 머문 비율: {on_line_count}%")
    print(f"   최종 위치: {robot.position:.2f}")

# ========== 실행 ==========
print("=" * 40)
print("🏁 보상 함수 비교 시뮬레이션")
print("=" * 40)

for seed_val in [42]:
    random.seed(seed_val)
    run_simulation(reward_v1_binary, "이진 보상 v1")

    random.seed(seed_val)
    run_simulation(reward_v2_proportional, "거리 비례 보상 v2")

    random.seed(seed_val)
    run_simulation(reward_v3_scary, "과도한 벌점 v3")

print("\n🎉 시뮬레이션 완료! 결과를 비교해 보세요.")

    ⚠️ 자주 하는 실수¶

    실수 1: "벌점을 크게 줘야 빨리 배우겠지" 🚫

    벌점 -100을 주면 로봇이 빨리 배울 것 같지만, 실제로는 아무것도 하지 않는 로봇이 됩니다. 움직이지 않으면 -100을 맞을 위험이 없으니까요. 벌점은 양의 보상보다 작게 설정하는 것이 원칙입니다.

    실수 2: "보상을 결과에만 주기" 🚫

    "골인하면 +1000, 나머지는 0"처럼 최종 결과에만 보상을 주면, 로봇이 우연히 골인하기 전까지 아무 학습 신호가 없습니다. 매 걸음마다 "지금 잘 가고 있는지"를 알려주는 밀도 있는 보상이 훨씬 효과적입니다.

    실수 3: "원하는 것과 측정하는 것이 다른 보상" 🚫

    "선을 따라가길" 원하면서 "전진 거리"에만 보상을 주면, 로봇은 선을 무시하고 앞으로만 돌진합니다. 보상 함수를 작성한 후 반드시 "이 보상을 최대화하면 진짜로 내가 원하는 행동이 나올까?" 라고 자문해 보세요.

    실수 4: "보상 함수를 한 번에 완성하려고 하기" 🚫

    처음부터 완벽한 보상 함수를 만들 수 있는 사람은 없습니다. 단순하게 시작 → 테스트 → 문제 발견 → 수정 의 반복이 정상적인 과정입니다. 프로 연구자들도 이렇게 합니다!
