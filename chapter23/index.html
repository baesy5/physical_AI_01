    Chapter 23: 프로젝트 문서화와 발표 준비¶

    Part 7: 프로젝트 완성과 발표 | 24차시 중 23차시

    🎯 이 장에서 배우는 것¶

    • 프로젝트 보고서 템플릿을 활용해 8주간의 과정을 체계적으로 문서화할 수 있다
    • 기술적 내용을 비전문가도 이해할 수 있는 발표 자료로 구성할 수 있다
    • 실패와 극복 과정을 스토리텔링 형식으로 논리적으로 서술할 수 있다
    • 발표 리허설과 동료 피드백을 통해 발표를 개선할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기: 세계적인 AI 엔지니어들도 논문과 발표로 자신의 연구를 공유합니다. 아무리 뛰어난 연구도 다른 사람에게 전달되지 않으면 존재하지 않는 것과 같습니다. 우리도 할 수 있을까요?

    8주 동안 여러분은 정말 많은 일을 했습니다. 자율주행 알고리즘을 설계하고, 코드를 작성하고, 시뮬레이터에서 테스트하고, RC카에 적용하고, 실패하고, 다시 도전했습니다. 그런데 이 모든 과정이 여러분의 머릿속에만 있다면?

    문서화와 발표는 단순한 "마무리 작업"이 아닙니다.

    • 🧠 정리하면 더 깊이 이해됩니다 — 글로 쓰는 순간, "내가 정말 이해한 건가?"를 확인하게 됩니다
    • 🤝 공유해야 가치가 커집니다 — 여러분의 경험이 다른 사람에게 영감이 됩니다
    • 📋 실무에서 필수 역량입니다 — 어떤 개발자도 문서화와 발표에서 벗어날 수 없습니다

    이번 장에서는 프로젝트의 모든 여정을 하나의 보고서와 하나의 발표로 완성합니다.

    📚 핵심 개념¶

    개념 1: 프로젝트 보고서 구조 📄¶

    비유로 시작하기

    영화를 생각해보세요. 모든 영화에는 도입(배경 설명) → 전개(사건 발생) → 위기(갈등) → 절정(해결) → 결말(마무리)이라는 구조가 있습니다. 프로젝트 보고서도 마찬가지입니다. 정해진 구조가 있어야 읽는 사람이 흐름을 따라갈 수 있습니다.

    정확한 정의

    프로젝트 보고서란, 프로젝트의 목적부터 결과까지의 전 과정을 논리적 순서로 정리한 문서입니다. 다음 6개 섹션으로 구성됩니다.

    flowchart LR A["1. 배경 및 목표"] --> B["2. 설계"] B --> C["3. 구현"] C --> D["4. 테스트"] D --> E["5. 결과 및 분석"] E --> F["6. 향후 과제"]

    각 섹션의 역할을 정리하면 다음과 같습니다.

    • 1. 배경 및 목표 — "왜 이 프로젝트를 시작했는가?" 자율주행의 필요성, 해결하려는 문제, 구체적 목표
    • 2. 설계 — "어떤 방식으로 접근했는가?" 시스템 구조도, 알고리즘 선택 이유, 하드웨어 구성
    • 3. 구현 — "실제로 어떻게 만들었는가?" 핵심 코드, 사용한 라이브러리, 개발 환경
    • 4. 테스트 — "제대로 작동하는지 어떻게 확인했는가?" 테스트 시나리오, 측정 방법
    • 5. 결과 및 분석 — "결과가 어떻게 나왔는가?" 성능 데이터, 그래프, 목표 달성 여부
    • 6. 향후 과제 — "앞으로 무엇을 더 할 수 있는가?" 한계점, 개선 방향

    예시로 확인

    "우리 팀은 카메라 기반 차선 인식 자율주행 RC카를 개발했다(배경). PID 제어와 OpenCV를 결합한 구조를 설계했고(설계), Python으로 약 500줄의 코드를 작성했다(구현). 직선·곡선·장애물 3가지 시나리오에서 테스트했고(테스트), 곡선 구간 성공률이 72%에서 91%로 개선되었다(결과). 향후 야간 주행과 다중 차선 인식을 추가하고 싶다(향후 과제)."

    개념 2: 실패 스토리텔링 📖¶

    비유로 시작하기

    발명왕 에디슨은 전구를 만들기까지 수천 번 실패했다고 합니다. 누군가 "수천 번 실패한 기분이 어떠냐"고 묻자, "나는 실패한 것이 아니라 전구가 작동하지 않는 수천 가지 방법을 발견한 것"이라고 답했죠. 실패는 숨길 대상이 아니라, 가장 강력한 이야기 소재입니다.

    정확한 정의

    실패 스토리텔링이란, 프로젝트 중 겪은 문제와 시행착오를 "문제 → 원인 분석 → 해결 시도 → 최종 결과" 순서로 서술하는 기법입니다. 이것이 보고서와 발표에서 가장 인상적인 부분이 됩니다.

    flowchart TD A["😰 문제 발생"] --> B["🔍 원인 분석"] B --> C["💡 해결 시도 1"] C --> D{"성공?"} D -- "아니오" --> E["💡 해결 시도 2"] E --> F{"성공?"} F -- "예" --> G["🎉 결과와 교훈"] D -- "예" --> G

    예시로 확인

    ❌ 나쁜 예: "곡선 주행에서 문제가 있었지만 해결했다."

    ✅ 좋은 예: "곡선 구간에서 RC카가 차선을 이탈하는 문제가 발생했다(문제). 로그를 분석한 결과, PID의 D값 반응이 너무 느려 급커브에서 조향이 지연되는 것이 원인이었다(원인 분석). D값을 2배로 높였더니 직선에서 진동이 심해졌고(해결 시도 1 실패), 결국 곡선 감지 시에만 D값을 동적으로 조절하는 방식을 적용하여 성공률을 91%로 끌어올렸다(최종 결과)."

    개념 3: 발표 자료 구성 🎬¶

    비유로 시작하기

    요리 프로그램을 생각해보세요. 셰프가 요리 과정을 설명할 때, 말로만 하면 지루합니다. 하지만 재료 클로즈업, 조리 과정 영상, 완성된 요리 사진이 함께 나오면 훨씬 생생하죠. 발표 자료도 마찬가지입니다.

    정확한 정의

    발표 자료란, 보고서의 핵심 내용을 시각적 요소 중심으로 재구성한 프레젠테이션입니다. 텍스트는 최소화하고, 이미지·영상·그래프·코드 하이라이트로 청중의 이해를 돕습니다.

    발표 슬라이드 구성 (10장 내외)

    • 슬라이드 1 — 제목, 팀명, 날짜
    • 슬라이드 2 — 프로젝트 배경과 목표 (한 문장 + 이미지)
    • 슬라이드 3 — 시스템 구조도 (다이어그램)
    • 슬라이드 4~5 — 핵심 구현 (코드 하이라이트 + 설명)
    • 슬라이드 6 — 실패와 극복 스토리 (Before/After 비교)
    • 슬라이드 7 — 시연 영상 (시뮬레이션 또는 RC카 주행)
    • 슬라이드 8 — 성능 결과 그래프
    • 슬라이드 9 — 향후 과제
    • 슬라이드 10 — Q&A

    알아보기: 발표 자료에서 가장 중요한 원칙은 "한 슬라이드, 한 메시지"입니다. 하나의 슬라이드에 여러 개의 주제를 담으면 청중이 혼란스러워합니다.

    개념 4: 피드백과 리허설 🔄¶

    비유로 시작하기

    운동선수는 본 경기 전에 반드시 연습 경기를 합니다. 연습 없이 바로 본 경기에 나가면 긴장과 실수로 실력 발휘가 어렵죠. 발표도 완전히 같습니다. 리허설은 선택이 아니라 필수입니다.

    정확한 정의

    리허설이란, 실제 발표와 동일한 조건에서 진행하는 연습 발표입니다. 동료 피드백이란, 리허설을 지켜본 동료가 구체적인 개선점을 제시하는 것입니다.

    효과적인 피드백을 위한 3가지 관점

    • 📋 내용 — 핵심 메시지가 명확한가? 빠진 정보는 없는가?
    • 🎨 시각 — 글씨 크기는 적절한가? 그래프가 이해되는가?
    • 🗣️ 전달 — 말하는 속도는 적절한가? 시간 안에 끝나는가?
    flowchart LR A["1차 리허설"] --> B["동료 피드백 수집"] B --> C["피드백 반영 및 수정"] C --> D["2차 리허설"] D --> E["최종 발표"]

    🔨 따라하기: 프로젝트 보고서와 발표 자료 만들기¶

    Step 1: 프로젝트 타임라인 정리하기 🗓️¶

    먼저 8주간의 과정을 시간순으로 정리합니다. Python으로 타임라인을 자동 생성해봅시다.

    {
        "week": "7-8주차",
        "phase": "개선 및 완성",

print("=" * 50)

    Step 2: 성능 결과를 그래프로 시각화하기 📊¶

    보고서와 발표에서 가장 설득력 있는 요소는 데이터 그래프입니다.

    # performance_graph.py
# 프로젝트 성능 변화를 그래프로 시각화

import matplotlib.pyplot as plt

# 주차별 성능 데이터 (예시 - 여러분의 데이터로 교체하세요)
weeks = ["2주차", "4주차", "6주차", "8주차"]

# 직선 주행 성공률 (%)
straight_rate = [40, 75, 95, 98]

# 곡선 주행 성공률 (%)
curve_rate = [10, 35, 72, 91]

# 평균 주행 속도 (cm/s)  
avg_speed = [15, 25, 35, 42]

# 그래프 생성

# 🔹 하이라이트 1: 차선 검출 핵심 로직
# ========================================
def detect_lane(frame):
    """카메라 영상에서 차선 위치를 검출합니다."""
    # HSV 변환으로 흰색 차선 추출
    hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
    mask = cv2.inRange(hsv, (0, 0, 200), (180, 30, 255))

    # 관심 영역(ROI)만 분석 - 하단 1/3
    height = mask.shape[0]
    roi = mask[height * 2 // 3:, :]

    # 차선 중심 계산
    moments = cv2.moments(roi)
    if moments["m00"] > 0:
        cx = int(moments["m10"] / moments["m00"])
        return cx  # 차선 중심의 x좌표
    return None

# ========================================
# 🔹 하이라이트 2: PID 제어 핵심 로직
# ========================================
class PIDController:
    """조향각을 계산하는 PID 제어기입니다."""
    def __init__(self, kp=0.5, ki=0.01, kd=0.1):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.prev_error = 0
        self.integral = 0

    def calculate(self, error):
        self.integral += error
        derivative = error - self.prev_error
        output = (self.kp * error + 
                  self.ki * self.integral + 
                  self.kd * derivative)
        self.prev_error = error
        return output
