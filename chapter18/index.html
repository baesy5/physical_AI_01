    시뮬레이션에서 실제 로봇으로 – 코드 연결하기¶

    Part 5 | [2권] 실제 햄스터 로봇에 강화학습 적용하기

    🎯 이 장에서 배우는 것¶

    • 시뮬레이션의 상태·행동·보상 구조를 실제 햄스터 로봇 코드에 매핑할 수 있다
    • 실제 센서 값을 읽어 시뮬레이션과 동일한 상태로 변환하는 코드를 작성할 수 있다
    • reset()과 step(action)을 실제 로봇 동작으로 대체하는 코드를 작성할 수 있다
    • 시뮬레이션과 실제 환경 사이의 차이점(노이즈, 지연 등)을 인식하고 대처할 수 있다

    💡 왜 이걸 배우나요?¶

    지금까지 우리는 시뮬레이션이라는 안전한 연습실에서 강화학습을 훈련시켰습니다. Q-테이블도 만들었고, 에이전트가 벽을 피하며 미로를 탈출하는 것도 확인했죠.

    그런데 한 가지 의문이 남습니다.

    "시뮬레이션에서 잘 된다고, 진짜 로봇에서도 잘 될까?" 🤔

    이 질문은 강화학습에서 Sim-to-Real(시뮬레이션에서 현실로) 이라고 불리는 아주 중요한 주제입니다. 자동차 운전 시뮬레이터를 아무리 잘해도, 처음 실제 도로에 나가면 긴장되는 것처럼요.

    이번 장에서는 시뮬레이션 코드를 한 줄 한 줄 실제 로봇 코드로 바꾸는 작업을 합니다. 가상 세계의 reset()을 손으로 로봇을 놓는 것으로, step(action)을 실제 모터와 센서로 교체합니다. 그 과정에서 현실만의 까다로운 문제들도 함께 만나봅시다!

    📚 핵심 개념¶

    개념 1: Sim-to-Real 전환이란?¶

    비유로 시작 🎮➡️🚗

    비행 시뮬레이터로 조종을 배운 파일럿이 실제 비행기에 탑승하는 순간을 상상해보세요. 시뮬레이터에서 배운 원리(이륙, 선회, 착륙)는 그대로 적용되지만, 실제로는 바람, 기체 진동, 계기판의 미세한 오차 같은 새로운 변수가 등장합니다.

    정확한 정의

    Sim-to-Real 전환이란, 시뮬레이션에서 학습한 정책(Q-테이블, 알고리즘)을 실제 물리적 로봇에 적용하는 과정입니다. 핵심은 코드의 구조(상태→행동→보상 루프)는 동일하지만, 각 구성요소의 구현 방식이 달라진다는 것입니다.

    예시로 확인

    시뮬레이션: state = env.reset()         →  실제: 로봇을 출발점에 손으로 놓기
시뮬레이션: next_state, reward = env.step(action) → 실제: 모터 구동 후 센서 읽기
시뮬레이션: 벽 감지 = 격자 좌표 비교    →  실제: 적외선 센서 값 읽기

    개념 2: 매핑(Mapping) – 시뮬레이션 ↔ 실제 로봇 대응표¶

    비유로 시작 🗺️

    외국어 통역사가 하는 일을 생각해보세요. 한국어 문장의 의미는 유지하면서, 표현 방식만 영어로 바꿉니다. 매핑도 마찬가지입니다. 시뮬레이션의 의미(상태, 행동, 보상)는 유지하면서, 구현 방식만 실제 로봇용으로 바꾸는 것입니다.

    정확한 정의

    매핑이란 시뮬레이션의 각 구성요소(상태 정의, 행동 정의, 보상 계산)를 실제 하드웨어의 대응하는 요소로 1:1 연결하는 작업입니다.

    예시로 확인

    graph LR subgraph 시뮬레이션 S1["상태: 격자 좌표 (2,3)"] A1["행동: 'forward'"] R1["보상: +1 (목표 도달)"] end subgraph 실제 로봇 S2["상태: 센서값 → 구간 분류"] A2["행동: 모터 속도 설정"] R2["보상: 센서로 목표 감지"] end S1 -->|매핑| S2 A1 -->|매핑| A2 R1 -->|매핑| R2

    개념 3: 센서 값의 상태 변환 (Discretization)¶

    비유로 시작 🌡️

    체온계를 볼 때 "36.7도"라는 정확한 숫자보다 "정상" 이라는 구간 분류가 더 유용할 때가 있죠. 실제 센서도 마찬가지입니다. 적외선 센서가 돌려주는 0~255 사이의 연속적인 숫자를, 강화학습이 이해할 수 있는 몇 개의 구간으로 나누는 것입니다.

    정확한 정의

    이산화(Discretization)란 연속적인 센서 값을 유한한 개수의 상태 카테고리로 변환하는 과정입니다. 시뮬레이션에서는 격자 좌표가 이미 이산적이었지만, 실제 센서 값은 연속적이므로 이 변환이 반드시 필요합니다.

    예시로 확인

    def sensor_to_state(left_sensor, right_sensor):
    """적외선 센서 값을 상태 번호로 변환"""
    # 센서값이 클수록 가까운 물체가 있음
    if left_sensor > 50 and right_sensor > 50:
        return 0  # 양쪽 다 벽 가까움 → "막다른 길"
    elif left_sensor > 50:
        return 1  # 왼쪽만 벽 가까움 → "왼쪽 벽"
    elif right_sensor > 50:
        return 2  # 오른쪽만 벽 가까움 → "오른쪽 벽"
    else:
        return 3  # 양쪽 다 여유 → "탁 트인 길"

    개념 4: 현실의 불확실성 – 노이즈, 지연, 미끄러짐¶

    비유로 시작 🧊

    얼음판 위에서 걷는 것을 상상해보세요. "한 발 앞으로"라고 생각해도 실제로는 미끄러져서 1.5발이 될 수도 있고, 옆으로 빠질 수도 있습니다. 실제 로봇도 마찬가지입니다.

    정확한 정의

    실제 환경에서는 시뮬레이션에 없던 세 가지 주요 문제가 발생합니다.

    • 센서 노이즈: 같은 위치에서도 센서 값이 매번 조금씩 다름 (예: 48, 52, 49…)
    • 통신 지연: 명령을 보내고 로봇이 실제로 움직이기까지 시간차 존재
    • 바퀴 미끄러짐: "직진" 명령을 줘도 바닥 재질에 따라 약간 회전할 수 있음

    예시로 확인

    graph TD A["시뮬레이션에서<br/>행동: 직진"] --> B["결과: 정확히<br/>한 칸 전진"] C["실제 로봇에서<br/>행동: 직진"] --> D["결과: 0.8~1.2칸<br/>+ 약간 회전"] C --> E["센서 읽기:<br/>값이 매번 다름"] C --> F["통신 지연:<br/>0.1초 후 반응"] style A fill:#e8f5e9 style B fill:#e8f5e9 style C fill:#fff3e0 style D fill:#fff3e0 style E fill:#fff3e0 style F fill:#fff3e0

    🔨 따라하기¶

    이제 실제로 코드를 변환해봅시다! 시뮬레이션 코드를 하나씩 실제 로봇 코드로 바꾸어 나갑니다.

    Step 1: 햄스터 로봇 연결 확인하기¶

    먼저 로봇이 정상적으로 연결되는지 확인합니다.

    from roboid import *

# 햄스터 로봇 생성 및 연결
hamster = Hamster()

# 연결 확인 - 왼쪽 근접 센서 값 읽기
import time
time.sleep(1)  # 연결 안정화 대기

left = hamster.left_proximity()
right = hamster.right_proximity()
print(f"왼쪽 센서: {left}, 오른쪽 센서: {right}")

# LED를 켜서 연결 확인
hamster.leds(LED_GREEN, LED_GREEN)
time.sleep(1)
hamster.leds(LED_OFF, LED_OFF)

    📌 팁: 센서 값이 0으로만 나온다면 로봇 앞에 손이나 종이를 가까이 대보세요. 값이 변하면 정상입니다!

    Step 2: 센서 값을 상태로 변환하는 함수 만들기¶

    시뮬레이션에서는 격자 좌표가 곧 상태였습니다. 실제 로봇에서는 센서 값을 읽어서 상태 번호로 바꿔야 합니다.

    def get_state(hamster):
    """햄스터 로봇의 센서를 읽어 상태 번호를 반환"""
    left = hamster.left_proximity()
    right = hamster.right_proximity()

    # 여러 번 읽어서 평균 내기 (노이즈 대응!)
    for _ in range(4):
        time.sleep(0.05)
        left += hamster.left_proximity()
        right += hamster.right_proximity()
    left = left / 5
    right = right / 5

    # 임계값 기준으로 상태 분류
    THRESHOLD = 40  # 이 값은 환경에 따라 조정 필요

    left_close = left > THRESHOLD
    right_close = right > THRESHOLD

    if left_close and right_close:
        return 0  # 양쪽 벽
    elif left_close:
        return 1  # 왼쪽 벽
    elif right_close:
        return 2  # 오른쪽 벽
    else:
        return 3  # 열린 공간

    🔑 핵심 포인트: 센서를 5번 읽어서 평균을 내는 이유가 보이시나요? 바로 센서 노이즈 때문입니다! 한 번 읽으면 48이었다가 다음엔 55가 나올 수 있거든요. 평균을 내면 훨씬 안정적입니다.

    Step 3: 행동을 실제 모터 명령으로 변환하기¶

    시뮬레이션에서 action = 0(전진), action = 1(좌회전), action = 2(우회전) 이었다면, 이를 실제 모터 속도로 바꿉니다.

    # 행동 정의 (시뮬레이션과 동일한 번호 체계)
ACTION_FORWARD = 0
ACTION_LEFT = 1
ACTION_RIGHT = 2

# 모터 속도 설정
SPEED = 30  # 기본 속도 (너무 빠르면 제어가 어려움!)
TURN_TIME = 0.5  # 회전 시간 (초)
MOVE_TIME = 0.5  # 전진 시간 (초)

def do_action(hamster, action):
    """행동 번호를 받아 실제 모터를 구동"""
    if action == ACTION_FORWARD:
        hamster.wheels(SPEED, SPEED)
        time.sleep(MOVE_TIME)

    elif action == ACTION_LEFT:
        hamster.wheels(-SPEED, SPEED)  # 왼쪽 뒤로, 오른쪽 앞으로
        time.sleep(TURN_TIME)

    elif action == ACTION_RIGHT:
        hamster.wheels(SPEED, -SPEED)  # 왼쪽 앞으로, 오른쪽 뒤로
        time.sleep(TURN_TIME)

    # 행동 후 정지
    hamster.wheels(0, 0)
    time.sleep(0.3)  # 관성으로 미끄러지는 시간 대기

    ⚡ 중요: 행동 후 wheels(0, 0)으로 정지시키고 0.3초를 기다리는 이유는 관성 때문입니다. 모터를 꺼도 로봇은 즉시 멈추지 않아요. 이 대기 시간이 없으면 센서를 읽는 타이밍에 로봇이 아직 움직이고 있어서 엉뚱한 값을 읽게 됩니다.

    Step 4: 보상 함수 만들기¶

    시뮬레이션에서는 목표 좌표에 도달하면 +10, 벽에 부딪히면 -5를 줬습니다. 실제 로봇에서는 센서로 판단해야 합니다.

    # 바닥 센서로 목표 지점 감지 (검은 테이프 = 골라인)
FLOOR_GOAL_THRESHOLD = 30  # 바닥이 검으면 낮은 값

def get_reward(hamster, state):
    """현재 상태와 센서를 기반으로 보상 계산"""
    floor_left = hamster.left_floor()
    floor_right = hamster.right_floor()

    # 목표 도달 (바닥에 검은 테이프를 붙여둠)
    if floor_left < FLOOR_GOAL_THRESHOLD and floor_right < FLOOR_GOAL_THRESHOLD:
        print("🎉 목표 도달!")
        return 100, True  # 보상, 에피소드 종료 여부

    # 양쪽 벽에 너무 가까움 (막다른 길)
    if state == 0:
        return -10, False

    # 한쪽 벽에 가까움 (주의 필요)
    if state == 1 or state == 2:
        return -1, False

    # 열린 공간에서 전진 (좋은 상황)
    return 1, False

    Step 6: 안전장치 추가하기¶

    실제 로봇은 잘못하면 책상에서 떨어지거나 벽에 계속 부딪힐 수 있습니다. 안전장치는 필수입니다.

    MAX_STEPS_PER_EPISODE = 50  # 한 에피소드 최대 행동 수

def emergency_check(hamster):
    """긴급 상황 체크 - 너무 가까운 장애물 감지"""
    left = hamster.left_proximity()
    right = hamster.right_proximity()

    # 양쪽 모두 매우 가까운 물체 감지 → 즉시 정지
    if left > 80 and right > 80:
        hamster.wheels(0, 0)
        print("⚠️ 긴급 정지! 장애물이 너무 가깝습니다.")
        return True
    return False

    📝 전체 코드¶

    아래는 시뮬레이션에서 학습한 Q-테이블을 로드해서 실제 로봇에서 실행하는 전체 코드입니다.

    from roboid import *
import time
import pickle
import random

# ===== 1. 로봇 연결 =====
hamster = Hamster()
time.sleep(1)

# ===== 2. 설정 값 =====
ACTION_FORWARD = 0
ACTION_LEFT = 1
ACTION_RIGHT = 2
NUM_ACTIONS = 3
NUM_STATES = 4
SPEED = 30
MOVE_TIME = 0.5
TURN_TIME = 0.5
THRESHOLD = 40
FLOOR_GOAL_THRESHOLD = 30
MAX_STEPS = 50

# ===== 3. 상태 변환 함수 =====
def get_state(hamster):
    left = hamster.left_proximity()
    right = hamster.right_proximity()
    for _ in range(4):
        time.sleep(0.05)
        left += hamster.left_proximity()
        right += hamster.right_proximity()
    left, right = left / 5, right / 5

    if left > THRESHOLD and right > THRESHOLD:
        return 0
    elif left > THRESHOLD:
        return 1
    elif right > THRESHOLD:
        return 2
    else:
        return 3

# ===== 4. 행동 실행 함수 =====
def do_action(hamster, action):
    if action == ACTION_FORWARD:
        hamster.wheels(SPEED, SPEED)
        time.sleep(MOVE_TIME)
    elif action == ACTION_LEFT:
        hamster.wheels(-SPEED, SPEED)
        time.sleep(TURN_TIME)
    elif action == ACTION_RIGHT:
        hamster.wheels(SPEED, -SPEED)
        time.sleep(TURN_TIME)
    hamster.wheels(0, 0)
    time.sleep(0.3)

# ===== 5. 보상 함수 =====
def get_reward(hamster, state):
    floor_left = hamster.left_floor()
    floor_right = hamster.right_floor()
    if floor_left < FLOOR_GOAL_THRESHOLD and floor_right < FLOOR_GOAL_THRESHOLD:
        return 100, True
    if state == 0:
        return -10, False
    if state in [1, 2]:
        return -1, False
    return 1, False

# ===== 6. Q-테이블 (시뮬레이션에서 학습한 것 불러오기 또는 새로 생성) =====
try:
    with open('q_table.pkl', 'rb') as f:
        q_table = pickle.load(f)
    print("✅ 저장된 Q-테이블을 불러왔습니다!")
except FileNotFoundError:
    q_table = [[0.0] * NUM_ACTIONS for _ in range(NUM_STATES)]
    print("📝 새 Q-테이블을 생성했습니다.")

# ===== 7. 행동 선택 함수 =====
def choose_action(state, epsilon=0.1):
    if random.random() < epsilon:
        return random.randint(0, NUM_ACTIONS - 1)
    return q_table[state].index(max(q_table[state]))

# ===== 8. 실제 로봇 실행 루프 =====
LEARNING_RATE = 0.1
DISCOUNT = 0.9
NUM_EPISODES = 5  # 실제 로봇은 적은 횟수로!

print("\n🤖 실제 로봇 학습을 시작합니다!")
print("로봇을 출발점에 놓아주세요.")
input("준비되면 Enter를 누르세요...")

for episode in range(NUM_EPISODES):
    print(f"\n--- 에피소드 {episode + 1}/{NUM_EPISODES} ---")
    input("로봇을 출발점에 놓고 Enter를 누르세요.")

    # reset 대신: 사람이 로봇을 출발점에 놓음
    hamster.leds(LED_GREEN, LED_GREEN)
    time.sleep(0.5)
    hamster.leds(LED_OFF, LED_OFF)

    state = get_state(hamster)
    total_reward = 0

    for step in range(MAX_STEPS):
        # 행동 선택
        action = choose_action(state, epsilon=0.2)

        # 행동 실행
        do_action(hamster, action)

        # 새로운 상태 관찰
        next_state = get_state(hamster)

        # 보상 계산
        reward, done = get_reward(hamster, next_state)
        total_reward += reward

        # Q-테이블 업데이트
        old_q = q_table[state][action]
        next_max = max(q_table[next_state])
        new_q = old_q + LEARNING_RATE * (reward + DISCOUNT * next_max - old_q)
        q_table[state][action] = new_q

        print(f"  Step {step+1}: 상태={state}→행동={action}→새상태={next_state}, 보상={reward}")

        state = next_state

        if done:
            hamster.leds(LED_GREEN, LED_GREEN)
            print(f"🎉 목표 도달! 총 보상: {total_reward}")
            time.sleep(2)
            hamster.leds(LED_OFF, LED_OFF)
            break
    else:
        hamster.leds(LED_RED, LED_RED)
        print(f"⏰ 시간 초과. 총 보상: {total_reward}")
        time.sleep(1)
        hamster.leds(LED_OFF, LED_OFF)

    hamster.wheels(0, 0)

# Q-테이블 저장
with open('q_table_real.pkl', 'wb') as f:
    pickle.dump(q_table, f)
print("\n💾 Q-테이블을 저장했습니다!")
print("🏁 학습 완료!")

    실수 1: 센서를 한 번만 읽고 상태를 결정한다 🎲¶

    # ❌ 이렇게 하면 노이즈에 취약!
def get_state_bad(hamster):
    left = hamster.left_proximity()  # 한 번만 읽음
    if left > 40:
        return 1

    실수 2: 행동 후 대기 시간 없이 바로 센서를 읽는다 ⏩¶

    # ❌ 로봇이 아직 움직이는 중에 센서를 읽음!
def do_and_read_bad(hamster, action):
    hamster.wheels(30, 30)
    time.sleep(0.5)
    hamster.wheels(0, 0)
    state = get_state(hamster)  # 관성으로 미끄러지는 중!

    모터를 끈 직후에도 로봇은 관성으로 움직입니다. 최소 0.2~0.3초 대기한 후 센서를 읽으세요.

    실수 3: 시뮬레이션의 속도 그대로 에피소드를 돌린다 🏃‍♂️¶

    시뮬레이션에서는 1000 에피소드를 몇 초 만에 돌렸지만, 실제 로봇은 한 에피소드에 몇 분이 걸립니다. 처음에는 3~5 에피소드만 실행하면서 잘 동작하는지 확인하세요. 시뮬레이션에서 미리 학습한 Q-테이블을 불러와서 사용하면 실제 로봇에서는 소수의 에피소드로도 충분합니다.

    실수 4: THRESHOLD 값을 조정하지 않는다 🔧¶

    코드의 THRESHOLD = 40은 환경마다 다를 수 있습니다. 벽의 재질, 색상, 거리에 따라 센서 값이 크게 달라집
