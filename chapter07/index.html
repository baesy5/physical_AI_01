    Chapter 7: if-else로 만드는 규칙 기반 라인트레이싱¶

    🎯 이 장에서 배우는 것¶

    • 4가지 센서 상태(직진, 좌회전, 우회전, 정지)에 대응하는 모터 동작을 정의할 수 있다
    • if-elif-else 구조를 활용한 완전한 라인트레이싱 프로그램을 작성할 수 있다
    • while 루프 안에서 센서 읽기 → 판단 → 모터 제어의 흐름을 구현할 수 있다
    • 실제 트랙에서 로봇을 주행시키고, 속도·임계값 조정으로 성능 변화를 관찰할 수 있다

    💡 왜 이걸 배우나요?¶

    앞 챕터에서 우리는 센서 값을 읽고, 그 값을 4가지 상태로 분류하는 방법을 배웠습니다. 하지만 분류만 해서는 로봇이 움직이지 않죠! 🤖

    이번 장은 "상태를 판단하고 → 행동으로 옮기는" 단계입니다.

    여러분이 횡단보도에 서 있다고 상상해 보세요.

    • 🟢 초록불이면? → 건넌다
    • 🔴 빨간불이면? → 멈춘다
    • 🟡 깜빡이면? → 주의하며 판단한다

    이처럼 "조건에 따라 행동을 결정하는 것" 이 바로 규칙 기반(Rule-based) 제어의 핵심입니다. 이 방법은 직관적이고 이해하기 쉬워서, 로봇 제어의 가장 기본이 됩니다. 오늘 이 챕터를 마치면 여러분의 로봇이 처음으로 스스로 선을 따라 달리는 모습을 볼 수 있습니다! 🎉

    📚 핵심 개념¶

    개념 1: 상태-동작 매핑 (State-Action Mapping)¶

    비유부터 시작해 봅시다.

    교통 경찰관을 떠올려 보세요. 경찰관은 상황을 보고 즉시 수신호를 보냅니다. "차가 왼쪽에서 오면 → 오른쪽을 통과시킨다", "앞이 막히면 → 정지 신호를 보낸다." 이런 식으로 상황(상태)마다 미리 정해둔 행동(동작)이 있습니다.

    정확한 정의: 상태-동작 매핑이란, 센서로 파악한 각 상태에 대해 모터가 취해야 할 동작을 1:1로 대응시키는 것입니다.

    우리 로봇의 매핑:

    • 직진 상태 (두 센서 모두 라인 감지) → 양쪽 모터 동일 속도로 전진
    • 좌회전 상태 (왼쪽 센서만 라인 감지) → 왼쪽 모터 느리게, 오른쪽 모터 빠르게
    • 우회전 상태 (오른쪽 센서만 라인 감지) → 왼쪽 모터 빠르게, 오른쪽 모터 느리게
    • 정지 상태 (두 센서 모두 라인 미감지) → 양쪽 모터 정지

    개념 2: if-elif-else 의사결정 구조¶

    비유: 레스토랑 주문을 생각해 보세요. 웨이터가 손님에게 묻습니다.

    "스테이크 드실 건가요?" → 아니요 → "파스타 드실 건가요?" → 아니요 → "그러면 샐러드를 드리겠습니다."

    첫 번째 조건부터 차례로 확인하고, 해당하는 게 나오면 바로 실행합니다. 위에서 아래로 순서대로 검사하는 것이 핵심입니다.

    코드 구조:

    if 조건1:
    # 조건1이 참이면 실행
elif 조건2:
    # 조건1은 거짓이고, 조건2가 참이면 실행
elif 조건3:
    # 위 조건 모두 거짓이고, 조건3이 참이면 실행
else:
    # 위 조건 모두 거짓이면 실행

    중요 포인트: elif는 "else if"의 줄임말입니다. 조건을 위에서부터 순서대로 검사하고, 하나라도 참이면 나머지는 건너뜁니다.

    개념 3: 제어 루프 (Control Loop)¶

    비유: 자전거를 탈 때를 떠올려 보세요. 우리 뇌는 계속 이런 일을 반복합니다.

    눈으로 본다 → 방향을 판단한다 → 핸들을 조작한다 → 다시 눈으로 본다 → ...

    이 과정이 끊임없이, 아주 빠르게 반복되기 때문에 자전거가 넘어지지 않고 달릴 수 있습니다.

    로봇도 마찬가지입니다. 센서 읽기 → 상태 판단 → 모터 제어를 while 루프로 계속 반복해야 합니다.

    while True:
    # 1. 센서 읽기
    # 2. 상태 판단 (if-elif-else)
    # 3. 모터 제어

    이 세 단계가 한 사이클(cycle) 이고, 이것이 초당 수십~수백 번 반복됩니다.

    flowchart LR A[센서 읽기] --> B[상태 판단] B --> C[모터 제어] C --> A

    개념 4: 속도 튜닝과 한계¶

    비유: 라디오 주파수를 맞추는 것과 같습니다. 📻 다이얼을 조금씩 돌려서 소리가 가장 깨끗하게 들리는 지점을 찾죠. 로봇의 속도와 임계값도 마찬가지입니다. 조금씩 바꿔가며 최적의 값을 찾는 과정을 튜닝(Tuning) 이라고 합니다.

    • 속도가 너무 빠르면: 커브에서 라인을 벗어남
    • 속도가 너무 느리면: 안정적이지만 답답함
    • 임계값이 잘못되면: 상태 판단 자체가 틀어짐

    규칙 기반 접근법은 직관적이고 쉽지만, 급커브나 교차로 같은 복잡한 상황에서는 한계가 있습니다. 이 한계를 직접 경험하는 것도 오늘의 중요한 학습입니다!

    🔨 따라하기¶

    Step 1: 상태-동작 규칙표 설계하기¶

    코드를 작성하기 전에, 종이에 먼저 규칙을 정리하는 습관을 들이세요. ✏️

    우리 로봇에는 왼쪽 센서(L)과 오른쪽 센서(R)가 있습니다. 센서가 라인 위에 있으면 True, 없으면 False라고 합시다.

    • L=True, R=True → 직진: 양쪽 모터 같은 속도
    • L=True, R=False → 좌회전: 왼쪽 모터 줄이고 오른쪽 모터 유지
    • L=False, R=True → 우회전: 왼쪽 모터 유지하고 오른쪽 모터 줄이기
    • L=False, R=False → 정지: 양쪽 모터 멈춤

    💬 잠깐, 왜 왼쪽 센서가 감지하면 '좌회전'인가요?

    왼쪽 센서만 라인을 감지한다는 것은, 로봇이 라인의 오른쪽으로 치우쳐 있다는 뜻입니다. 다시 라인 중앙으로 돌아오려면 왼쪽으로 방향을 틀어야 합니다. 자전거를 타다가 오른쪽으로 치우치면 핸들을 왼쪽으로 꺾는 것과 같습니다!

    Step 2: 기본 함수 준비하기¶

    앞 챕터에서 만든 센서 읽기 함수와 모터 제어 함수를 활용합니다. 아직 없다면 아래처럼 준비해 주세요.

    import time

# --- 하드웨어 설정 (여러분의 환경에 맞게 수정) ---
# GPIO 핀 번호나 라이브러리는 사용하는 보드에 따라 다릅니다.
# 여기서는 개념 이해를 위한 의사코드(pseudocode) 스타일로 작성합니다.

THRESHOLD = 500  # 라인 감지 임계값 (환경에 따라 조정)

def read_sensors():
    """왼쪽, 오른쪽 센서 값을 읽어 (left, right) 튜플로 반환"""
    left_value = read_adc(0)   # 왼쪽 센서 (채널 0)
    right_value = read_adc(1)  # 오른쪽 센서 (채널 1)
    return left_value, right_value

def set_motors(left_speed, right_speed):
    """왼쪽, 오른쪽 모터 속도를 설정 (0~100)"""
    motor_left.set_speed(left_speed)
    motor_right.set_speed(right_speed)

    🔧 read_adc()와 motor.set_speed()는 여러분이 사용하는 로봇 키트의 라이브러리에 맞게 바꿔 주세요. 핵심은 구조입니다!

    Step 3: 상태 판단 함수 만들기¶

    센서 값을 읽어서 4가지 상태 중 하나를 반환하는 함수를 만듭니다.

    def get_state(left_val, right_val):
    """센서 값을 받아 상태 문자열을 반환"""
    left_on = left_val > THRESHOLD    # 왼쪽 센서가 라인 감지?
    right_on = right_val > THRESHOLD  # 오른쪽 센서가 라인 감지?

    if left_on and right_on:
        return "STRAIGHT"
    elif left_on and not right_on:
        return "TURN_LEFT"
    elif not left_on and right_on:
        return "TURN_RIGHT"
    else:
        return "STOP"

    여기서 THRESHOLD보다 크면 라인 위에 있다고 판단합니다. (센서 종류에 따라 반대일 수 있으니 꼭 확인하세요!)

    Step 4: 동작 실행 함수 만들기¶

    상태에 따라 모터를 제어하는 함수입니다.

    # 속도 설정 (튜닝 포인트!)
BASE_SPEED = 50    # 기본 속도
TURN_SPEED = 20    # 회전 시 느린 쪽 속도

def execute_action(state):
    """상태에 따라 모터를 제어"""
    if state == "STRAIGHT":
        set_motors(BASE_SPEED, BASE_SPEED)
    elif state == "TURN_LEFT":
        set_motors(TURN_SPEED, BASE_SPEED)
    elif state == "TURN_RIGHT":
        set_motors(BASE_SPEED, TURN_SPEED)
    else:  # STOP
        set_motors(0, 0)

    🎯 핵심 포인트: 회전할 때 한쪽 모터를 완전히 멈추는 게 아니라 느리게 돌립니다. 이렇게 하면 부드럽게 커브를 돌 수 있습니다.

    Step 5: 전체 프로그램 조립하기 (제어 루프)¶

    이제 모든 조각을 while 루프 안에 조립합니다!

    def main():
    print("라인트레이싱 시작! 중지하려면 Ctrl+C")

    try:
        while True:
            # 1단계: 센서 읽기
            left_val, right_val = read_sensors()

            # 2단계: 상태 판단
            state = get_state(left_val, right_val)

            # 3단계: 동작 실행
            execute_action(state)

            # (디버깅용) 현재 상태 출력
            print(f"L:{left_val} R:{right_val} -> {state}")

            # 너무 빠른 반복 방지
            time.sleep(0.05)

    except KeyboardInterrupt:
        set_motors(0, 0)
        print("정지!")

main()

    이 코드의 흐름을 다이어그램으로 정리하면 이렇습니다.

    flowchart TD A[프로그램 시작] --> B[센서 값 읽기] B --> C{왼쪽 & 오른쪽\n모두 감지?} C -->|Yes| D[직진] C -->|No| E{왼쪽만\n감지?} E -->|Yes| F[좌회전] E -->|No| G{오른쪽만\n감지?} G -->|Yes| H[우회전] G -->|No| I[정지] D --> J[0.05초 대기] F --> J H --> J I --> J J --> B

    Step 6: 트랙에서 실행하고 튜닝하기¶

    🏁 드디어 실전입니다!

    1단계: 직선 트랙에서 테스트

    먼저 직선 구간에서 로봇이 라인을 따라가는지 확인하세요. 잘 따라간다면 기본 설정이 올바른 것입니다.

    2단계: 곡선 트랙에서 테스트

    곡선에서 라인을 벗어난다면? 아래 값들을 조정해 보세요.

    • BASE_SPEED를 낮추기: 50 → 40 → 30으로 줄여보세요. 느릴수록 안정적입니다.
    • TURN_SPEED를 낮추기: 20 → 10 → 0으로 줄여보세요. 회전이 더 급해집니다.
    • THRESHOLD 조정: 센서 값이 경계에 걸린다면 임계값을 바꿔보세요.

    3단계: 관찰 기록하기 📋

    실험 1: BASE_SPEED=50, TURN_SPEED=20 → 직선 OK, 급커브 이탈
실험 2: BASE_SPEED=40, TURN_SPEED=10 → 직선 OK, 급커브 OK, 느림
실험 3: BASE_SPEED=45, TURN_SPEED=15 → 가장 균형 잡힌 결과!

    이렇게 기록하면서 최적값을 찾아가는 과정이 엔지니어링의 핵심입니다!

    📝 전체 코드¶

    import time

# ========== 설정값 (여러분의 환경에 맞게 수정!) ==========
THRESHOLD = 500     # 라인 감지 임계값
BASE_SPEED = 50     # 기본 주행 속도 (0~100)
TURN_SPEED = 20     # 회전 시 느린 쪽 속도 (0~100)
LOOP_DELAY = 0.05   # 루프 간격 (초)

# ========== 센서 함수 ==========
def read_sensors():
    """왼쪽, 오른쪽 센서 값을 읽어 반환"""
    left_value = read_adc(0)
    right_value = read_adc(1)
    return left_value, right_value

# ========== 모터 함수 ==========
def set_motors(left_speed, right_speed):
    """왼쪽, 오른쪽 모터 속도 설정"""
    motor_left.set_speed(left_speed)
    motor_right.set_speed(right_speed)

# ========== 상태 판단 ==========
def get_state(left_val, right_val):
    """센서 값으로부터 주행 상태를 판단"""
    left_on = left_val > THRESHOLD
    right_on = right_val > THRESHOLD

    if left_on and right_on:
        return "STRAIGHT"
    elif left_on and not right_on:
        return "TURN_LEFT"
    elif not left_on and right_on:
        return "TURN_RIGHT"
    else:
        return "STOP"

# ========== 동작 실행 ==========
def execute_action(state):
    """상태에 따라 모터를 제어"""
    if state == "STRAIGHT":
        set_motors(BASE_SPEED, BASE_SPEED)
    elif state == "TURN_LEFT":
        set_motors(TURN_SPEED, BASE_SPEED)
    elif state == "TURN_RIGHT":
        set_motors(BASE_SPEED, TURN_SPEED)
    else:
        set_motors(0, 0)

# ========== 메인 루프 ==========
def main():
    print("라인트레이싱 시작! Ctrl+C로 중지")

    try:
        while True:
            left_val, right_val = read_sensors()
            state = get_state(left_val, right_val)
            execute_action(state)
            print(f"L:{left_val} R:{right_val} -> {state}")
            time.sleep(LOOP_DELAY)

    except KeyboardInterrupt:
        set_motors(0, 0)
        print("프로그램 종료. 모터 정지!")

main()

    ⚠️ 자주 하는 실수¶

    실수 1: if를 연속으로 쓰고 elif를 안 쓰는 경우 😵

    # ❌ 잘못된 코드
if state == "STRAIGHT":
    set_motors(50, 50)
if state == "TURN_LEFT":     # elif가 아니라 if!
    set_motors(20, 50)
if state == "TURN_RIGHT":    # 이것도 if!
    set_motors(50, 20)

    이렇게 하면 모든 if를 다 검사합니다. elif를 써야 하나가 참이면 나머지를 건너뜁니다. 성능 문제뿐 아니라 의도치 않은 동작이 발생할 수 있습니다.

    실수 2: 센서 값의 방향을 반대로 이해하는 경우 🔄

    어떤 센서는 라인 위에서 값이 높고, 어떤 센서는 라인 위에서 값이 낮습니다. 반드시 print()로 실제 값을 확인한 후에 THRESHOLD와 비교 방향(> vs <)을 결정하세요!

    # 먼저 이렇게 센서 값을 확인하세요
while True:
    l, r = read_sensors()
    print(f"왼쪽: {l}, 오른쪽: {r}")
    time.sleep(0.5)

    실수 3: time.sleep()을 빼먹거나 너무 길게 설정하는 경우 ⏰

    • sleep()이 없으면: CPU를 100% 사용하고, 출력이 너무 빨라 디버깅이 불가능
    • sleep(1)처럼 너무 길면: 1초에 한 번만 센서를 읽으므로 반응이 심각하게 느림
    • 권장값: sleep(0.02) ~ sleep(0.1) (초당 10~50회 확인)

    실수 4: 좌회전/우회전 모터를 반대로 설정하는 경우 ↔️

    좌회전인데 오른쪽 모터를 느리게 하면 오른쪽으로 돕니다! 헷갈리면 이렇게 기억하세요.

    🧠 "가고 싶은 방향의 모터를 느리게!" 왼쪽으로 가고 싶다 → 왼쪽 모터를 느리게 → 로봇이 왼쪽으로 회전

    ✅ 스스로 점검하기¶

    아래 질문에 답해 보세요. 모두 자신 있게 대답할 수 있다면 이 챕터를 완전히 이해한 것입니다! 💪

    1. 왼쪽 센서만 라인을 감지했을 때, 왼쪽 모터와 오른쪽 모터 중 어느 쪽이 느려져야 하나요? 그 이유는?

    💬 왼쪽 모터가 느려져야 합니다. 로봇이 오른쪽으로 치우친 상태이므로, 왼쪽으로 돌아오려면 왼쪽 모터를 줄여야 합니다.

    2. if를 4번 연속 쓰는 것과 if-elif-elif-else를 쓰는 것의 차이는?

    💬 if 4번은 매번 모든 조건을 검사합니다. if-elif-else는 하나가 참이면 나머지를 건너뛰어 효율적이고, 의도하지 않은 중복 실행을 방지합니다.

    3. 로봇이 커브에서 자꾸 라인을 벗어난다면, 어떤 값을 어떻게 바꿔볼 수 있나요?

    💬 BASE_SPEED를 낮추거나, TURN_SPEED를 더 낮춰서 회전을 더 급하게 만들 수 있습니다. THRESHOLD도 확인해 볼 필요가 있습니다.

    4. 제어 루프에서 time.sleep(0.05)의 역할은?

    💬 루프가 너무 빠르게 돌아가는 것을 방지합니다. CPU 부담을 줄이고, 디버깅 출력을 읽을 수 있게 합니다.
