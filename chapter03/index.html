    Chapter 03: 시뮬레이션이 중요한 이유¶

    🎯 이 장에서 배우는 것¶

    • 자율주행 개발에서 시뮬레이션이 왜 필수적인지 3가지 이유를 설명할 수 있다
    • CARLA 시뮬레이터의 서버-클라이언트 구조와 주요 기능을 이해할 수 있다
    • Sim-to-Real(시뮬레이션에서 현실로) 전환 개념과 그 한계를 설명할 수 있다
    • Python으로 CARLA 시뮬레이터에 접속하여 가상 차량을 생성할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔

    웨이모(Waymo)는 하루에 약 2,000만 킬로미터를 가상으로 주행합니다. 이것은 실제 도로에서 테스트한 거리의 1,000배 이상입니다. 왜 자율주행 회사들은 수십억 킬로미터를 가상으로 먼저 주행시킬까요?

    자율주행 자동차를 실제 도로에서 테스트하는 것은 마치 운전면허를 따기 전에 고속도로에 나가는 것과 같습니다. 위험하고, 비용이 많이 들고, 비효율적이죠.

    실제 도로 테스트의 문제점을 구체적으로 살펴봅시다.

    • 안전 문제 🚨: AI가 학습 중 실수하면 사고로 이어집니다. 보행자, 다른 차량 모두 위험에 노출됩니다
    • 비용 문제 💰: 테스트 차량 한 대에 센서만 수억 원, 운영 인력과 보험료까지 합치면 연간 수십억 원이 소요됩니다
    • 시간 문제 ⏰: 비가 오는 날, 눈이 오는 날, 야간 등 특정 조건을 기다려야 합니다. 원하는 시나리오를 만들 수 없습니다
    • 재현 불가 🔄: "어제 그 교차로에서 일어난 상황"을 똑같이 다시 만들 수 없습니다

    시뮬레이션은 이 모든 문제를 해결합니다. 이번 장에서는 자율주행의 연습장인 시뮬레이션의 세계를 탐험합니다.

    📚 핵심 개념¶

    개념 1: 시뮬레이션의 역할 — 자율주행의 비행 시뮬레이터 ✈️¶

    비유로 시작합시다.

    비행기 조종사가 되려면 어떻게 할까요? 처음부터 실제 비행기를 몰지 않습니다. 비행 시뮬레이터에서 수백 시간을 훈련합니다. 엔진 고장, 악천후, 비상 착륙 등 실제로 겪으면 위험한 상황을 안전하게 연습합니다.

    자율주행 시뮬레이션도 똑같은 원리입니다.

    정확한 정의

    자율주행 시뮬레이션이란, 컴퓨터 안에 가상의 도로·차량·센서·환경을 만들어 자율주행 AI를 훈련하고 테스트하는 기술입니다.

    시뮬레이션이 자율주행 개발에서 수행하는 세 가지 핵심 역할이 있습니다.

    ① 안전한 훈련 환경 제공

    가상 세계에서는 AI가 아무리 실수해도 괜찮습니다. 벽에 부딪히고, 신호를 무시하고, 보행자를 인식하지 못해도 아무도 다치지 않습니다. 실패에서 배우는 것이 AI 학습의 핵심이기 때문에, 안전하게 실패할 수 있는 환경이 반드시 필요합니다.

    ② 극한 상황 테스트

    현실에서 만들기 어려운 시나리오를 자유롭게 생성할 수 있습니다.

    • 폭우 속 역주행 차량이 나타나는 상황
    • 갑자기 공이 도로로 굴러가고 뒤이어 어린이가 뛰어나오는 상황
    • 터널 출구에서 강렬한 역광이 카메라를 덮는 상황

    이런 시나리오를 현실에서 재현하는 것은 불가능하거나 매우 위험합니다.

    ③ 대규모 병렬 학습

    컴퓨터 한 대로 수십 개의 가상 차량을 동시에 돌릴 수 있습니다. 1,000대의 가상 차량이 각각 다른 시나리오를 동시에 경험하면, 하루 만에 수백만 킬로미터의 주행 데이터를 생성할 수 있습니다.

    알아보기 📖

    테슬라는 자체 시뮬레이터에서 매일 수백만 건의 시나리오를 돌립니다. Waymo는 2023년 기준 누적 200억 마일 이상을 시뮬레이션으로 주행했습니다. 실제 도로 테스트만으로는 수천 년이 걸릴 양입니다.

    flowchart LR A["🏗️ 시뮬레이션 환경 구축"] --> B["🤖 AI 훈련\n(수십억 km 가상 주행)"] B --> C["📊 성능 평가\n(안전성 검증)"] C --> D{"통과?"} D -->|"❌ 미달"| B D -->|"✅ 통과"| E["🚗 실차 테스트"] E --> F["🛣️ 실제 도로 배포"]

    개념 2: CARLA 시뮬레이터 — 오픈소스 자율주행 연습장 🎮¶

    비유로 시작합시다.

    CARLA는 자율주행 AI를 위한 GTA(게임) 같은 것입니다. 다만 게임은 사람이 즐기기 위한 것이고, CARLA는 AI가 운전을 배우기 위한 것입니다. 도시의 건물, 도로, 신호등, 보행자, 날씨까지 모두 진짜처럼 구현되어 있습니다.

    정확한 정의

    CARLA(Car Learning to Act)는 자율주행 연구를 위해 만들어진 오픈소스 시뮬레이터입니다. 인텔 연구소와 바르셀로나 컴퓨터 비전 센터가 2017년에 공개했으며, Unreal Engine 기반의 사실적인 3D 환경을 제공합니다.

    CARLA의 핵심 구조: 서버-클라이언트

    CARLA는 서버와 클라이언트가 분리된 구조로 동작합니다. 이것이 CARLA의 가장 중요한 설계 원리입니다.

    flowchart TB subgraph SERVER["🖥️ CARLA 서버"] S1["3D 세계 렌더링\n(Unreal Engine)"] S2["물리 엔진\n(차량 움직임 계산)"] S3["가상 센서 시뮬레이션"] S4["NPC 차량·보행자 AI"] end subgraph CLIENT["🐍 Python 클라이언트"] C1["차량 제어 명령\n(조향, 가속, 브레이크)"] C2["센서 데이터 수신\n(카메라, LiDAR)"] C3["자율주행 AI 알고리즘"] end SERVER <-->|"TCP 통신"| CLIENT
    • 서버: 가상 세계 그 자체입니다. 3D 그래픽을 그리고, 물리 법칙을 계산하고, 센서 데이터를 생성합니다
    • 클라이언트: 여러분이 Python으로 작성하는 프로그램입니다. 서버에 접속하여 차량을 생성하고, 센서 데이터를 읽고, 운전 명령을 내립니다

    이 구조의 장점은? 클라이언트를 여러 개 동시에 연결할 수 있습니다. 하나의 가상 세계에 여러 자율주행 AI를 동시에 테스트할 수 있다는 뜻입니다!

    CARLA가 제공하는 주요 기능

    • 가상 센서 📸: RGB 카메라, 깊이 카메라, LiDAR, RADAR, GPS, IMU 등 실제 자율주행차에 탑재되는 센서를 가상으로 재현합니다
    • 날씨 시뮬레이션 🌧️: 맑음, 흐림, 비, 안개, 야간 등 다양한 기상 조건을 실시간으로 변경할 수 있습니다
    • 교통 시뮬레이션 🚦: NPC(Non-Player Character) 차량과 보행자가 교통법규를 지키며 움직입니다
    • 다양한 맵 🗺️: 도심, 교외, 고속도로 등 다양한 도로 환경이 내장되어 있습니다

    개념 3: Sim-to-Real — 가상에서 현실로의 도약 🌉¶

    비유로 시작합시다.

    수영장에서 수영을 완벽하게 배운 사람이 바다에 나가면 어떨까요? 파도, 해류, 수온 차이 때문에 처음에는 당황합니다. 수영 실력 자체는 통하지만, 환경이 다르기 때문에 적응 과정이 필요합니다.

    시뮬레이션에서 훈련한 AI도 마찬가지입니다. 가상 세계에서 완벽하게 운전하던 AI가 실제 도로에서는 헤매는 경우가 발생합니다.

    정확한 정의

    Sim-to-Real(시뮬레이션에서 현실로 전환)이란, 시뮬레이션 환경에서 훈련한 AI 모델을 실제 물리적 환경(현실 세계)에서 작동하도록 이식하는 과정입니다.

    Sim-to-Real Gap이 발생하는 이유

    시뮬레이션과 현실 사이에는 다음과 같은 차이(Gap)가 존재합니다.

    flowchart TB GAP["🔍 Sim-to-Real Gap의 원인"] GAP --> V["👁️ 시각적 차이\n시뮬레이션 그래픽은\n현실보다 단순함"] GAP --> P["⚙️ 물리적 차이\n타이어 마찰, 바람 저항 등\n완벽히 재현 불가"] GAP --> S["📡 센서 차이\n가상 센서에는\n노이즈·왜곡이 부족"] GAP --> B["🧠 행동 차이\n실제 운전자·보행자는\n예측 불가능하게 행동"]

    Sim-to-Real Gap을 줄이는 방법들

    • 도메인 랜덤화(Domain Randomization) 🎲: 시뮬레이션에서 텍스처, 조명, 물체 크기 등을 매번 무작위로 바꿉니다. AI가 다양한 변화에 강해지면 현실에서도 잘 적응합니다
    • 도메인 적응(Domain Adaptation) 🔄: 시뮬레이션 이미지를 현실 이미지와 비슷하게 변환하는 기술을 사용합니다
    • 시뮬레이션 정밀도 향상 🎯: 시뮬레이션 자체를 최대한 현실에 가깝게 만듭니다. NVIDIA의 Omniverse처럼 물리 법칙을 정밀하게 재현하는 플랫폼이 이 접근법을 사용합니다

    생각해보기 🤔

    게임 그래픽이 점점 현실과 구별하기 어려울 정도로 발전하고 있습니다. 언젠가 시뮬레이션이 현실과 완벽히 동일해지면, Sim-to-Real Gap은 사라질까요? 아니면 근본적으로 해결 불가능한 차이가 있을까요?

    개념 4: 자율주행 개발 파이프라인에서 시뮬레이션의 위치 🔄¶

    자율주행 시스템은 하루아침에 완성되지 않습니다. 여러 단계를 반복하며 점진적으로 성능을 높여가는 개발 파이프라인이 존재합니다.

    flowchart LR A["1️⃣ 데이터 수집\n시뮬레이션 + 실제 도로"] --> B["2️⃣ AI 모델 훈련\n인지·판단·제어"] B --> C["3️⃣ 시뮬레이션 테스트\n수백만 시나리오 검증"] C --> D["4️⃣ 폐쇄 도로 테스트\n제한된 실제 환경"] D --> E["5️⃣ 공개 도로 테스트\n안전 운전자 탑승"] E --> F["6️⃣ 상용 서비스\n완전 무인 운행"] C -->|"실패 시 피드백"| B D -->|"문제 발견 시"| C

    시뮬레이션은 3단계에서 핵심적인 역할을 합니다. 하지만 1단계(합성 데이터 생성)에서도, 2단계(강화학습 환경)에서도 활용됩니다. 사실상 전체 개발 과정에 시뮬레이션이 녹아 있는 셈입니다.

    정리하기 📋

    4가지 핵심 개념 요약 - 시뮬레이션의 역할: 안전, 비용, 시간, 재현성 문제를 해결하는 자율주행의 필수 도구 - CARLA 시뮬레이터: 서버-클라이언트 구조의 오픈소스 자율주행 시뮬레이터 - Sim-to-Real: 가상에서 훈련한 AI를 현실에 적용하는 과정과 그 격차 - 개발 파이프라인: 시뮬레이션은 자율주행 개발 전 단계에 걸쳐 활용됨

    🔨 따라하기: CARLA에서 첫 번째 가상 차량 만들기¶

    이제 직접 CARLA 시뮬레이터에 접속하여 가상 차량을 생성해봅시다!

    사전 준비¶

    CARLA 시뮬레이터가 이미 설치되어 있다고 가정합니다. 아직 설치하지 않았다면, CARLA 공식 문서(https://carla.readthedocs.io)의 Quick Start를 참고하세요.

    필요한 것: - CARLA 0.9.15 이상 - Python 3.7 이상 - carla Python 패키지 (CARLA 설치 시 함께 제공)

    Step 1: CARLA 서버 실행하기¶

    먼저 CARLA 서버를 실행합니다. 터미널에서 CARLA가 설치된 폴더로 이동한 뒤 실행합니다.

    # Windows
cd C:\CARLA_0.9.15
CarlaUE4.exe

# Linux
cd ~/CARLA_0.9.15
./CarlaUE4.sh

    실행하면 3D 도시가 렌더링된 창이 뜹니다. 이것이 서버입니다. 서버가 실행된 상태에서 Python 클라이언트로 접속합니다.

    💡 팁: GPU 성능이 부족하면 -quality-level=Low 옵션을 추가하세요.

    Step 2: Python 클라이언트로 서버에 접속하기¶

    새 터미널을 열고 Python 스크립트를 작성합니다.

    import carla
import time

# 1. CARLA 서버에 접속
client = carla.Client('localhost', 2000)
client.set_timeout(10.0)  # 10초 내 응답 없으면 에러

# 2. 가상 세계(World) 가져오기
world = client.get_world()

print(f"접속 성공! 현재 맵: {world.get_map().name}")

    localhost는 "이 컴퓨터"를 의미하고, 2000은 CARLA 서버의 기본 포트 번호입니다.

    Step 3: 가상 차량 생성하기¶

    # 3. 차량 블루프린트(설계도) 가져오기
blueprint_library = world.get_blueprint_library()
vehicle_bp = blueprint_library.find('vehicle.tesla.model3')

# 4. 차량이 생성될 위치 선택 (스폰 포인트)
spawn_points = world.get_map().get_spawn_points()
spawn_point = spawn_points[0]  # 첫 번째 스폰 포인트 사용

# 5. 차량 생성!
vehicle = world.spawn_actor(vehicle_bp, spawn_point)
print(f"차량 생성 완료! ID: {vehicle.id}")

    블루프린트(Blueprint)란? 🏗️ 차량의 "설계도"입니다. CARLA에는 Tesla, Audi, BMW 등 다양한 차량 모델의 블루프린트가 내장되어 있습니다. blueprint_library에서 원하는 차량을 골라 사용합니다.

    Step 4: 카메라 센서 부착하기¶

    # 6. 카메라 블루프린트 설정
camera_bp = blueprint_library.find('sensor.camera.rgb')
camera_bp.set_attribute('image_size_x', '800')
camera_bp.set_attribute('image_size_y', '600')

# 7. 카메라 위치 설정 (차량 위 1.5m)
camera_transform = carla.Transform(
    carla.Location(x=1.5, z=2.4)  # 차량 앞쪽 1.5m, 위쪽 2.4m
)

# 8. 카메라를 차량에 부착
camera = world.spawn_actor(camera_bp, camera_transform, attach_to=vehicle)

# 9. 카메라 이미지 저장 콜백
def save_image(image):
    image.save_to_disk(f'output/{image.frame:06d}.png')

camera.listen(save_image)
print("카메라 부착 완료! 이미지 저장 시작...")

    Step 5: 차량을 움직이고 날씨 변경하기¶

    # 10. 차량에 자동 조종(Autopilot) 활성화
vehicle.set_autopilot(True)
print("자동 조종 모드 ON — 차량이 스스로 주행합니다!")

# 11. 날씨를 비 오는 날로 변경
weather = carla.WeatherParameters(
    cloudiness=80.0,       # 구름 80%
    precipitation=60.0,    # 강수량 60%
    sun_altitude_angle=30.0  # 태양 고도 30도
)
world.set_weather(weather)
print("날씨 변경: 비 오는 오후")

# 12. 20초간 주행 관찰
time.sleep(20)

    Step 6: 정리 (리소스 해제)¶

    # 13. 생성한 액터들 제거 (중요!)
camera.stop()       # 카메라 리스닝 중지
camera.destroy()    # 카메라 제거
vehicle.destroy()   # 차량 제거
print("정리 완료!")

    ⚠️ 중요: destroy()를 호출하지 않으면 가상 세계에 차량과 센서가 계속 남아 메모리가 낭비됩니다. 항상 정리하는 습관을 들이세요!

    📝 전체 코드¶

    """
CARLA 시뮬레이터 첫 번째 실습
- 가상 차량 생성, 카메라 부착, 자동 주행, 날씨 변경
"""
import carla
import time
import os

# === 설정 ===
CARLA_HOST = 'localhost'
CARLA_PORT = 2000
OUTPUT_DIR = 'output'

def main():
    # 이미지 저장 폴더 생성
    os.makedirs(OUTPUT_DIR, exist_ok=True)

    # 서버 접속
    client = carla.Client(CARLA_HOST, CARLA_PORT)
    client.set_timeout(10.0)
    world = client.get_world()
    print(f"✅ 접속 성공! 현재 맵: {world.get_map().name}")

    # 차량 생성
    blueprint_library = world.get_blueprint_library()
    vehicle_bp = blueprint_library.find('vehicle.tesla.model3')
    spawn_point = world.get_map().get_spawn_points()[0]
    vehicle = world.spawn_actor(vehicle_bp, spawn_point)
    print(f"🚗 차량 생성 완료! ID: {vehicle.id}")

    # 카메라 부착
    camera_bp = blueprint_library.find('sensor.camera.rgb')
    camera_bp.set_attribute('image_size_x', '800')
    camera_bp.set_attribute('image_size_y', '600')
    camera_transform = carla.Transform(
        carla.Location(x=1.5, z=2.4)
    )
    camera = world.spawn_actor(
        camera_bp, camera_transform, attach_to=vehicle
    )
    camera.listen(
        lambda image: image.save_to_disk(
            f'{OUTPUT_DIR}/{image.frame:06d}.png'
        )
    )
    print("📸 카메라 부착 완료!")

    # 자동 조종 + 날씨 변경
    vehicle.set_autopilot(True)
    print("🤖 자동 조종 모드 ON")

    weather = carla.WeatherParameters(
        cloudiness=80.0,
        precipitation=60.0,
        sun_altitude_angle=30.0
    )
    world.set_weather(weather)
    print("🌧️ 날씨: 비 오는 오후")

    # 20초 주행
    print("⏳ 20초간 주행 중...")
    time.sleep(20)

    # 정리
    camera.stop()
    camera.destroy()
    vehicle.destroy()
    print("🧹 정리 완료!")

if __name__ == '__main__':
    main()

    실행하면 output/ 폴더에 카메라가 촬영한 이미지들이 저장됩니다. 비 오는 날씨 속에서 가상 Tesla가 도시를 주행하는 모습을 확인할 수 있습니다!

    ⚠️ 자주 하는 실수¶

    실수 1: CARLA 서버를 실행하지 않고 클라이언트 코드를 돌리는 경우 🔌

    RuntimeError: time-out of 10000ms while waiting for the simulator

    이 에러가 보인다면 CARLA 서버(CarlaUE4.exe 또는 CarlaUE4.sh)가 실행 중인지 확인하세요. 서버가 완전히 로딩된 후(3D 화면이 뜬 후) 클라이언트를 실행해야 합니다.

    실수 2: destroy()를 호출하지 않아 가상 세계가 엉망이 되는 경우 🗑️

    스크립트를 여러 번 실행하면 차량이 계속 누적됩니다. 도로에 수십 대의 유령 차량이 쌓여 시뮬레이션이 느려집니다. 반드시 try-finally 패턴을 사용하세요.

    try:
    vehicle = world.spawn_actor(vehicle_bp, spawn_point)
    # ... 작업 수행 ...
finally:
    vehicle.destroy()  # 에러가 나더라도 반드시 정리

    실수 3: 스폰 포인트 충돌 💥

    같은 위치에 두 대의 차량을 생성하면 물리 엔진이 충돌을 감지하여 에러가 발생합니다. spawn_points 리스트에서 서로 다른 인덱스를 사용하거나, try_spawn_actor()를 사용하세요. try_spawn_actor()는 실패 시 에러 대신 None을 반환합니다.

    실수 4: Sim-to-Real을 과신하는 경우 🌉

    시뮬레이션에서 100% 성공했다고 현실에서도 잘 될 거라고 생각하는 것은 위험합니다. 시뮬레이션 성능은 필요조건이지 충분조건이 아닙니다. 반드시 실차 테스트를 거쳐야 합니다.
