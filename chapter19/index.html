    Chapter 19: 실제 로봇으로 Q-learning 학습 실행¶

    🎯 이 장에서 배우는 것¶

    • 시뮬레이션에서 학습한 Q-테이블을 실제 햄스터 로봇에 불러와 적용(Transfer)할 수 있다
    • 실제 트랙 환경에서 Q-learning 학습 루프를 실행하고 에피소드를 반복할 수 있다
    • 로봇 이탈, 센서 오류 등 실제 학습 중 발생하는 문제에 대처할 수 있다
    • 학습 과정을 기록하고, 성능 개선을 관찰·분석할 수 있다

    💡 왜 이걸 배우나요?¶

    지금까지 우리는 시뮬레이션 안에서 Q-learning을 훈련했습니다. 화면 속 가상 로봇은 벽에 부딪혀도 아프지 않고, 센서 값은 항상 깨끗했죠. 하지만 진짜 세계는 다릅니다.

    바닥 재질이 조금만 달라져도 바퀴가 미끄러지고, 조명이 바뀌면 바닥 센서 값이 흔들립니다. 로봇이 트랙을 이탈하면 누군가 직접 손으로 돌려놔야 합니다. 이것이 바로 강화학습 연구에서 가장 도전적인 부분인 "Sim-to-Real Transfer" — 시뮬레이션에서 현실로의 전환입니다.

    이 장에서 여러분은 시뮬레이션에서 열심히 학습시킨 Q-테이블을 실제 햄스터 로봇에 올리고, 진짜 트랙 위에서 로봇이 달리는 것을 눈으로 확인합니다. 처음엔 삐걱거리던 로봇이 추가 학습을 통해 점점 나아지는 모습을 보면, "내가 만든 AI가 현실에서 작동한다!" 라는 감동을 느낄 수 있을 거예요. 🤖✨

    📚 핵심 개념¶

    개념 1: Sim-to-Real Transfer (시뮬레이션 → 현실 전이)¶

    🎭 비유로 시작

    비행기 조종사가 처음부터 실제 비행기를 모는 건 아닙니다. 먼저 플라이트 시뮬레이터에서 충분히 연습한 뒤, 실제 비행기에 앉습니다. 하지만 시뮬레이터에서 아무리 잘해도 실제 비행에선 바람, 난기류, 계기판의 미세한 차이가 있죠. 그래서 실제 비행기에서도 추가 훈련이 필요합니다.

    📖 정확한 정의

    Sim-to-Real Transfer란, 시뮬레이션 환경에서 학습한 정책(Q-테이블)을 실제 물리적 로봇에 적용하는 기법입니다. 시뮬레이션은 빠르고 안전하게 수천 번의 에피소드를 돌릴 수 있지만, 현실과 100% 동일하지 않습니다. 이 차이를 "Reality Gap" 이라고 부릅니다.

    🔍 예시로 확인

    • 시뮬레이션: 바닥 센서가 검은색 위에서 항상 0~50 값 반환
    • 실제 환경: 조명에 따라 10~80까지 흔들림
    • 시뮬레이션: 모터 속도 30 → 정확히 직진
    • 실제 환경: 모터 속도 30 → 약간 왼쪽으로 치우침 (바퀴 마모 등)
    flowchart LR A["🖥️ 시뮬레이션 학습<br/>수천 에피소드<br/>빠르고 안전"] --> B["💾 Q-테이블 저장<br/>(JSON/pickle)"] B --> C["🤖 실제 로봇에 로드"] C --> D["🏃 실제 환경 테스트<br/>Reality Gap 확인"] D --> E["🔄 추가 학습<br/>(Fine-tuning)<br/>현실에 적응"] E --> F["✅ 최종 성능 달성"]

    개념 2: 실제 환경 학습 루프의 구조¶

    🎭 비유로 시작

    요리 레시피를 보고 따라 하는 것을 생각해보세요. 레시피(시뮬레이션)에서는 "중불에서 3분"이라고 했지만, 실제 가스레인지는 화력이 다를 수 있습니다. 그래서 직접 냄비를 보면서 "좀 더 줄일까? 좀 더 익힐까?"를 실시간으로 판단합니다. 로봇 학습도 마찬가지입니다.

    📖 정확한 정의

    실제 환경 학습 루프는 시뮬레이션과 동일한 Q-learning 알고리즘을 따르되, 몇 가지 현실적 요소가 추가됩니다.

    • 시간 제어: 실제 로봇은 물리적 시간이 필요합니다. 액션 후 센서를 읽기까지 대기 시간이 필요합니다
    • 수동 개입: 로봇이 트랙을 이탈하면 사람이 직접 복귀시켜야 합니다
    • 에피소드 종료 판단: 시뮬레이션에서는 자동이지만, 실제에서는 이탈 감지 + 수동 판단이 함께 필요합니다

    🔍 예시로 확인

    flowchart TD A["에피소드 시작<br/>로봇을 출발선에 놓기"] --> B["센서 읽기<br/>상태 s 결정"] B --> C{"ε-greedy로<br/>행동 a 선택"} C --> D["모터 명령 전송<br/>일정 시간 대기"] D --> E["새 센서 읽기<br/>상태 s' 결정"] E --> F["보상 r 계산"] F --> G["Q-테이블 업데이트"] G --> H{"트랙 이탈?<br/>또는 목표 도달?"} H -- 아니오 --> B H -- 이탈 --> I["⚠️ 로봇 수동 복귀<br/>에피소드 종료"] H -- 목표 도달 --> J["🎉 에피소드 성공!"] I --> A J --> A

    개념 3: 현실 세계의 문제와 대처법¶

    🎭 비유로 시작

    시험공부를 집에서 완벽하게 했는데, 시험장에 가니 에어컨 소리가 너무 크고, 옆 사람이 계속 기침을 합니다. 공부한 내용은 같지만 환경이 다르면 실력 발휘가 어렵습니다. 로봇도 정확히 같은 상황입니다.

    📖 정확한 정의

    실제 로봇 학습에서 자주 발생하는 문제와 각각의 대처 전략입니다.

    문제 1 — 센서 노이즈 - 증상: 같은 위치인데 센서 값이 매번 다름 - 대처: 센서 값을 여러 번 읽어서 평균 내기 (이동 평균 필터)

    문제 2 — 트랙 이탈 - 증상: 로봇이 검은 선을 벗어나 멈춤 없이 달려감 - 대처: 양쪽 센서가 모두 밝은 값(흰색)이면 즉시 정지 + 큰 음수 보상

    문제 3 — 모터 비대칭 - 증상: 직진 명령을 줬는데 한쪽으로 치우침 - 대처: 모터 보정값(offset)을 사전에 측정해서 적용

    문제 4 — 배터리 소모 - 증상: 학습 후반에 모터 출력이 약해짐 - 대처: 일정 에피소드마다 배터리 확인, 완충 후 재개

    개념 4: 학습 기록과 성능 관찰¶

    🎭 비유로 시작

    다이어트를 할 때 매일 체중을 기록하면 효과가 보입니다. 기록하지 않으면 "나아지고 있는 건지, 제자리인 건지" 알 수 없죠. 로봇 학습도 매 에피소드의 결과를 기록해야 개선 여부를 판단할 수 있습니다.

    📖 정확한 정의

    학습 기록(logging)이란, 각 에피소드에서의 총 보상, 생존 스텝 수, 이탈 여부 등을 저장하는 것입니다. 이 데이터를 시각화하면 학습 곡선(learning curve)을 그릴 수 있고, "에피소드가 진행될수록 로봇이 더 오래, 더 잘 달린다"는 것을 확인할 수 있습니다.

    🔍 기록할 항목들 - 에피소드 번호 - 총 스텝 수 (오래 살아남을수록 좋음) - 누적 보상 - 이탈 횟수 - 특이사항 (수동 개입 여부 등)

    🔨 따라하기¶

    준비물 확인! - 햄스터 로봇 (배터리 완충) - 검은 테이프로 만든 트랙 (이전 장에서 준비) - 시뮬레이션에서 저장한 Q-테이블 파일 (q_table.json) - 파이썬 환경 + roboid 라이브러리 설치 완료

    Step 1: 시뮬레이션 Q-테이블 불러오기 💾¶

    먼저 이전 장에서 시뮬레이션으로 학습해둔 Q-테이블을 불러옵니다. Q-테이블이 없다면, 빈 테이블로 시작해도 됩니다(다만 학습에 더 많은 에피소드가 필요합니다).

    import json
import numpy as np

def load_q_table(filename="q_table.json"):
    """저장된 Q-테이블을 불러온다"""
    try:
        with open(filename, "r") as f:
            data = json.load(f)
        q_table = {}
        for key, values in data.items():
            # JSON에서는 키가 문자열이므로 튜플로 변환
            state = tuple(map(int, key.strip("()").split(",")))
            q_table[state] = np.array(values)
        print(f"✅ Q-테이블 로드 완료! 상태 수: {len(q_table)}")
        return q_table
    except FileNotFoundError:
        print("⚠️ 저장된 Q-테이블이 없습니다. 빈 테이블로 시작합니다.")
        return {}

def save_q_table(q_table, filename="q_table_real.json"):
    """Q-테이블을 파일로 저장한다"""
    data = {}
    for state, values in q_table.items():
        key = str(state)
        data[key] = values.tolist()
    with open(filename, "w") as f:
        json.dump(data, f, indent=2)
    print(f"💾 Q-테이블 저장 완료! ({filename})")

# Q-테이블 불러오기
q_table = load_q_table("q_table.json")

    핵심 포인트: Q-테이블을 JSON으로 저장/불러오기 할 때, 딕셔너리의 키(상태 튜플)와 값(numpy 배열)의 형변환에 주의하세요!

    Step 2: 실제 로봇 연결 및 센서 보정 🔧¶

    로봇을 연결하고, 현재 환경에서 센서 값이 어떤 범위인지 확인합니다. 이 단계가 매우 중요합니다 — 시뮬레이션과 실제 센서 값은 분명히 다릅니다!

    import roboid
import time

# 햄스터 로봇 연결
hamster = roboid.Hamster()
time.sleep(1)  # 연결 안정화 대기

def read_sensors():
    """왼쪽, 오른쪽 바닥 센서를 읽는다 (노이즈 감소를 위해 3회 평균)"""
    readings_left = []
    readings_right = []
    for _ in range(3):
        readings_left.append(hamster.left_floor())
        readings_right.append(hamster.right_floor())
        time.sleep(0.02)  # 20ms 간격으로 읽기
    left = int(np.mean(readings_left))
    right = int(np.mean(readings_right))
    return left, right

# 센서 보정: 트랙 위와 바깥의 센서 값 확인
print("=" * 40)
print("🔍 센서 보정을 시작합니다")
print("=" * 40)

input("👉 로봇을 검은 선(트랙) 위에 올려놓고 Enter를 누르세요...")
left_on, right_on = read_sensors()
print(f"   검은 선 위: 왼쪽={left_on}, 오른쪽={right_on}")

input("👉 로봇을 흰 바닥(트랙 바깥)에 올려놓고 Enter를 누르세요...")
left_off, right_off = read_sensors()
print(f"   흰 바닥 위: 왼쪽={left_off}, 오른쪽={right_off}")

# 경계값 계산 (검은색과 흰색의 중간값)
threshold = int((left_on + left_off) / 2)
print(f"\n📊 센서 경계값(threshold): {threshold}")
print(f"   이 값보다 작으면 = 검은 선 위(트랙)")
print(f"   이 값보다 크면 = 흰 바닥(트랙 이탈)")

    💡 왜 3번 읽어서 평균 내나요? 실제 센서는 빛 반사, 전기 노이즈 등으로 매번 조금씩 다른 값을 줍니다. 여러 번 읽어서 평균 내면 안정적인 값을 얻을 수 있어요. 이것을 이동 평균 필터(Moving Average Filter) 라고 합니다.

    Step 3: 상태 변환 함수 만들기 🗂️¶

    실제 센서의 연속적인 값을 Q-테이블에서 사용할 수 있는 이산적인 상태로 변환합니다. 시뮬레이션과 같은 방식으로 변환해야 Q-테이블을 재활용할 수 있습니다.

    # 행동 정의 (시뮬레이션과 동일하게!)
ACTIONS = {
    0: ("직진", 30, 30),
    1: ("살짝 좌회전", 15, 30),
    2: ("살짝 우회전", 30, 15),
    3: ("강하게 좌회전", 0, 40),
    4: ("강하게 우회전", 40, 0),
}
NUM_ACTIONS = len(ACTIONS)

def sensor_to_state(left, right, threshold):
    """
    센서 값을 이산 상태로 변환한다.
    각 센서를 3구간으로 나눔: 0(확실히 트랙 위), 1(경계), 2(확실히 트랙 밖)
    → 총 3 x 3 = 9가지 상태
    """
    def categorize(value, thresh):
        margin = 15  # 경계 구간의 폭
        if value < thresh - margin:
            return 0  # 확실히 검은 선 위
        elif value < thresh + margin:
            return 1  # 경계 (애매한 구간)
        else:
            return 2  # 확실히 트랙 밖

    left_cat = categorize(left, threshold)
    right_cat = categorize(right, threshold)
    return (left_cat, right_cat)

def get_q_values(q_table, state):
    """해당 상태의 Q값 배열을 반환 (없으면 0으로 초기화)"""
    if state not in q_table:
        q_table[state] = np.zeros(NUM_ACTIONS)
    return q_table[state]

    Step 4: 핵심 — 실제 학습 루프 실행! 🏃‍♂️¶

    드디어 실제 로봇으로 Q-learning을 실행합니다. 이 코드가 이 장의 핵심입니다.

    import random

# === 하이퍼파라미터 ===
ALPHA = 0.3        # 학습률 (실제 환경에서는 좀 더 크게)
GAMMA = 0.9        # 할인율
EPSILON_START = 0.3  # 탐험율 시작값 (시뮬 학습 완료이므로 낮게)
EPSILON_MIN = 0.05
EPSILON_DECAY = 0.95
MAX_STEPS = 200     # 에피소드당 최대 스텝
NUM_EPISODES = 20   # 실제에서는 에피소드를 적게 (시간이 오래 걸림!)
ACTION_DURATION = 0.3  # 각 행동 실행 시간 (초)

def calculate_reward(state, prev_state):
    """상태에 따른 보상 계산"""
    left_cat, right_cat = state

    # 양쪽 다 트랙 위 → 최고!
    if left_cat == 0 and right_cat == 0:
        return 5
    # 한쪽만 트랙 위 → 약간 보상
    elif left_cat == 0 or right_cat == 0:
        return 1
    # 한쪽이 경계 → 경고
    elif left_cat == 1 or right_cat == 1:
        return -1
    # 양쪽 다 트랙 밖 → 이탈!
    else:
        return -10

def is_off_track(state):
    """양쪽 센서 모두 트랙 밖이면 이탈로 판단"""
    return state[0] == 2 and state[1] == 2

def execute_action(action_id):
    """로봇에 행동 명령을 보내고 일정 시간 대기"""
    name, left_speed, right_speed = ACTIONS[action_id]
    hamster.wheels(left_speed, right_speed)
    time.sleep(ACTION_DURATION)

def stop_robot():
    """로봇 정지"""
    hamster.wheels(0, 0)

# === 학습 기록용 ===
episode_log = []

print("🚀 실제 로봇 Q-learning 학습을 시작합니다!")
print(f"   총 {NUM_EPISODES} 에피소드, 각 최대 {MAX_STEPS} 스텝")
print("=" * 50)

epsilon = EPSILON_START

for episode in range(NUM_EPISODES):
    # --- 에피소드 시작 준비 ---
    stop_robot()
    input(f"\n📍 에피소드 {episode+1}/{NUM_EPISODES} "
          f"| ε={epsilon:.2f} "
          f"| 로봇을 출발선에 놓고 Enter!")

    time.sleep(0.5)  # 안정화 대기

    # 초기 상태 읽기
    left, right = read_sensors()
    state = sensor_to_state(left, right, threshold)

    total_reward = 0
    steps = 0
    off_track = False

    # --- 에피소드 루프 ---
    for step in range(MAX_STEPS):
        # 1) ε-greedy로 행동 선택
        q_values = get_q_values(q_table, state)

        if random.random() < epsilon:
            action = random.randint(0, NUM_ACTIONS - 1)  # 탐험
        else:
            action = int(np.argmax(q_values))  # 활용

        # 2) 행동 실행
        execute_action(action)

        # 3) 새 상태 관찰
        new_left, new_right = read_sensors()
        new_state = sensor_to_state(new_left, new_right, threshold)

        # 4) 보상 계산
        reward = calculate_reward(new_state, state)
        total_reward += reward

        # 5) Q-테이블 업데이트
        new_q_values = get_q_values(q_table, new_state)
        best_next = np.max(new_q_values)

        q_table[state][action] += ALPHA * (
            reward + GAMMA * best_next - q_table[state][action]
        )

        # 6) 이탈 확인
        if is_off_track(new_state):
            stop_robot()
            off_track = True
            print(f"   ⚠️ Step {step+1}: 트랙 이탈! (센서: L={new_left}, R={new_right})")
            break

        # 상태 전이
        state = new_state
        steps = step + 1

    # --- 에피소드 종료 ---
    stop_robot()

    # 탐험율 감소
    epsilon = max(EPSILON_MIN, epsilon * EPSILON_DECAY)

    # 기록 저장
    log_entry = {
        "episode": episode + 1,
        "steps": steps,
        "total_reward": total_reward,
        "off_track": off_track,
    }
    episode_log.append(log_entry)

    status = "❌ 이탈" if off_track else "✅ 완주"
    print(f"   결과: {status} | 스텝: {steps} | 보상: {total_reward:.1f}")

# 학습 완료 후 저장
save_q_table(q_table, "q_table_real.json")
print("\n🎉 학습 완료!")

    🔑 코드에서 꼭 눈여겨볼 부분

    • input() 으로 매 에피소드 시작 전 사람이 로봇을 놓을 시간을 줍니다
    • time.sleep(ACTION_DURATION) — 실제 로봇에는 행동 후 물리적 시간이 필요합니다
    • EPSILON_START = 0.3 — 시뮬에서 이미 학습했으므로 탐험을 적게 합니다
    • ALPHA = 0.3 — 실제 환경에 빠르게 적응하도록 학습률을 약간 높였습니다
