    Chapter 5: while 루프와 실시간 로봇 제어¶

    🎯 이 장에서 배우는 것¶

    • while 반복문의 원리를 이해하고, 센서 값을 지속적으로 읽는 루프를 작성할 수 있다
    • 근접 센서 기반 장애물 회피 로봇을 만들 수 있다
    • 무한 루프를 안전하게 종료하는 방법(try-except, 키보드 인터럽트)을 적용할 수 있다
    • 실시간 제어 루프의 기본 구조를 이해하고 활용할 수 있다

    💡 왜 이걸 배우나요?¶

    지난 챕터에서 우리는 센서 값을 한 번 읽어서 로봇의 상태를 확인했습니다. 그런데 생각해보세요. 여러분이 길을 걸을 때 눈을 한 번만 뜨고 나머지는 감고 걷나요? 당연히 아닙니다! 계속 눈을 뜨고 주변을 살피면서 걷죠. 🚶‍♂️

    로봇도 마찬가지입니다. 진짜 쓸모 있는 로봇은 센서를 끊임없이 읽으면서 상황에 맞게 반응해야 합니다. 장애물이 나타나면 피하고, 길이 열리면 다시 전진하고요.

    이걸 가능하게 해주는 것이 바로 while 루프입니다. 이번 장을 마치면 여러분의 햄스터 로봇은 스스로 장애물을 피하며 돌아다니는 자율 로봇이 됩니다! 🤖✨

    그리고 이 "반복해서 감지하고 → 판단하고 → 행동하는" 구조는 앞으로 배울 라인트레이싱, 나아가 강화학습 에이전트의 기본 골격이 됩니다.

    📚 핵심 개념¶

    개념 1: while 반복문 — "조건이 맞는 한 계속!"¶

    🎪 비유로 시작

    놀이공원의 회전목마를 떠올려보세요. 운영 시간이 끝나지 않는 한 계속 빙글빙글 돕니다. "운영 시간인가?" → "YES!" → 한 바퀴 돌기 → "운영 시간인가?" → "YES!" → 한 바퀴 돌기… "운영 시간인가?" → "NO!" → 멈춤. 이것이 while 루프의 원리입니다.

    📖 정확한 정의

    while문은 조건이 True인 동안 코드 블록을 반복 실행하는 구문입니다. 조건이 False가 되면 반복을 멈추고 다음 코드로 넘어갑니다.

    while 조건:
    반복할 코드

    💻 예시로 확인

    count = 0
while count < 5:
    print(f"반복 {count}번째!")
    count = count + 1
print("루프 종료!")

    실행 결과: 

    반복 0번째!
반복 1번째!
반복 2번째!
반복 3번째!
반복 4번째!
루프 종료!

    count가 5가 되면 count < 5가 False가 되어 루프를 빠져나옵니다.

    flowchart TD A[시작] --> B{조건 확인} B -- "True" --> C[코드 블록 실행] C --> B B -- "False" --> D[루프 종료]

    개념 2: 무한 루프 — "멈추라 할 때까지 영원히!"¶

    🎪 비유로 시작

    24시간 편의점을 생각해보세요. "영업 중인가?" → 항상 YES! 특별한 사건(정전, 폐업 결정 등)이 없는 한 영원히 문을 열고 있죠. 이것이 무한 루프입니다.

    📖 정확한 정의

    while True:는 조건이 항상 True이므로 스스로는 절대 멈추지 않는 반복문입니다. 로봇 제어에서는 "계속 센서를 읽고 반응하라"는 의미로 무한 루프를 많이 사용합니다.

    💻 예시로 확인

    while True:
    print("계속 실행 중...")

    ⚠️ 위 코드를 실행하면 정말로 영원히 출력됩니다! 멈추려면 Ctrl + C를 눌러야 해요. 그래서 안전한 종료 방법이 필요합니다. (개념 4에서 배웁니다!)

    개념 3: 센서 + 루프 = 실시간 제어¶

    🎪 비유로 시작

    운전할 때를 생각해보세요. 운전자는 이런 과정을 끊임없이 반복합니다:

    1. 👀 앞을 본다 (센서 읽기)
    2. 🧠 상황을 판단한다 (if문으로 조건 확인)
    3. 🖐️ 핸들/브레이크를 조작한다 (모터 제어)
    4. 1번으로 돌아간다

    이 과정을 코드로 옮기면 바로 실시간 제어 루프가 됩니다!

    📖 정확한 정의

    실시간 제어 루프란, while 루프 안에서 "감지 → 판단 → 행동"을 반복하는 구조입니다. 로봇 프로그래밍의 가장 핵심적인 패턴이에요.

    while True:
    sensor = 센서값_읽기()      # 1. 감지
    if sensor > 기준값:         # 2. 판단
        장애물_회피()           # 3. 행동
    else:
        직진()                  # 3. 행동
    flowchart LR A["👀 감지<br/>(센서 읽기)"] --> B["🧠 판단<br/>(if문)"] B --> C["🖐️ 행동<br/>(모터 제어)"] C --> A

    이 순환 구조가 이 챕터의 가장 중요한 핵심입니다!

    개념 4: try-except — "비상구를 만들어두자!"¶

    🎪 비유로 시작

    건물에는 반드시 비상구가 있죠. 평소에는 사용하지 않지만, 비상 상황에서 안전하게 빠져나올 수 있습니다. try-except는 프로그램의 비상구입니다.

    📖 정확한 정의

    try-except는 코드 실행 중 예외(에러)가 발생했을 때 프로그램이 갑자기 죽지 않고 지정된 처리를 하도록 하는 구문입니다. 무한 루프에서 Ctrl + C를 누르면 KeyboardInterrupt라는 예외가 발생하는데, 이걸 잡아서 로봇을 안전하게 정지시킬 수 있습니다.

    💻 예시로 확인

    try:
    while True:
        print("열심히 일하는 중...")
except KeyboardInterrupt:
    print("안전하게 종료합니다!")

    Ctrl + C를 누르면 "안전하게 종료합니다!"가 출력되고 프로그램이 깔끔하게 끝납니다. 로봇 제어에서는 이 부분에 모터 정지 명령을 넣어야 합니다. 그래야 프로그램이 끝난 후에도 로봇이 멈추지 않고 돌아다니는 사태를 막을 수 있어요! 😅

    🔨 따라하기: 장애물 회피 로봇 만들기¶

    이제 핵심 개념을 모두 조합해서 스스로 장애물을 피하는 로봇을 만들어봅시다! 🚀

    Step 1: 센서를 반복해서 읽어보기¶

    먼저, while 루프로 근접 센서 값을 계속 읽어 화면에 출력해봅시다.

    from roboid import *

hamster = Hamster()

try:
    while True:
        left = hamster.left_proximity()
        right = hamster.right_proximity()
        print(f"왼쪽: {left}, 오른쪽: {right}")
        wait(100)
except KeyboardInterrupt:
    hamster.wheels(0, 0)
    print("종료!")

    실행해보세요! 로봇 앞에 손을 가까이 대거나 멀리하면 숫자가 실시간으로 변합니다. Ctrl + C를 누르면 안전하게 종료됩니다.

    💡 wait(100)은 0.1초 대기입니다. 이것이 없으면 너무 빠르게 반복되어 화면이 폭포처럼 쏟아져요!

    Step 2: 기준값 정하기¶

    손이나 장애물을 로봇 앞 다양한 거리에 두면서 센서 값을 관찰하세요.

    • 아무것도 없을 때: 보통 0~10 정도
    • 손을 가까이 대면: 30~70 정도로 올라감

    우리는 기준값 30을 사용하겠습니다. 센서 값이 30 이상이면 "장애물이 가까이 있다!"고 판단합니다.

    🔧 환경에 따라 기준값은 다를 수 있어요. Step 1에서 관찰한 값을 바탕으로 조정하세요!

    Step 3: "감지 → 판단 → 행동" 완성하기¶

    이제 본격적으로 로봇에게 판단 능력을 부여합니다.

    from roboid import *

hamster = Hamster()
THRESHOLD = 30  # 장애물 감지 기준값

try:
    while True:
        left = hamster.left_proximity()
        right = hamster.right_proximity()

        if left > THRESHOLD and right > THRESHOLD:
            # 양쪽 다 장애물 → 뒤로!
            hamster.wheels(-30, -30)
            print("뒤로!")
        elif left > THRESHOLD:
            # 왼쪽에 장애물 → 오른쪽으로 회전
            hamster.wheels(30, -30)
            print("오른쪽 회전!")
        elif right > THRESHOLD:
            # 오른쪽에 장애물 → 왼쪽으로 회전
            hamster.wheels(-30, 30)
            print("왼쪽 회전!")
        else:
            # 장애물 없음 → 직진
            hamster.wheels(30, 30)
            print("직진!")

        wait(100)

except KeyboardInterrupt:
    hamster.wheels(0, 0)
    print("로봇 정지. 안전하게 종료!")

    Step 4: 실행하고 관찰하기¶

    1. 코드를 실행합니다
    2. 로봇이 앞으로 직진하는 것을 확인합니다
    3. 손이나 책을 로봇 왼쪽 앞에 가져다 대보세요 → 오른쪽으로 회전하나요?
    4. 오른쪽 앞에 가져다 대보세요 → 왼쪽으로 회전하나요?
    5. 정면에 가져다 대보세요 → 뒤로 가나요?
    6. Ctrl + C로 종료합니다

    🎉 축하합니다! 여러분이 만든 로봇은 스스로 판단하고 행동하는 자율 로봇입니다!

    Step 5: 동작을 부드럽게 개선하기¶

    Step 3의 로봇을 보면 움직임이 다소 "딱딱"합니다. 장애물과의 거리에 따라 회전 속도를 다르게 하면 더 자연스러워집니다.

    from roboid import *

hamster = Hamster()
THRESHOLD = 30

try:
    while True:
        left = hamster.left_proximity()
        right = hamster.right_proximity()

        if left > THRESHOLD and right > THRESHOLD:
            hamster.wheels(-40, -40)
        elif left > THRESHOLD:
            speed = min(left, 60)  # 가까울수록 빠르게 회전
            hamster.wheels(speed, -speed)
        elif right > THRESHOLD:
            speed = min(right, 60)
            hamster.wheels(-speed, speed)
        else:
            hamster.wheels(30, 30)

        wait(100)

except KeyboardInterrupt:
    hamster.wheels(0, 0)
    print("종료!")

    💡 min(left, 60)은 센서 값과 60 중 작은 값을 선택합니다. 속도가 너무 빨라지는 것을 방지하는 안전장치예요!

    📝 전체 코드¶

    최종 완성된 장애물 회피 로봇의 전체 코드입니다. 복사해서 바로 실행할 수 있습니다.

    from roboid import *

# 햄스터 로봇 연결
hamster = Hamster()

# 장애물 감지 기준값 (환경에 따라 조정하세요)
THRESHOLD = 30

print("장애물 회피 로봇 시작! (Ctrl+C로 종료)")

try:
    while True:
        # 1. 감지: 센서 값 읽기
        left = hamster.left_proximity()
        right = hamster.right_proximity()

        # 2. 판단 & 3. 행동
        if left > THRESHOLD and right > THRESHOLD:
            # 정면에 장애물 → 후진
            hamster.wheels(-40, -40)
        elif left > THRESHOLD:
            # 왼쪽에 장애물 → 오른쪽 회전
            speed = min(left, 60)
            hamster.wheels(speed, -speed)
        elif right > THRESHOLD:
            # 오른쪽에 장애물 → 왼쪽 회전
            speed = min(right, 60)
            hamster.wheels(-speed, speed)
        else:
            # 장애물 없음 → 직진
            hamster.wheels(30, 30)

        # 0.1초 대기 후 다시 반복
        wait(100)

except KeyboardInterrupt:
    # Ctrl+C 누르면 로봇 안전 정지
    hamster.wheels(0, 0)
    print("로봇 안전 정지 완료!")
    flowchart TD Start["🚀 프로그램 시작"] --> Loop{"while True"} Loop --> Read["👀 센서 읽기<br/>left, right"] Read --> Both{양쪽 다<br/>장애물?} Both -- "Yes" --> Back["⬅️ 후진"] Both -- "No" --> Left{왼쪽<br/>장애물?} Left -- "Yes" --> TurnR["➡️ 오른쪽 회전"] Left -- "No" --> Right{오른쪽<br/>장애물?} Right -- "Yes" --> TurnL["⬅️ 왼쪽 회전"] Right -- "No" --> Go["⬆️ 직진"] Back --> Wait["⏱️ 0.1초 대기"] TurnR --> Wait TurnL --> Wait Go --> Wait Wait --> Loop Loop -- "Ctrl+C" --> Stop["🛑 로봇 정지 & 종료"]

    ⚠️ 자주 하는 실수¶

    실수 1: try-except 없이 무한 루프 실행 😱

    # ❌ 위험한 코드
while True:
    hamster.wheels(30, 30)

    Ctrl + C로 강제 종료하면 모터 정지 명령이 실행되지 않아 로봇이 계속 달립니다! 반드시 try-except로 감싸고 except 블록에서 hamster.wheels(0, 0)을 호출하세요.

    실수 2: wait() 빼먹기 😵‍💫

    # ❌ wait 없는 코드
while True:
    left = hamster.left_proximity()
    print(left)  # 엄청난 속도로 출력됨!

    wait(100) 없이 실행하면 루프가 초당 수백~수천 번 돌아갑니다. 화면에 숫자가 폭포처럼 쏟아지고, 컴퓨터 자원도 불필요하게 소모됩니다. 센서를 0.1초 간격으로 읽어도 충분합니다.

    실수 3: 조건 순서를 잘못 배치하기 🤔

    # ❌ 잘못된 순서
if left > THRESHOLD:
    hamster.wheels(30, -30)
elif left > THRESHOLD and right > THRESHOLD:
    hamster.wheels(-30, -30)  # 여기 절대 도달 못함!

    left > THRESHOLD가 먼저 True가 되면 elif는 확인하지 않습니다! 더 구체적인 조건(양쪽 다 감지)을 먼저 적어야 합니다.

    # ✅ 올바른 순서
if left > THRESHOLD and right > THRESHOLD:  # 구체적 조건 먼저!
    hamster.wheels(-30, -30)
elif left > THRESHOLD:
    hamster.wheels(30, -30)

    ✅ 스스로 점검하기¶

    아래 질문에 자신 있게 대답할 수 있다면 이 챕터를 잘 이해한 것입니다! 🎯

    1. while 루프의 동작 원리

    Q: while count < 3:에서 count가 0부터 시작하면 루프 안의 코드는 몇 번 실행될까요? 정답: 3번 (count가 0, 1, 2일 때 실행, 3이 되면 조건이 False)

    2. 무한 루프

    Q: while True:는 왜 스스로 멈추지 않나요? 정답: True는 항상 True이므로 조건이 절대 False가 되지 않기 때문

    3. 안전 종료

    Q: try-except KeyboardInterrupt에서 except 블록은 언제 실행되나요? 정답: 사용자가 Ctrl + C를 눌렀을 때

    4. 실시간 제어

    Q: 장애물 회피 로봇의 핵심 구조 3단계는? 정답: 감지 → 판단 → 행동의 반복
