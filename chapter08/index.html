    Chapter 8: 규칙 기반의 한계 – 왜 로봇이 선을 놓칠까?¶

    Part 2 | [1권] 라인트레이싱 – 로봇이 선을 따라 달린다

    🎯 이 장에서 배우는 것¶

    • 급커브, 교차로, 끊긴 선 등 까다로운 트랙에서 규칙 기반 방식이 실패하는 이유를 설명할 수 있다
    • 규칙 수정·추가를 직접 시도하고, 개선 전후 결과를 비교할 수 있다
    • if-else 규칙을 늘릴수록 코드가 복잡해지는 "규칙 폭발" 문제를 체감할 수 있다
    • 사람이 모든 상황을 예측하는 방식의 근본적 한계를 인식하고, 학습 기반 접근의 필요성을 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    지난 장까지 우리는 "왼쪽이 밝으면 오른쪽으로, 오른쪽이 밝으면 왼쪽으로"라는 규칙으로 로봇을 꽤 잘 달리게 만들었습니다. 직선과 완만한 곡선에서는 문제없었죠. 🎉

    그런데 진짜 도로를 떠올려 보세요. 급커브도 있고, 사거리도 있고, 차선이 점선으로 바뀌기도 합니다. 이런 예상 밖의 상황이 등장하면 우리가 만든 규칙은 어떻게 될까요?

    이번 장은 일부러 로봇을 실패하게 만드는 시간입니다. 실패를 통해 "규칙을 계속 추가하면 결국 한계에 부딪힌다"는 사실을 직접 체험합니다. 이 깨달음이 바로 다음 권에서 배울 강화학습(로봇이 스스로 배우는 방법)으로 넘어가는 출발점이 됩니다. 🚀

    📚 핵심 개념¶

    개념 1: 까다로운 트랙 – 규칙이 무너지는 순간들¶

    🎒 비유로 시작

    시험 공부할 때 "이 유형은 이렇게 풀어"라고 5가지 풀이법을 외웠다고 상상해 보세요. 시험에 딱 그 유형만 나오면 만점이겠지만, 한 번도 본 적 없는 유형이 나오면? 멘붕이죠. 규칙 기반 로봇도 마찬가지입니다.

    📖 정확한 정의

    까다로운 트랙이란, 기존 if-else 규칙이 예상하지 못한 센서 패턴을 만들어내는 환경을 말합니다. 대표적으로 세 가지가 있습니다.

    • 급커브(Sharp Curve): 센서가 선을 완전히 벗어날 만큼 빠르게 방향이 바뀌는 구간
    • T자 교차로(T-Junction): 여러 센서가 동시에 검은 선을 감지해서, 어느 쪽으로 갈지 결정할 수 없는 구간
    • 끊긴 선(Dashed Line): 선이 사라졌다 나타나기를 반복해서, "선을 잃었다"와 "트랙이 끝났다"를 구분할 수 없는 구간

    🔍 예시로 확인

    flowchart LR A["완만한 곡선 ✅"] --> B["급커브 ❌\n센서가 선을 놓침"] A --> C["T자 교차로 ❌\n어디로 갈지 모름"] A --> D["점선 구간 ❌\n선이 사라진 건지\n트랙 끝인지 혼동"]

    우리 로봇의 현재 규칙은 "센서 값에 따라 좌·우·직진"을 즉시 결정합니다. 하지만 위 세 상황에서는 센서 값만으로는 정답을 알 수 없는 경우가 생깁니다.

    개념 2: 규칙 패치 – 땜질할수록 복잡해진다¶

    🎒 비유로 시작

    비가 새는 지붕을 테이프로 막았더니, 옆에서 또 샙니다. 거기도 막으면 다른 곳에서 또 새고… 결국 지붕 전체를 뜯어고쳐야 하는 상황. 규칙 기반 프로그래밍에서 조건을 하나씩 추가하는 것이 딱 이 모습입니다. 🩹

    📖 정확한 정의

    규칙 패치(Rule Patching)란, 새로운 상황이 발견될 때마다 if-else 조건을 추가하여 문제를 해결하려는 접근 방식입니다. 단기적으로는 효과가 있지만, 조건이 늘어날수록 코드가 복잡해지고, 조건 간 충돌이 발생할 수 있습니다.

    🔍 예시로 확인

    처음 규칙이 3개였다면, 급커브 대응 규칙 2개, 교차로 대응 규칙 2개, 점선 대응 규칙 2개를 추가하면 벌써 9개. 여기에 "급커브인데 점선"인 조합까지 고려하면? 규칙 수가 기하급수적으로 증가합니다.

    flowchart TD R1["기본 규칙 3개"] --> R2["급커브 패치 +2개"] R2 --> R3["교차로 패치 +2개"] R3 --> R4["점선 패치 +2개"] R4 --> R5["조합 상황 패치 +4개"] R5 --> R6["😵 총 13개 규칙\n서로 충돌 발생!"]

    개념 3: 규칙 폭발(Rule Explosion)¶

    🎒 비유로 시작

    식당 메뉴판에 "맵게 / 안 맵게" 2가지 옵션이 있으면 관리가 쉽습니다. 그런데 "면 종류 3개 × 맵기 3단계 × 토핑 5종 × 사이즈 2개"가 되면 조합이 90가지! 손님마다 다른 주문에 주방이 마비됩니다. 🍜💥

    📖 정확한 정의

    규칙 폭발(Rule Explosion)은 입력 조건의 조합이 늘어남에 따라 필요한 규칙 수가 폭발적으로 증가하는 현상입니다. 센서 수가 N개이고 각 센서가 M가지 상태를 가지면, 이론적으로 M^N 가지 조합이 가능합니다. 사람이 이 모든 조합에 대해 올바른 행동을 미리 정하는 것은 사실상 불가능합니다.

    🔍 예시로 확인

    센서 3개, 각각 "검정/회색/흰색" 3가지 상태라면 → 3 × 3 × 3 = 27가지 조합. 센서 5개로 늘리면 → 3^5 = 243가지. 현실의 센서 값은 0~1023의 연속 값이므로 조합은 사실상 무한합니다.

    개념 4: 학습 기반 접근 – "규칙을 외우지 말고, 경험에서 배우자"¶

    🎒 비유로 시작

    자전거 타기를 배울 때, "페달을 시계 방향으로 37도 각도에서 밟고, 핸들을 3도 기울여라"라는 규칙서를 읽고 배우는 사람은 없습니다. 그냥 타보고, 넘어지고, 다시 타면서 몸이 스스로 배우죠. 🚲

    📖 정확한 정의

    학습 기반 접근(Learning-based Approach)은 사람이 규칙을 하나하나 지정하는 대신, 로봇이 직접 시행착오를 통해 좋은 행동 패턴을 스스로 찾아가는 방식입니다. 대표적인 방법이 강화학습(Reinforcement Learning)이며, 로봇은 "잘하면 보상, 못하면 벌점"이라는 피드백을 통해 점점 나아집니다.

    🔍 예시로 확인

    flowchart LR subgraph 규칙 기반 A1["사람이 규칙 작성"] --> A2["로봇이 규칙 실행"] --> A3["새 상황 → 실패"] --> A1 end subgraph 학습 기반 B1["로봇이 직접 시도"] --> B2["결과 관찰\n보상 or 벌점"] --> B3["행동 개선"] --> B1 end

    규칙 기반은 사람이 계속 수정해야 하지만, 학습 기반은 로봇이 반복 경험을 통해 스스로 개선합니다. 이것이 다음 권에서 본격적으로 다룰 내용입니다!

    🔨 따라하기¶

    지금부터 실제로 까다로운 트랙을 시뮬레이션하고, 규칙 패치를 시도하면서 한계를 체감해 봅시다.

    Step 1: 기본 라인트레이싱 코드 준비¶

    지난 장에서 만든 기본 코드를 다시 꺼냅니다. 핵심만 간추린 버전입니다.

    # basic_line_follower.py
# 기본 규칙 기반 라인트레이싱 (시뮬레이션 버전)

def decide_action(left_sensor, center_sensor, right_sensor, threshold=500):
    """센서 값을 받아 행동을 결정하는 규칙 함수"""
    if center_sensor < threshold:
        return "직진"
    elif left_sensor < threshold:
        return "좌회전"
    elif right_sensor < threshold:
        return "우회전"
    else:
        return "정지"  # 모든 센서가 흰색 → 선을 잃음

# 테스트: 일반 트랙
test_cases_normal = [
    (800, 200, 800, "직진 예상"),   # 가운데가 검정
    (200, 800, 800, "좌회전 예상"),  # 왼쪽이 검정
    (800, 800, 200, "우회전 예상"),  # 오른쪽이 검정
]

print("=== 일반 트랙 테스트 ===")
for left, center, right, expected in test_cases_normal:
    result = decide_action(left, center, right)
    status = "✅" if expected.startswith(result) else "❌"
    print(f"  센서({left}, {center}, {right}) → {result} {status} ({expected})")

    실행하면 일반 트랙에서는 모두 ✅가 나옵니다. 여기까진 완벽하죠! 😊

    Step 2: 까다로운 트랙 시뮬레이션¶

    이제 급커브, 교차로, 끊긴 선 상황의 센서 값을 넣어봅니다.

    # tricky_tracks.py
# 까다로운 트랙에서의 센서 값 시뮬레이션

print("\n=== 까다로운 트랙 테스트 ===")

tricky_cases = [
    # (왼쪽, 가운데, 오른쪽, 상황 설명, 올바른 행동)
    (800, 800, 800, "급커브: 선이 센서 범위 밖", "좌회전 해야 함"),
    (200, 200, 200, "T자 교차로: 전부 검정", "좌회전 또는 우회전"),
    (800, 800, 800, "점선 끊김: 잠시 선이 없음", "직진 유지해야 함"),
    (200, 200, 800, "Y자 갈림길: 왼쪽+가운데 검정", "판단 불가"),
]

for left, center, right, situation, correct in tricky_cases:
    result = decide_action(left, center, right)
    print(f"  [{situation}]")
    print(f"    센서({left}, {center}, {right}) → 로봇 판단: {result}")
    print(f"    올바른 행동: {correct}")
    match = "✅" if result.replace(" ", "") in correct.replace(" ", "") else "❌ 실패!"
    print(f"    결과: {match}")
    print()

    실행 결과를 직접 확인해 보세요. 대부분 ❌가 나올 겁니다!

    • 급커브에서 센서가 전부 흰색(800) → "정지"를 선택하지만, 실제로는 회전해야 함
    • T자 교차로에서 전부 검정(200) → "직진"을 선택하지만, 방향을 골라야 함
    • 점선 끊김에서 전부 흰색(800) → "정지"를 선택하지만, 잠깐 직진해야 함

    Step 3: 규칙 패치 시도 – 급커브 대응¶

    첫 번째 문제인 급커브부터 고쳐봅시다. "마지막으로 선이 있던 방향을 기억하자"는 아이디어입니다.

    # patched_v1.py
# 패치 1: 마지막 방향 기억하기

last_direction = "직진"  # 마지막으로 성공한 방향을 저장

def decide_action_v1(left_sensor, center_sensor, right_sensor, threshold=500):
    global last_direction

    if center_sensor < threshold:
        last_direction = "직진"
        return "직진"
    elif left_sensor < threshold:
        last_direction = "좌회전"
        return "좌회전"
    elif right_sensor < threshold:
        last_direction = "우회전"
        return "우회전"
    else:
        # 🩹 패치: 선을 잃으면 마지막 방향으로 계속 이동
        print(f"    → 패치 작동! 마지막 방향({last_direction})으로 계속 이동")
        return last_direction

# 급커브 시나리오 테스트
print("=== 급커브 시나리오 (패치 v1) ===")
sequence = [
    (200, 800, 800, "곡선 진입 - 왼쪽 감지"),
    (800, 800, 800, "급커브 - 선 놓침!"),
    (800, 800, 800, "계속 선 없음"),
    (200, 800, 800, "선 다시 발견!"),
]

for left, center, right, desc in sequence:
    result = decide_action_v1(left, center, right)
    print(f"  {desc}: 센서({left},{center},{right}) → {result}")

    급커브 문제는 해결됐습니다! 🎉 하지만...

print("\n=== 점선 구간 시나리오 (패치 v1) ===")
last_direction = "직진"  # 리셋

dashed_line = [

    Step 5: 교차로 패치 추가 – 규칙이 복잡해지는 순간¶

    T자 교차로까지 대응하려면 조건을 더 추가해야 합니다.

    # patched_v2.py
# 패치 2: 교차로 대응 + 급커브 대응 + 점선 대응

last_direction = "직진"
lost_count = 0  # 선을 잃은 연속 횟수
LOST_LIMIT = 3  # 이 횟수를 넘으면 정지

def decide_action_v2(left_sensor, center_sensor, right_sensor, threshold=500):
    global last_direction, lost_count

    left_black = left_sensor < threshold
    center_black = center_sensor < threshold
    right_black = right_sensor < threshold

    # 🩹 패치 2-1: T자 교차로 (전부 검정)
    if left_black and center_black and right_black:
        lost_count = 0
        print("    → 교차로 감지! 기본값: 좌회전 선택")
        return "좌회전"  # 항상 왼쪽? 🤔

    # 기본 규칙
    if center_black:
        last_direction = "직진"
        lost_count = 0
        return "직진"
    elif left_black:
        last_direction = "좌회전"
        lost_count = 0
        return "좌회전"
    elif right_black:
        last_direction = "우회전"
        lost_count = 0
        return "우회전"
    else:
        lost_count += 1
        # 🩹 패치 2-2: 점선 vs 진짜 이탈 구분
        if lost_count <= LOST_LIMIT:
            return last_direction  # 잠깐 끊긴 것 → 유지
        else:
            return "정지"  # 오래 끊김 → 정지

# 종합 테스트
print("=== 종합 테스트 (패치 v2) ===\n")

scenarios = {
    "급커브": [
        (200, 800, 800), (800, 800, 800), (800, 800, 800), (200, 800, 800)
    ],
    "T자 교차로": [
        (800, 200, 800), (200, 200, 200), (200, 800, 800)
    ],
    "점선 구간": [
        (800, 200, 800), (800, 800, 800), (800, 200, 800), (800, 800, 800)
    ],
}

for name, sensor_list in scenarios.items():
    print(f"--- {name} ---")
    last_direction = "직진"
    lost_count = 0
    for left, center, right in sensor_list:
        result = decide_action_v2(left, center, right)
        print(f"  센서({left},{center},{right}) → {result}")
    print()

    📝 전체 코드¶

    아래는 이번 장의 핵심 실습을 하나로 합친 전체 코드입니다. 복사해서 바로 실행할 수 있습니다.

    # chapter08_full.py
# 규칙 기반의 한계 체험 - 전체 코드

# ========== 기본 버전 (v0) ==========
def decide_v0(left, center, right, threshold=500):
    if center < threshold:
        return "직진"
    elif left < threshold:
        return "좌회전"
    elif right < threshold:
        return "우회전"
    else:
        return "정지"

# ========== 패치 버전 (v2) ==========
last_direction = "직진"
lost_count = 0

def decide_v2(left, center, right, threshold=500):
    global last_direction, lost_count
    left_b = left < threshold
    center_b = center < threshold
    right_b = right < threshold

    if left_b and center_b and right_b:
        lost_count = 0
        return "좌회전"  # 교차로 → 항상 왼쪽 (한계!)
    if center_b:
        last_direction = "직진"
        lost_count = 0
        return "직진"
    elif left_b:
        last_direction = "좌회전"
        lost_count = 0
        return "좌회전"
    elif right_b:
        last_direction = "우회전"
        lost_count = 0
        return "우회전"
    else:
        lost_count += 1
        if lost_count <= 3:
            return last_direction
        return "정지"

# ========== 까다로운 트랙 테스트 ==========
tricky = [
    ((800, 800, 800), "급커브: 선 밖", "회전 필요"),
    ((200, 200, 200), "T자 교차로", "방향 선택 필요"),
    ((800, 800, 800), "점선 끊김", "직진 유지 필요"),
    ((200, 200, 800), "Y자 갈림길", "판단 필요"),
]

print("===== v0 (기본) vs v2 (패치) 비교 =====\n")
for (l, c, r), situation, correct in tricky:
    r0 = decide_v0(l, c, r)
    # v2 테스트를 위해 상태 리셋
    last_direction = "직진"
    lost_count = 0
    r2 = decide_v2(l, c, r)
    print(f"[{situation}] 센서({l},{c},{r})")
    print(f"  v0 판단: {r0}")
    print(f"  v2 판단: {r2}")
    print(f"  정답: {correct}")
    print()

# ========== 규칙 폭발 계산 ==========
print("===== 규칙 폭발 계산 =====")
for sensors in [3, 5, 7]:
    states = 3  # 검정/회색/흰색
    combinations = states ** sensors
    print(f"  센서 {sensors}개 × 상태 {states}가지 = {combinations}가지 조합")

print("\n🤖 결론: 사람이 이 모든 조합에 규칙을 만들 수 있을까?")
print("   → 로봇이 스스로 배우는 방법이 필요합니다!")

    실수 1: "규칙을 더 잘 만들면 되지 않나?"라고 생각하기 🤔

    물론 규칙을 정교하게 만들면 더 많은 상황에 대응할 수 있습니다. 하지만 핵심은 "더 많은"이지 "모든"이 아니라는 것입니다. 새로운 트랙이 나올 때마다 규칙을 추가해야 하고, 규칙 간 충돌도 관리해야 합니다. 이것이 바로 규칙 폭발의 본질입니다.
